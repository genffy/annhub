# 采集规则

## 1. 职责

采集层把用户的一次“留下这个”的指认，转换为来源明确、语境尽量完整的条目（[条目契约](entry.md)）并保存到本地。

核心不变量：**每条条目都带来源 URL；语境尽力保存，提取失败不阻塞保存。** 采集不改网页：页面上没有标记，入口与描边都是扩展自己的浮层。

页面级交互以 [扩展 PRD](extension.md) 为准。

## 2. 两种采集，一种内化

| 动作 | 用户意图                         | 入口                                                                                  | 产出                         | 保存方式                                       |
| ---- | -------------------------------- | ------------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------- |
| 剪藏 | 保存一段内容供之后阅读           | 选区菜单“剪藏”（选区剪藏）；指向一个区块后的“剪藏”（区块剪藏，见 §6.2）               | `clip` 条目（Markdown）      | 一次点击，不打开窗口                           |
| 截图 | 保存网页某处的画面               | 选区菜单“截图”；快捷键；区块胶囊里的“截图”；页面批注里的“截图”（只在顶层框架，见 §3） | `screenshot` 条目 + 图片资产 | 选区内编辑后确认，见 [截图采集](screenshot.md) |
| 高亮 | 读懂并划出重点，把内容变成自己的 | 不在页面里：在资料库打开一条剪藏，选中原文（[extension.md §4.2](extension.md)）       | 这条剪藏里的一条高亮         | 一次点击；契约见 [entry.md §4](entry.md)       |

页面上只有剪藏与截图两种采集，选区菜单只有这两项；高亮不是采集，页面里没有高亮入口，也不留任何标记。条目保存之后不转换类型。

## 3. 通用流程

```text
指认内容（选区 / 区块 / 区域 / 元素）
  -> 提取 content（剪藏转为 Markdown，截图为图片）
  -> 提取 context（仅选区剪藏）
  -> 记录来源
  -> 附加类型预设属性
  -> 校验并落库
  -> 提示结果（可撤销，可编辑）
```

自动能力失败时降级，而不是丢弃：缺语境、缺页面 meta 都照样保存。

保证采集可用的页面范围：普通文章、信息流和 SPA 页面，以及同源 iframe 与 open shadow root 里的选区和区块（识别沿 `composedPath` 穿透 shadow 边界）。跨源 iframe、closed shadow root、可编辑区（输入框与 `contenteditable`）和严格内容安全策略的页面里不出现入口、不报错；`chrome://`、浏览器商店页这类受限页面同样没有入口，由工具栏弹窗兜底（[extension.md §2.6](extension.md)）；PDF 不在采集范围内（见 [Q-20](validation.md)）。

- **iframe**：页面脚本在页面的所有框架里运行；子框架与顶层框架同源时才启用入口，跨源时静默不工作。保存只接受与该标签页顶层框架同源的子框架发来的写入。
- **子框架里只提供剪藏**：截图会话的遮罩、取景坐标和被截取的画面都属于顶层框架的视口，所以子框架里的选区菜单只有“剪藏”，区块胶囊没有“截图”，区块模式没有 `S`；两个全局快捷键只发给顶层框架，一次只开一个会话。
- **shadow root 里的选区**：浏览器给得出选区的真实范围（`Selection.getComposedRanges`）时照常剪藏；给不出时降级为纯文本剪藏，没有行内格式和语境，仍然保存。最低浏览器版本不因此提高（[permissions.md §5](permissions.md)）。

### 3.1 转换为 Markdown

选区与区块都转换成 Markdown 保存，转换规则只在共享领域层实现一次：

- **保留**：标题层级、段落与换行、有序与无序列表、引用、行内代码与代码块（保留语言标记）、表格、强调、链接。相对链接解析为绝对 http(s)，其他协议的链接只保留文字。图片保留替代文字与地址；`<video>` `<audio>` 的直链文件地址按图片语法写（Markdown 没有视频语法），没有直链的视频保留封面图，`<iframe>` 嵌入的播放器写成指向嵌入地址的链接。
- **换行与空白**：文本容器的 `white-space` 是 `pre`、`pre-wrap` 或 `pre-line` 时（推文、评论、论坛帖子的正文都是这样），容器里的换行是内容：连续两个及以上的换行写成段落分隔，单个换行写成硬换行；其余容器里的换行与空白折叠成一个空格。
- **强调**：同一段文字被几层粗体或斜体元素包着（`b` 里套 `strong`、`i` 里套 `b`）时，每种强调只写一对记号，不叠加；记号紧贴文字，文字两侧的空白留在记号外面；相邻的同种强调合并。
- **列表项**：条目的文字在块级元素里（`li` 里套 `p` 或 `div`）时，第一个块的文字就是条目行，其余的块缩进在条目之下；不产生只有标记的空条目。
- **有序列表与任务列表**：`ol` 的 `start` 决定第一个序号（从 3 开始就写 `3.`）；条目前的复选框写成 `[ ]` 与 `[x]`，勾选状态不丢。
- **定义列表**：`dl` 里每个术语写成一行粗体，它的释义写在下一行，一个术语有几条释义就写几行。
- **代码块**：围栏的语言标记取 `language-*`、`lang-*` 或 `highlight-source-*` 类名，或 `data-language`、`data-lang` 属性（在代码块自己或包着它的容器上）；页面没有标出语言时不写，不猜；代码块头部与「复制」按钮同处的短标签也是语言标记，不单独成段。
- **表情图片**：替代文字是表情符号的图片（平台常把表情渲染成小图）写成这个字符，不写图片语法。
- **图片**：保留替代文字与原地址，不下载、不内联。阅读视图里只显示占位（替代文字、“图片未保存”和“打开原图”），不联网加载；需要保留画面时用截图，区块胶囊里就有“截图”。
- **图与图注**：`figure` 里的内容按顺序全部写出，多张图、表格、引用、代码块都在；`figcaption` 写成紧跟其后的一行斜体。
- **段落里的媒体**：`<video>`、`<audio>`、`<iframe>` 与图片出现在段落中间时，和独立成块时同样处理（上面“保留”一条），不因为在行内而丢掉。
- **提示框**：文档站里的提示、注意、警告框（出现在正文中间的 `aside`，或类名带 `note`、`tip`、`warning`、`callout`、`admonition`、`alert` 的容器）写成引用块，第一行是加粗的标题（取框自己显示的标题，没有就不写这一行）；正文之外的边栏（`aside` 与 `complementary` 地标）仍是页面自己的界面。
- **上标与下标**：能用 Unicode 上下标字符写出的就用它们（`10⁸`、`H₂O`），写不出的写成 `^(…)` 与 `_(…)`；不把 `10<sup>8</sup>` 写成 `108`。
- **表格**：`caption` 写成表格上方的一行粗体；`rowspan` 与 `colspan` 合并的格子在被合并的每个位置重复写出，使每一行的列数一致、表头对得上列；一个格子里有几个段落或列表项时，之间用空格加 `·` 分隔，不连成一串。
- **公式、删除线与脚注**：写法随用途不同，见 §3.3。公式取页面自己带的 TeX 源（MathML 的 `annotation` 与 `alttext`，KaTeX 与 MathJax 的源码），不把 MathML 的文字平铺成一串。
- **页面自己的界面**：区块里常混着页面的界面，转换前先去掉：按钮与工具栏、点赞与分享条、会员与订阅提示、相关文章与推荐、评论区与评论入口、广告（下载时评论是内容，见 §3.3）。X 的帖子与长文按平台规则组装，见 §3.2。
- **丢弃**：脚本、样式、表单控件、隐藏内容、扩展自己的界面，以及原始 HTML。
- **隐藏内容与标签页**：隐藏的内容不保存；关闭的 `<details>` 不算隐藏，摘要与内容都保存。标签页组（如同一个示例的多种语言）里只保存当前显示的那一页，想要另一页就切到那一页再剪；否则一页文档会带上全部语言的隐藏代码，字数膨胀几倍，个别页面约二十倍（[market.md §4.3](market.md)）。
- **上限**：转换后的 Markdown 超过 100,000 个字符时，在块边界截断保存前面的部分，提示里写明“内容过长，只保存了前 100,000 个字符”，并建议改选其中一节再剪藏。上限是初始值，见 [Q-17](validation.md)；它只管剪藏，下载不截断（§3.3）。
- 转换失败时降级为纯文本，仍然保存。
- 渲染（阅读视图、导出）同样不解析原始 HTML；链接只允许 http(s)，在新标签页打开并带 `rel="noopener noreferrer"`。

### 3.2 平台规则

有的平台页面由层层嵌套的 `div` 搭成，通用规则分不出作者、正文、被引用的内容和页面自己的界面，转换结果是一串碎段落。对这样的少数平台，转换按它的内容结构组装：只读用户正在看的页面，不调用平台的接口，不解析平台的媒体流。区块剪藏与下载共用这套规则，得到同样的 Markdown（下载见 [download.md §4.3](download.md)）；选区剪藏用 §3.1 的通用转换。目前只有 X（`x.com` 与 `twitter.com`）。

- **锚点**：规则认页面的语义结构，不认会随改版变化的测试属性与样式类名：`article` 元素（嵌套在帖子里的 `article` 是被引用的帖子；长文的正文容器也是嵌套的 `article`，以它没有自己的时间戳、带节标题或代码区分）、指向 `/status/` 的链接、文本容器的换行样式、图片与视频的地址。登录状态不同、前端版本不同的页面结构都要认得（[Q-27](validation.md)）。
- **失效时**：锚点找不到，或规则没有取到正文，就退回 §3.1 的通用转换，仍然保存（§7；风险见 RK-18）。

**X 的帖子**（一条推文，含被引用的帖子、图片、视频与卡片）按这个顺序写：

1. **作者行**：`**显示名** [@账号](账号主页) · [YYYY-MM-DD](帖子地址)`。日期是发布日的本地日期，取页面里的发布时间；页面没有时，由帖子地址里的数字 ID 换算（X 的帖子 ID 编码了发布时间）；换算不出就没有这一段。页面上“12h”这类相对时间不写。
2. **正文**：保留作者写的段落与换行（§3.1）；@提及、话题与链接保持为链接；表情写成字符。
3. **媒体**：图片按页面顺序写成图片语法，替代文字取页面的替代文字；视频有直链时按 [download.md §5.2](download.md) 处理，没有直链时写成封面图，后面跟一行指向这条帖子的链接（链接文字是界面语言的“视频”，英文界面是 Video），说明视频要在原帖里看；卡片写成一行链接（卡片的标题与地址）。
4. **被引用的帖子**：整体写成一个引用块（`>`），里面同样是作者行、正文与媒体，不再嵌套引用块。

**不写进去**：头像，认证与所属组织的徽章；回复、转发、喜欢、书签、浏览量与分享这一排数字和按钮；「更多」菜单；屏幕阅读器专用的标签（如“引用”）；关注、推荐与推广；发布时间与浏览量的链接行（日期已经在作者行里）。

**X 的长文**（有标题和正文的文章页）：

1. **标题与封面**：标题写成全文唯一的一级标题 `#`，封面图紧跟其后；正文里各节的标题整体下移，使最浅的一级是二级标题，相对层级不变。
2. **只转换正文**：作者卡、“更多文章”、关注者数、浏览量与回复数、升级与发布提示、发布时间的链接行都不写；作者与发布日期不进正文，给到属性（下面一条）。
3. **正文**按 §3.1：保留作者的分段、列表、代码块（语言标记）、强调、链接与图片，图片按页面顺序写在原位。

**标题与属性**：帖子的 `title` 是 `显示名 - 正文开头`，正文开头是折叠空白后的前 40 个字符，更长的截断，不加省略号；没有正文（只有图片或视频）时，`-` 后面写帖子地址里的数字 ID。长文的 `title` 是文章标题。`author` 写成一项 `显示名 (@账号)`，`published` 是发布日（取法同作者行）。这三项给剪藏的属性初值与下载的 frontmatter（§5）。

### 3.3 下载取用时的转换

剪藏与下载用同一套识别（§3.1、§3.2），取用的目的不同：剪藏的内容进库、在阅读视图里读，拿不准的就少存；下载的产物是文件，丢了什么用户看不出来，拿不准的就保留。区别只有下面几条，其余同 §3.1、§3.2。

- **不截断**：下载的正文不受 §3.1 的 100,000 字符上限，页面有多长，文件就有多长。
- **指认即所得**：用户指认的区块（或页面主体）里有什么就下载什么，只去掉页面自己的界面。按类名与 id 里的整词认界面时，词表收窄到从不属于内容的词（分享、点赞、广告、订阅、弹窗、Cookie 横幅一类）；“评论”“回复”不再是界面词：评论列表与回复串在被转换的区块里就保存，每条的作者、时间与正文都写（D-92）。评论入口（写评论的表单、评论数的链接、回复与点赞按钮）仍是界面。标签与角色认出的界面（导航、页眉页脚、边栏、对话框）和文字模式认出的单行（“复制链接”“关注”）照旧去掉。
- **折叠内容全取**：关闭的 `<details>`，以及由 `aria-expanded="false"` 的按钮控制的面板（手风琴、“展开全文”）里的内容都写出来。标签页组（`role="tabpanel"` 的面板）仍只取当前显示的那一页，同 §3.1（Q-31）。
- **不悄悄变成纯文本**：过滤后什么都没剩而区块里有文字时，先只按标签与角色去掉界面再转换一次；仍然为空才降级为纯文本（§3.1 的“转换失败”一条）。

**写法**：下载是文件，打开它的工具（Obsidian、Typora、VS Code）认得的写法比阅读视图多，公式、删除线与脚注因此写得更完整；剪藏停留在阅读视图认得的写法里（D-91）。

| 构造     | 下载                                                     | 剪藏                       |
| -------- | -------------------------------------------------------- | -------------------------- |
| 行内公式 | `$TeX$`                                                  | 行内代码，内容是 TeX       |
| 独立公式 | 独占的 `$$` 块                                           | 语言为 `latex` 的代码块    |
| 删除线   | `~~文字~~`                                               | 只保留文字，不加记号       |
| 脚注     | 正文里写 `[^n]`，定义写在文末 `[^n]: 文字`，不指向来源页 | 角标照常是指向来源页的链接 |

页面没有 TeX 源的公式，按它可见的文字写成行内代码，两种用途相同。下载写法里正文文字中的 `$` 与 `~` 也要转义，不被读成公式或删除线；转义的约定另见 Q-28。转换层的结构（先标准化再输出、站点提取器）另议，见 Q-29。

## 4. 语境提取

`context` 是能让用户重新理解这段内容的最小上下文，不等于整个页面正文。只有选区剪藏保存它；区块剪藏的内容本身就是一个完整的单元，不保存 `context`。

- 必须包含选区的纯文本；选区本身超过上限时不保存 `context`。
- 优先取完整句或语义段，避免按固定字数生硬截断；超长时围绕选区向两侧截断，保证目标内容仍在结果里。
- 不把导航、按钮、页脚、广告和扩展自身 UI 混进上下文。
- 提取失败时省略 `context`，条目仍可保存。

## 5. 来源与页面元数据

采集层记录 `sourceUrl`、`sourceHost` 和创建时间，并从页面得到 `title`、`author`、`published`、`description` 四个属性的初值（[entry.md §5.4](entry.md)）。

- **永久链接**：信息流页面应尽力解析内容项的永久链接作为 `sourceUrl`，而不是只保存列表页地址。区块剪藏取该区块自己的永久链接：帖子取帖子的地址（X 取自帖子里发布时间的链接）；一节取页面地址加该节标题的锚点（标题或包住它的元素有 `id` 时），“回到来源”因此直接落在这一节；其余区块取页面地址。平台规则集中维护，新增站点通过追加规则实现，不散落在业务模块里。解析失败时使用当前页面 URL。
- **页面 meta**：作者、发布日期、描述取自页面内嵌的结构化数据（`application/ld+json` 里文章类型的 `author`、`datePublished`、`description`）与页面 meta（含 Open Graph 与标准 meta），两处都有时以结构化数据为准，取不到就不设置；`title` 取页面标题。站点名（`og:site_name`）、页面语言（`html` 的 `lang`）和封面图地址（`og:image`）另外取出，只给下载的 frontmatter 用（[download.md §4.3](download.md)），不进条目属性。区块是平台规则认得的帖子或长文时，`title`、`author`、`published` 由平台规则给出，优先于页面 meta（§3.2）；信息流里的帖子带的是它自己的标题，不是信息流页面的标题。取到的值不符合 [entry.md §5.2](entry.md) 的格式或上限时：标题与描述截断到上限，作者里过长的项丢弃，发布日期不是有效日期就不设置；剪藏照常保存。
- **来源地址里的 query 与 hash**：保存前去掉带令牌特征的参数，其余保留，包括区块剪藏用的标题锚点。清理规则只在共享领域层实现一次：query 与 hash 里以 `?` / `&` 分隔的参数，名称不区分大小写并去掉首尾空白后属于令牌名清单的，整段删除；hash 里非查询参数形式的部分（路径与锚点）原样保留；清理后留下空的 `?` 或 `#` 时一并去掉；清理后的地址仍必须是绝对 http(s) 链接。令牌名清单：`token`、`access_token`、`refresh_token`、`id_token`、`code`、`session`、`session_id`、`sessionid`、`auth`、`auth_token`、`api_key`、`apikey`、`secret`、`sig`、`signature`、`jwt`。
- **回到来源**：只打开 `sourceUrl`，不在原页面里定位，也不恢复任何标记。

## 6. 剪藏的细节

剪藏有两个入口，保存后的提示、撤销和编辑完全一致。

### 6.1 选区剪藏

- 选中文字后，在选区菜单点击“剪藏”立即保存，不打开窗口。
- 保存后出现约 3 秒的提示“已剪藏 · 撤销 · 编辑”：撤销删除刚保存的条目；编辑在选区旁打开小气泡，可改标题、标签和备注（[extension.md §3](extension.md)）。

### 6.2 区块剪藏

指一下就剪整块，不需要先选中文字。入口有两个，保存的结果完全相同：**悬停入口**（鼠标）和**区块模式**（键盘）。截图取景（[screenshot.md §1.2](screenshot.md)）与下载（[download.md §2](download.md)）读的是同一条目标链：三个入口指着同一处，描出同一个范围。悬停入口的范围完全由指针停在哪里决定，胶囊上没有换层级的按钮；要换层级，用区块模式或截图取景的 `↑` `↓`。识别规则的依据和页面抽样见 [market.md §4.3](market.md)，链与悬停的做法参照的现有产品见 [market.md §4.9](market.md)。

**目标链里的层。** 指针下从里到外的一串目标叫目标链，按包含关系排列，每一层是下面一种。块以外的七种叫单元，其中帖子、代码块、表格、图、引用叫小单元。“标注”列是描边上沿显示的类型与范围：

| 层     | 怎样识别                                                                                                                                                                                              | 标注                            |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| 块     | 计算样式不是行内的元素；指针下是行内元素（`display` 以 `inline` 开头，`inline-block` 除外）时，往外取到它所在的块。`p` 叫段落，`li` 叫列表项，`ul` 与 `ol` 叫列表，`h1` 至 `h6` 叫标题，其余叫块      | 段落 · 开头的文字               |
| 帖子   | 平台规则：X 时间线或详情页里的一条帖子，含图片、卡片和被引用的帖子                                                                                                                                    | 帖子 · @账号                    |
| 代码块 | `pre`                                                                                                                                                                                                 | 代码块 · 18 行                  |
| 表格   | 有表头，或至少两行两列的数据表；包住整篇正文的布局表格不算                                                                                                                                            | 表格 · 6 行 × 4 列              |
| 图     | `figure`，或宽度不小于 200px 的图片                                                                                                                                                                   | 图 · 图注，没有图注时 640 × 360 |
| 引用   | `blockquote`，不少于 20 个字符                                                                                                                                                                        | 引用 · 开头的文字               |
| 一节   | 从一个标题（`h1` 至 `h4`）到下一个同级或更高级标题之前的内容；页面用 `section` 包住各节时取这个 `section`。一节里还有低一级的标题时，每一级各是一层：`h3` 的一节在 `h2` 的一节里面                    | 一节 · 指数退避加抖动           |
| 文章   | `article`、`[role=article]`；没有时取正文容器：`main`、`[role=main]` 和常见的内容容器（如 `.entry-content`、`.post-content`、`.markdown-body`）；仍没有时取直接包含至少三个有文字量的段落的最内层容器 | 文章 · 整篇                     |

一节和文章都要求正文不少于 120 个字符，按字符数而不是词数计，中文同样适用；够不上的 `section` 是块，够不上的标题区间不成层。首个标题之前的段落不属于任何一节，外面一层直接是文章。帖子（X）和文章（Medium）有平台规则，集中维护；新增站点靠追加规则，不改通用识别。

**标注怎样写。** 标注放在描边上沿的左端，位置同截图取景的标签；胶囊在左上角时，标注放到上沿的右端；目标比窗口高、或上沿离窗口顶部放不下标注时，和胶囊一样贴着窗口里可见部分的上沿。块、引用和图注取开头 16 个字符，一节的标题取 24 个字符，超出的截断并加省略号；开头的文字不含页面自己的界面（代码卡片工具栏上的“复制”、分享条上的数字），相邻两块的文字之间隔一个空格，即使源码里它们紧挨着。代码块写 `pre` 里的行数，末尾的换行不算一行，卡片工具栏上的文字不算。目标宽不到 260 像素，或完整的标注会碰到胶囊时，只显示类型；只写类型仍碰到胶囊时（目标刚比胶囊宽一点），标注移到胶囊的上面。英文界面里，段落、列表项、列表、标题、块、帖子、代码块、表格、图、引用、一节、文章依次是 Paragraph、List item、List、Heading、Block、Post、Code block、Table、Figure、Quote、Section、Article，范围写成 `@handle`、`18 lines`、`6 rows × 4 columns`、`Whole page`。

**两种看法。** 同一条链，截图取景与剪藏看到的层数不同：

- **像素看法**（截图取景）：指针下的块和它的每一个祖先都是一层，直到 `body` 之下；只跳过外框与里面一层完全相同的层。标题与段落平铺的页面上，一节作为一层插在段落与它们的容器之间。下文“不出现”所列的区域照样取得到，截图要的是画面。
- **内容看法**（悬停胶囊与区块模式）在像素看法之上再做四处调整：
  - 外层比里层多出的文字不到 20 个字符（不算空白）、也没有多出图片或视频时，两层并成一层，范围取外面那一层；同类的外框装着里面那层九成以上的文字时，同样并成一层（文档站的正文容器套在文章里）。类型这样定：块与单元相并是那个单元（`div` 包着 `pre`，是代码块，范围是整张代码卡片）；两个块相并，用外面那个块的叫法；一节与文章相并，取外面那一层。小单元不与另一个单元相并：帖子里的图、被引用的帖子，以及包着一条帖子的一节，仍各是一层。
  - 页面自己的界面不成层：按钮与工具栏、分享条、推荐与评论入口等（识别同 §3.1“页面自己的界面”）不是目标，指针停在上面时，起点是它外面第一个不是界面的层——分享条上是它所在的块或整篇文章，代码卡片工具栏上是整张卡片。卡片只有指到代码时才定为代码块，指到工具栏时是块。像素看法照取。
  - 小单元里面不再分出块：指针在帖子的一段文字上，起点就是这条帖子。小单元里面的小单元仍是一层，如帖子里的图、被引用的帖子。
  - 链到文章为止，文章之外不再有层。并列至少两条帖子的容器（X 的时间线列，含高出窗口很多倍的虚拟列表）和它外面的层都不进链，帖子或外层帖就是最外一层。两者都没有时，链到最外一个不包含“不出现”区域的块为止。

**起点。** 三个入口都从同一个起点开始：指针下最内层的块；指针在块与块之间的空隙里时，是空隙所在的那个块，文章的正文容器就是整篇文章。有两个例外：

- 指在标题上，起点是这个标题开头的那一节；标题本身仍在链里，是这一节里面的一层，区块模式里按 `↓` 就到。
- 宽不到 30 或高不到 10 CSS 像素的块（图标、角标、行内的小按钮）不作起点，起点取它外面第一个够这个尺寸的块，不再往外放大；小块仍在链里，区块模式里按 `↓` 取得到。

内容看法里，起点落在小单元里面时取那个小单元，起点与外层并成一层时取并成的那一层。区块模式与截图取景里，指针每移到一个新的起点，层级都回到起点；区块模式里指针在同一个起点里移动，已用 `↑` `↓` 选好的层级和 `Tab` 移到的目标不变。悬停入口只取起点：文章里的一节靠指它的标题取到，整篇靠指段落之间的空隙取到。

**悬停入口。**

- **停下**：指针每 100ms 移动不到 6px 算停着；连续停约 400ms，起点这一层出现描边与标注，旁边出现胶囊。手抖与触控板的漂移不重新计时。识别只在停下之后运行。
- **胶囊**：只带图标的按钮，从左到右是剪藏、截图、下载、更多；悬停显示名称，读屏读出名称。「剪藏」保存描边的这一层；「截图」以它为目标直接进入原位编辑（[screenshot.md §1](screenshot.md)）；「下载」把它取成本地的 Markdown 文件夹（[download.md §2.1](download.md)）；「更多」里有“在此网站停用”“关闭区块剪藏入口”“设置…”。
- **没有换层按钮**：悬停入口的范围完全由指针停在哪里决定，指到哪一块就是哪一块，胶囊上没有扩大或缩小范围的按钮；想剪更大或更小的一块，把指针移到它上面。悬停不接管方向键，页面要用它们滚动；要用键盘换层级，进区块模式。
- **收起**：指针离开描边与胶囊约 150ms 后收起；开始滚动、按键或拖选时立刻收起。一次手势只剪一次：同一个目标在 1.5 秒内再次触发剪藏（页面重派了这次点击）不再保存第二条，再次有意剪同一个目标不受影响（issue #105）。
- **暂停**：选区菜单因为点击页面而收起、选区塌缩、或者按键关掉了胶囊之后，胶囊在当时指针下的起点上暂停：指针在这一块上停多久都不出现。指针下的起点变了才解除——移到别的块上，或者页面滚动让另一块来到指针下——在新的块上照常计时。暂停跟着块走、不计时，因为点偏之后人往往在原处停不止 1 秒。
- **位置**：优先放在目标的右上角，左右缘留在目标轮廓内（距左右缘一小段），上沿跨在轮廓上，这样不会盖住旁边的边栏。目标比窗口高时，贴着窗口里可见部分的上沿，这样指针在一篇长文里的任何位置，胶囊都在视野里。右上角被页面自己的链接、按钮或菜单占住时（时间线帖子的“更多”按钮、代码块的“复制”按钮），依次试左上角、右下角、左下角，再沿上沿向左；上沿整条都被占住时（吸顶的页头），最后沿下沿向左。选第一个不盖住页面控件的位置；左右缘仍然留在轮廓内。

**区块模式。** 快捷键进入（默认 `Ctrl+Shift+E` / `Cmd+Shift+E`，可在浏览器的快捷键设置里改），页面里的链接在模式里暂不响应点击。模式用内容看法的链，描边与标注同悬停入口。指针悬停时，描边跟着指针下的起点；键盘上 `Tab` / `Shift+Tab` 移到下一个或上一个同档的目标，`↑` / `↓` 换层级，`Enter` 剪藏，`S` 截图，`D` 下载（[download.md §2.2](download.md)），`Esc` 退出。模式胶囊用文字说明当前目标的标注和这些按键，读屏会读出类型与摘要。页面没有键盘焦点（如地址栏获焦）时，胶囊先说明先点一下页面，否则 `Esc` 会落在浏览器里。同源子框架里的区块模式没有 `S` 与 `D`（§3）。

- **起点**：模式一打开就有目标，不需要先动鼠标：键盘焦点所在元素的起点，取法同悬停；没有焦点时，是窗口里第一个起点。
- **同档**：块与小单元是一档；一节按标题级别各成一档（`h2` 的一节与 `h2` 的一节同档）；文章一档。`Tab` 按文档顺序移到当前目标之后的下一个同档目标，`Shift+Tab` 移到之前的一个；不进入当前目标里面，也不停在包着它的层上。块这一档里 `Tab` 只停在能作起点的块上，取法同悬停，只是标题按块算，停在标题本身；并进来的包装（代码卡片、`div` 包着的段落）与里面的内容是同一站，范围是并成的那一层，其余外层的包装不停；这一站排在里面那个内容所在的位置，不是包装开始的位置（一节只多出一个标题而并进表格时，先停标题，再停表格）。键盘与悬停用同一套排除：“不出现”所列区域里的目标不参与同档移动，`Tab` 跳过它们。`Tab` 移到窗口外的目标时滚动到可见。
- **换层与进入**：`↑` 换到链上外面一层，到了最外一层不再动；`↓` 换回里面一层。在链的最里一层按 `↓`，进入当前目标里面的目标，一次一层：文章先进入窗口所在的一节，窗口里没有一节时进入下一节；其余目标进入窗口处的第一个起点。找到的目标不在窗口里时滚动到可见；进入之后，链从新的目标重新算。

**不出现**：页面上有选区或正在拖选、焦点在输入框或可编辑区、指针在扩展自己的界面上、`nav` `header` `footer` `aside`、表单与对话框里、不可见的元素、既没有文字也没有图片或视频的块、暂停中的块（上文）。入口只是扩展自己的浮层，不改网页内容。识别只在指针停下之后运行，只检查指针下的祖先链和标题所在的同级元素，不整页扫描，所以不拖慢滚动；open shadow root 里的目标同样可以识别。

**保存。** 目标转为 Markdown（§3.1）；`sourceUrl` 取目标自己的永久链接（§5）；不保存 `context`。保存后的提示、撤销与编辑和选区剪藏完全一致。

**默认与开关。** 悬停入口默认开启，设置里可整体关闭，也可在胶囊的“更多”里按网站停用，已停用的网站在设置里管理（[extension.md §2.5](extension.md)）。区块模式是用户明确发起的，不受这个开关影响。

### 6.3 高亮在这里没有入口

在页面里划线保存的需求由“剪藏”承担；读的时候划重点在资料库里完成，见 [extension.md §4.2](extension.md)。

## 7. 失败处理

| 失败点                     | 处理                                                   |
| -------------------------- | ------------------------------------------------------ |
| 上下文提取失败             | 省略 `context`，继续保存                               |
| 永久链接解析失败           | 使用当前页面 URL                                       |
| Markdown 转换失败          | 降级为纯文本，继续保存                                 |
| 内容超过上限（剪藏）       | 保存前 100,000 个字符，并在提示里说明；下载不截断      |
| 页面 meta 缺失             | 对应属性不设置                                         |
| 平台规则失效（站点改版）   | 退回通用识别与通用转换，内容可能带页面的界面；仍然保存 |
| 页面里没有符合的区块       | 不出现入口；选区剪藏照常可用                           |
| 图片保存失败               | 保留截图预览并允许重试                                 |
| 条目落库失败（含配额不足） | 显示可读错误并允许重试；不显示成功；选区保持           |

任何自动步骤都不能导致用户已经输入的备注、标题或属性丢失。

## 8. 非目标

- 不做无确认的一键批量保存；不默认保存整页正文（区块剪藏保存的是用户指认的一个整体内容，整页正文见 [Q-11](validation.md)）。
- 不在网页上留任何标记。
- 不自动展开线程或评论串：一次剪一个帖子，想要整串时逐条剪，或者截图。
- 不把截图字节放进条目消息；图片通过 `assetId` 引用独立保存的字节。
- 不让站点适配逻辑散落在各业务模块里。
- 不做重复检测与提示：同一内容在不同语境里价值不同，可以多次保存，需要时在资料库里删除。
