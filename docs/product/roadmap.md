# 产品路线图

> 层级：vision
> 状态：当前计划；交付状态的唯一入口
> 更新：2026-10-30

本文写已发布的能力、正在做的事、发布门禁与真机验收项，是交付状态的唯一真源。页面体验见 [扩展](extension.md)，字段见 [条目契约](entry.md) 和 [存储](storage.md)，待确认的决策、风险与开放问题见 [validation.md](validation.md)。代码按本目录的契约实现；与契约不符的代码、消息、设置、测试入口和文案，在实现时一并删除。

## 1. 排期原则

1. 已发布的能力是基线（第 2 节）：新功能在它之上增量交付，不破坏已保存的条目、属性与导出。
2. 每个版本都必须在断网时可降级运行。
3. 不迁移 1.x 的数据（与 1.x 是同一个商店条目，见 [permissions.md §6](permissions.md)），本地数据库直接使用本目录的契约。
4. 一个功能一个 PR：契约、用户故事与验收、指标和代码在同一个 PR 里修改，产品负责人在评审里确认规格（[AGENTS.md](AGENTS.md)）。导出、测试和文档是功能的一部分，不在版本末尾补做。
5. 边界随功能调整：功能越过 [product.md §2.3](product.md) 的不做清单时，在它的 PR 里改那一行；没有开始做的能力不提前放宽边界，也不提前增加 UI 入口。

## 4. 发布门禁

每个版本必须同时满足：

- TypeScript compile 通过；领域逻辑全量单测通过；Extension 关键路径 E2E 通过。
- 主流程在断网时仍可完成，用户输入在所有已知错误路径中不丢失。
- Markdown ZIP 的内容、frontmatter、来源与图片相对链接检查通过；断网时可独立导出，文件可独立阅读，ZIP 不被宣传为完整恢复备份。
- 所有扩展页面的版式检查通过：左导航 + 右内容，没有顶部导航。
- 页面和术语符合产品边界（[product.md §2.3](product.md)）。
- 对外分发的构建可由目标用户自行安装：扩展已通过商店审核。
- 权限、隐私政策里的权限表和商店的权限说明三者一致；一次完整使用（采集、阅读、导出）期间，扩展自己发出的网络请求只有截图时代取的页面内图片（[permissions.md §1](permissions.md)）。
- 改动涉及第 5 节某一项的范围时，这一项的真机走查通过。
- 受影响文档和错误恢复路径更新。
