# 下载

下载把页面里的一个区块或整页正文，或资料库里选中的条目，取成本地的 Markdown 文件夹（可选一个 ZIP），页面里的图片与直链的视频、音频一并取回。它的终点是文件：不建条目、不进资料库，与录屏一样“下载即终点”（[annotate.md §2.3](annotate.md)）。页面里的入口见 §2，资料库里的见 §3，产物见 §4，媒体见 §5，权限与数据边界见 §6。

## 1. 定位与边界

### 1.1 解决什么

- **为谁**：每周读大量网页资料、要把读到的内容带进别的工具继续写的工程师、产品/设计和研究者（[product.md §2.1](product.md)）。
- **问题**：剪藏只保存文字，图片只留原地址（[capture.md §3.1](capture.md)）；唯一的用户导出是整库 ZIP（[storage.md §6](storage.md)），取不出一篇文章或几条条目；Obsidian Web Clipper 默认也不下载图片（[market.md §4.2](market.md)）。用户要的是：读到一篇文章，一次点击就得到一个带图片、断网也能读的文件夹。

### 1.2 它不是什么

| 不是             | 区别                                                                                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 剪藏             | 剪藏建条目、进资料库，可阅读、高亮、检索；下载不建条目，产物在资料库之外，用别的工具打开                                                                                                                     |
| “导出内容”       | 整库导出是备份式：文件名只由受控 ID 生成，图片共用一个 `assets/`，不联网（[storage.md §6](storage.md)）。下载是取用式：按标题命名，每份自包含，可以联网取回图片。两者并存，互不替代                          |
| 整页剪藏、稍后读 | 下载由用户逐次点击触发，对象是用户指认的区块，或页面的主体文章（“文章”这种区块）；没有待下载的队列，不在库里阅读。不做清单（[product.md §2.3](product.md)）不变；整页剪藏进库仍另议（[Q-11](validation.md)） |
| 视频下载器       | 只取页面里的直链文件；流媒体、受保护的内容和嵌入的播放器不取（§5.2）                                                                                                                                         |

### 1.3 范围

- **范围内**：页面区块与页面主体文章的下载；资料库里单个与多选下载；页面里的图片，以及直链的视频与音频。
- **范围外**：直接写入用户选定的文件夹（Q-22）；`data:` 与 `blob:` 图片、内联 SVG；需要登录 cookie 才看得到的图（Q-23）；定时或自动下载；跨标签页的批量下载。剪藏仍只留图片原地址，是否把图片存进库见 Q-21。

## 2. 页面上的入口

### 2.1 区块胶囊

- 区块胶囊上的动作是「剪藏 | 截图 | 下载 | 更多」。「下载」在「截图」之后、「更多」之前，图标加短文本；它与「剪藏」「截图」作用于同一个被描边的区块：点击后下载这个区块的 Markdown，以及区块里的媒体。
- 悬停时目标始终是指针下最内层的区块，胶囊上没有调整层级的按钮（D-85）。要下载整页正文，用工具栏弹窗或命令（§2.3），或用区块模式选到“文章”再按 `D`（§2.2）。
- 同源 iframe 里的区块没有「下载」，与「截图」一样属于顶层页面（[capture.md §3](capture.md)）。
- 胶囊的出现时机、位置、不出现的情形和「更多」里的内容，同 [capture.md §6.2](capture.md)；区块入口被整体关闭或在某个网站停用时，胶囊不出现，弹窗与命令不受影响。
- 入口只响应用户的真实点击与按键；网页脚本合成的事件不触发下载。

### 2.2 区块模式

- 键盘区块模式用 `D` 下载当前目标，模式胶囊的按键说明里加“D 下载”；`Tab`、`↑` `↓`、`Enter`、`S`、`Esc` 同 [capture.md §6.2](capture.md)。同源子框架里的区块模式没有 `D`。

### 2.3 工具栏弹窗与命令

- 工具栏弹窗底部有「下载本页正文」（[extension.md §2.6](extension.md)），下载当前标签页的主体文章；`chrome://` 等受限页面上不可用，并写明原因。
- 另有一个命令「下载本页正文」，默认不绑定快捷键，用户在浏览器的快捷键设置里自己绑（[extension.md §7.1](extension.md)）。

### 2.4 页面主体

- 页面主体指页面上的“文章”区块，识别规则同 [capture.md §6.2](capture.md)；页面上有多个时取文字最多的一个。
- 找不到时提示“没找到正文，请把指针停在正文上选一个区块”，不下载。

### 2.5 进度与结果

页面里出现一条提示条，样式同剪藏的提示条：

| 状态 | 提示                                                                               |
| ---- | ---------------------------------------------------------------------------------- |
| 进行 | 「正在下载 3/12 · 取消」，n 是已处理的媒体数，N 是总数                             |
| 完整 | 「已下载 · 显示文件」，在系统的文件管理器里显示这次下载                            |
| 部分 | 「部分下载：N 项媒体未保存」，未保存的项在 README 里                               |
| 失败 | 本地化的原因短句，依据稳定的错误码生成，不显示浏览器的原始信息；给“重试”，正文不丢 |

- 一次只进行一个下载，跨标签页也是；进行中再触发，提示“上一个还在进行”。
- **取消**：停止取回，取消在途的文件，删除已经写好的文件；浏览器已建好的空文件夹留下，提示里写明。取消后不留下 Markdown 与媒体，也不再发出请求。

## 3. 资料库里的下载

### 3.1 单个条目

- 详情抽屉头部与阅读视图顶栏有「下载」，剪藏与截图条目都有（[extension.md §4.1、§4.2](extension.md)）。它下载 Markdown 文件夹，提示文字是“下载为 Markdown”；截图卡片与抽屉图片节里原有的下载按钮仍然下载图片本身（[extension.md §2.3、§4.1](extension.md)）。
- 单条直接开始，不弹准备态；进度与结果显示在内容区顶部的一行状态里，结果的完整、部分、失败三种提示同“导出内容”。

### 3.2 多选

- 全部、剪藏、截图三个列表视图的页头有「选择」；高亮、属性与设置视图没有（D-88）。
- **选择模式**：卡片出现复选框；点击卡片切换选中，不再打开抽屉；`Shift` 加点击选中一个区间；`Space` 切换焦点所在的卡片；`Esc` 退出并清空。截图卡片悬停时的下载与删除在选择模式里隐藏。
- **选择条**固定在列表上方：「已选 N 条」「选择当前筛选的全部 M 条」「清除」「下载所选」「完成」。读屏用状态播报已选数量，卡片的按钮标注是否被选中。选择条只有“下载所选”一个动作。
- 改变视图、筛选或搜索会清空选择；选择状态不写进地址。
- 一次选择的条数有上限（D-82）；当前筛选的全部条数超过上限时，「选择当前筛选的全部」不可用并写明上限。

### 3.3 下载对话框

- 沿用“导出内容”对话框的壳与键盘行为（[extension.md §2.2](extension.md)）。
- **准备态**：条数、预计文件数、形态（文件夹或 ZIP，默认取设置）、“同时下载媒体”（图片、视频与音频，需要联网，默认取设置）。预计文件数很多时建议选 ZIP，门槛见 D-82。
- **进行态**：显示 n/N 与「取消」。联网取回可以取消，这一点不同于整库导出的“开始即完成”。
- **结果**：完整、部分（列出未保存的媒体）、失败三种横幅，同“导出内容”。

### 3.4 内容

- 读取已保存的条目与图片；frontmatter 与章节同整库导出（[storage.md §6](storage.md)），高亮写成 `==…==`。
- 截图条目用已保存的图片字节，不联网。剪藏里的远程媒体联网取回（§5.3）；取消勾选或断网时只写 Markdown，媒体保留原地址，README 说明。

## 4. 产物

### 4.1 形态

| 形态           | 落到哪里                            | 说明                                                                                                                                          |
| -------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件夹（默认） | 浏览器下载目录下的 `AnnHub/<标题>/` | 一批独立的下载，由浏览器逐个写入；先写媒体、最后写 Markdown，Markdown 里的链接按媒体落盘后的实际文件名写；同一个标题再次下载时文件夹加 ` (2)` |
| ZIP            | `AnnHub/<标题>.zip`                 | 一个文件，内容是同一棵目录树，一次下载                                                                                                        |

- 设置页有一张「下载」卡片（[extension.md §2.5](extension.md)）：形态（文件夹或 ZIP，默认文件夹）和“同时下载媒体”（默认开）；资料库的下载对话框可以临时改（§3.3）。
- 文件夹形态的代价：浏览器设置了“下载前询问每个文件的保存位置”时，每个文件都会弹出保存对话框（[market.md §4.7](market.md)）。设置页在形态旁写明这一点，并建议此时改用 ZIP。多个文件连续下载的实际表现见 Q-25。
- 扩展不弹自己的另存为对话框，同截图与录屏的下载（[annotate.md §2.1](annotate.md)）。
- 不直接写入用户选定的文件夹（Q-22）。

### 4.2 目录结构

```text
AnnHub/<标题>/                       文件夹形态；ZIP 形态是 AnnHub/<标题>.zip 里的同一棵树
├── <标题>.md                        frontmatter + 正文，媒体用相对链接
├── assets/                          img-001.jpg … video-001.mp4（序号 + 响应类型决定的扩展名）
└── README.md                        只在有未保存的媒体时出现：每一项的原地址与原因

AnnHub/AnnHub-download-YYYY-MM-DD/   资料库多选（文件夹形态）；ZIP 形态是 AnnHub-download-YYYY-MM-DD.zip
├── README.md                        条目清单与失败清单
├── <条目标题 A>/ …                  每条一个同样结构的文件夹
└── <条目标题 B>/ …
```

页面里没有可取的媒体时没有 `assets/`。日期是下载当天的本地日期。

### 4.3 Markdown 的内容

- **页面下载**：frontmatter 有 `title`、`source`、`author`、`published`、`created`、`description`，键名对齐 Obsidian Web Clipper 的默认模板（同 [storage.md §6](storage.md)）；`title` 取页面标题，`source` 取区块的来源地址并去掉带令牌特征的参数（[capture.md §5](capture.md)），`created` 是下载当天的本地日期；取不到的字段不写。正文是区块或主体文章转换出的 Markdown，转换规则同 [capture.md §3.1](capture.md)。
- **资料库条目**：frontmatter 与章节同整库导出，含 `annhub_` 键和全部属性。
- **媒体**：图片写成指向 `assets/` 的相对链接；视频与音频的写法见 D-83；没取到的媒体保留原地址。
- 页面下载的正文不受入库字数上限的限制（Q-17 是入库的口径）。

### 4.4 文件名

- 文件夹名与 Markdown 的文件名由标题清洗而来：去掉 `\ / : * ? " < > |` 与控制字符；折叠空白；去掉首尾的点和空格；避开 Windows 的保留名；长度有上限（D-82）；标题为空时用来源的主机名；同一批里重名加 ` (2)`。标题取页面标题，资料库里取条目的标题。
- 媒体的文件名只由序号和响应类型生成，永远不取自网页。
- 这与整库导出“路径只由受控 ID 生成”并存（[storage.md §6](storage.md)），整库导出不变。

## 5. 媒体

### 5.1 取哪些

- 只取页面自己声明的地址，顺序是：`currentSrc` → http(s) 的 `src` → `data-src` / `data-original` / `data-actualsrc` / `data-lazy-src` → `srcset` 里最大的一项 → `<picture>` 的 `<source>`。`src` 是 `data:` 占位图时，用后面的地址。`<video>` 的 `poster` 按图片处理。
- 同一个地址只取一次；过小的图和追踪像素不取，门槛见 D-82。
- 不改写地址去换更高清的版本，不猜测、不枚举页面没有引用的地址。

### 5.2 种类

| 种类       | 规则                                                                                                                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 图片       | 响应须是 `image/*`；SVG 不取（可以带脚本），保留链接；大小上限见 D-82                                                                                                                         |
| 视频、音频 | 只取 http(s) 直链的 `<video>` `<audio>` `<source>`；响应须是 `video/*` 或 `audio/*`；大小上限见 D-82，写法见 D-83；大体量文件的打包见 Q-26                                                    |
| 不取的     | `blob:` 与 `mediastream:` 地址、HLS（`.m3u8`）、DASH（`.mpd`）、受 DRM 保护的内容、`<iframe>` 嵌入的播放器。保留原链接，视频有封面（`poster`）时附封面图；嵌入的播放器写成 `[标题](嵌入地址)` |

### 5.3 怎么取

- 取回由扩展在用户点击之后进行；字节不经过网页，也不发往任何地方，只写进产物。
- 规则同截图代取页面图片（[screenshot.md §2](screenshot.md)）：只接受公网 http(s) 地址，拒绝本机、局域网、链路本地和带账号的地址，不带凭据；另外重定向之后重新检查，响应类型和大小在读取时校验。
- 不带 cookie（D-84）；登录后才看得到的图保留原地址（Q-23）。
- 按 Referer 拦截的图床：请求带上页面的来源作 Referer，就是浏览器显示这张图时发的值（§6.1）。资料库里的条目用条目来源页的来源（D-89）。各图床的实际表现见 Q-24。
- 同时取回的数量、单个请求的等待时间和整包的大小上限见 D-82。

### 5.4 取不到

- 单个媒体取不到、超限或类型不符：Markdown 保留原地址，README 列出这一项的原地址和原因，其余照常保存。
- 全部取不到：Markdown 照常保存，README 列全。断网：只保存 Markdown，README 说明。
- 不因为媒体失败而让整个下载失败，也不丢已经转换好的正文。按 Referer 或 cookie 拦截的图床是常见原因（RK-17）。

## 6. 权限与数据边界

### 6.1 权限

| 权限                                  | 用途                                                                                                                       |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `downloads`                           | 把产物写成下载目录下的相对路径文件；路径不含 `..`，不绕过浏览器的下载确认与危险文件拦截                                    |
| `offscreen`、`<all_urls>`             | 取回与打包在扩展自己的后台文档里进行，与录屏共用同一个后台文档（Q-26）；`<all_urls>` 让取回绕开页面的 CORS，同截图的代取   |
| `declarativeNetRequestWithHostAccess` | 取回图片时把 Referer 设为页面的来源。规则只在下载期间存在，只作用于扩展自己发出的取图请求，只设置 Referer 这一个头（D-86） |

- `declarativeNetRequestWithHostAccess` 只服务 Referer 还原，页面下载本身不需要它；它依赖已有的 `<all_urls>`，目标是不增加安装时的权限警告（验收见 §9）。
- 不申请 `declarativeNetRequest`（[官方参考](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)：安装时带警告，并隐含拦截类规则的权限，比所需更宽），也仍然不申请 `webRequest`、`cookies`、`debugger`、`scripting`。

### 6.2 数据边界

- 页面内容与媒体只写到用户本机，不发往 AnnHub 或第三方；没有账号。
- 出站请求只发往页面自己引用的媒体主机，只在用户点击之后，同时取回的数量有上限（D-82）。
- 对方（图床）能看到：用户的网络地址、被请求的地址、页面的来源（Referer），以及请求可能显示为来自本扩展（Origin 带扩展 ID，Q-24 核实）。这些写进隐私政策（[permissions.md §6](permissions.md)）。
- 日志与指标不含地址、标题、正文和媒体（[metrics.md §9](metrics.md)）。

### 6.3 商店规则对照

下表左列是本功能自己守的约束，右列是依据的商店政策页；政策本身以官方页面为准，这张表随政策复核（RK-16）。

| 约束                                         | 本功能怎么做                                                                                                                                                                                              | 依据                                                                                                                                                                                                |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 单一用途                                     | 下载是“把读到的内容留在本机”的另一种输出，终点是本地文件；不加账号、云端和站点专用的解析；商店文案不把它写成视频下载器                                                                                    | [质量指南](https://developer.chrome.com/docs/webstore/program-policies/quality-guidelines)                                                                                                          |
| 最小权限                                     | 页面下载只用已有的权限；Referer 还原只用一项没有安装警告的权限，并且先验证页面内取图是否已经够用（D-86、Q-24）                                                                                            | [权限政策](https://developer.chrome.com/docs/webstore/program-policies/permissions)、[declarativeNetRequest 参考](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest) |
| 无远程代码                                   | 转换、打包与后台文档都在扩展包内；媒体清单只来自当前页面，不从网络取规则                                                                                                                                  | [MV3 要求](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements)                                                                                                            |
| 用户数据只用于单一用途，披露清楚             | 页面内容与媒体只写本机、不发往任何第三方；权限、隐私政策与商店披露随改动同步（[permissions.md §7](permissions.md)）                                                                                       | [Limited Use](https://developer.chrome.com/docs/webstore/program-policies/limited-use)、[隐私政策要求](https://developer.chrome.com/docs/webstore/program-policies/privacy)                         |
| 不协助绕过付费墙或登录，不促成未经授权的下载 | 只处理用户正在看的页面里已出现的地址，逐次点击触发；不枚举、不猜测、不改写地址，不解析站点的流；`blob:`、HLS、DASH、DRM 与嵌入的播放器不取；不批量抓取；不带用户的 cookie；Referer 与浏览器显示该图时一致 | [违规与禁止内容](https://developer.chrome.com/docs/webstore/program-policies/malicious-and-prohibited)                                                                                              |
| 行为与描述一致                               | 只在点击之后发出请求；提示条显示进度与结果；失败可见，不静默                                                                                                                                              | [误导与意外行为](https://developer.chrome.com/docs/webstore/program-policies/unexpected-behavior)                                                                                                   |

## 7. 本地指标

下载结束（完成、部分、失败或取消）后记录一个本地事件，字段不含地址、标题和正文。事件与指标的口径见 D-87。

## 8. 失败与降级

| 情况                                | 处理                                                         |
| ----------------------------------- | ------------------------------------------------------------ |
| 受限页面（`chrome://`、扩展商店等） | 弹窗里“下载本页正文”不可用并写明原因；页面内入口不出现       |
| 没找到页面主体                      | 提示“没找到正文，请把指针停在正文上选一个区块”，不下载       |
| 上一个下载还在进行                  | 提示“上一个还在进行”，不开始新的                             |
| 个别媒体取不到、超限或类型不符      | 该项保留原地址，README 列出原因，其余照常                    |
| 全部媒体失败                        | 仍保存 Markdown，README 列全                                 |
| 断网                                | 只保存 Markdown（资料库里的截图用已保存的图片），README 说明 |
| ZIP 打包失败                        | 提示原因，给“重试”，并保证至少能单独下载 Markdown，不丢正文  |
| 浏览器拒绝或中断某个文件的下载      | 提示原因，给“重试”；已经写好的文件保留                       |
| 后台文档被浏览器关闭                | 这次下载失败，提示重试                                       |
| 取消                                | 见 §2.5                                                      |

上表里的提示都是本地化的短句，依据稳定的错误码生成，不显示浏览器的原始信息。

## 9. 验收与测试

- 10 张各不超过 2 MB 图片的文章页：从点击到文件落地的 95 分位小于 5 秒。
- 所有媒体都失败时，Markdown 仍然保存，README 逐项列全。
- 文件夹形态：落盘的文件清单与 Markdown 里的链接一致，包括浏览器给重名文件加序号之后；ZIP 形态：清单与链接一致。
- 取消之后不留下 Markdown 与媒体文件，也不再发出请求。
- 资料库多选 50 条（约 100 张图）可以完成，也可以中途取消；只用键盘能完成选择、下载与取消。
- 页面下载不改变权限清单；Referer 还原使清单恰好多一项权限，安装时没有新的权限警告，并且规则不改动页面自己发出的请求。
- 浏览器设置“下载前询问”的开与关，文件夹形态各走一遍（Q-25）。
