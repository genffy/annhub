# 下载

下载把页面里的一个区块或整页正文，或资料库里选中的条目，取成本地的 Markdown 文件夹（可选一个 ZIP），页面里的图片与直链的视频、音频一并取回。它的终点是文件：不建条目、不进资料库，与录屏一样“下载即终点”（[annotate.md §2.3](annotate.md)）。页面里的入口见 §2，资料库里的见 §3，产物见 §4，媒体见 §5，权限与数据边界见 §6。

## 1. 定位与边界

### 1.1 解决什么

- **为谁**：每周读大量网页资料、要把读到的内容带进别的工具继续写的工程师、产品/设计和研究者（[product.md §2.1](product.md)）。
- **问题**：剪藏只保存文字，图片只留原地址（[capture.md §3.1](capture.md)）；唯一的用户导出是整库 ZIP（[storage.md §6](storage.md)），取不出一篇文章或几条条目；Obsidian Web Clipper 默认也不下载图片（[market.md §4.2](market.md)）。用户要的是：读到一篇文章，一次点击就得到一个带图片、断网也能读的文件夹。

### 1.2 它不是什么

| 不是             | 区别                                                                                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 剪藏             | 剪藏建条目、进资料库，可阅读、高亮、检索；下载不建条目，产物在资料库之外，用别的工具打开                                                                                                                     |
| “导出内容”       | 整库导出是备份式：文件名只由受控 ID 生成，图片共用一个 `assets/`，不联网（[storage.md §6](storage.md)）。下载是取用式：按标题命名，每份自包含，可以联网取回图片。两者并存，互不替代                          |
| 整页剪藏、稍后读 | 下载由用户逐次点击触发，对象是用户指认的区块，或页面的主体文章（“文章”这种区块）；没有待下载的队列，不在库里阅读。不做清单（[product.md §2.3](product.md)）不变；整页剪藏进库仍另议（[Q-11](validation.md)） |
| 视频下载器       | 只取页面里的直链文件；流媒体、受保护的内容和嵌入的播放器不取（§5.2）                                                                                                                                         |

### 1.3 范围

- **范围内**：页面区块与页面主体文章的下载；资料库里单个与多选下载；页面里的图片，以及直链的视频与音频。正文尽量完整：评论串、折叠的内容、表格、提示框、公式与脚注都写进文件，不因长度截断（[capture.md §3.3](capture.md)）。
- **范围外**：直接写入用户选定的文件夹（Q-22）；`data:` 与 `blob:` 图片、内联 SVG 与 CSS 背景图（D-93）；需要登录 cookie 才看得到的图（Q-23）；定时或自动下载；跨标签页的批量下载。剪藏仍只留图片原地址，是否把图片存进库见 Q-21。

## 2. 页面上的入口

### 2.1 区块胶囊

- 区块胶囊上的动作是「剪藏 | 截图 | 下载 | 更多」。「下载」在「截图」之后、「更多」之前，图标加短文本；它与「剪藏」「截图」作用于同一个被描边的区块：点击后下载这个区块的 Markdown，以及区块里的媒体。
- 悬停时目标始终是指针下最内层的区块，胶囊上没有调整层级的按钮。要下载整页正文，用工具栏弹窗或命令（§2.3），或用区块模式选到“文章”再按 `D`（§2.2）。
- 同源 iframe 里的区块没有「下载」，与「截图」一样属于顶层页面（[capture.md §3](capture.md)）。
- 胶囊的出现时机、位置、不出现的情形和「更多」里的内容，同 [capture.md §6.2](capture.md)；区块入口被整体关闭或在某个网站停用时，胶囊不出现，弹窗与命令不受影响。
- 入口只响应用户的真实点击与按键；网页脚本合成的事件不触发下载。

### 2.2 区块模式

- 键盘区块模式用 `D` 下载当前目标，模式胶囊的按键说明里加“D 下载”；`Tab`、`↑` `↓`、`Enter`、`S`、`Esc` 同 [capture.md §6.2](capture.md)。同源子框架里的区块模式没有 `D`。

### 2.3 工具栏弹窗与命令

- 工具栏弹窗底部有「下载本页正文」（[extension.md §2.6](extension.md)），下载当前标签页的主体文章；`chrome://` 等受限页面上不可用，并写明原因。
- 另有一个命令「下载本页正文」，默认不绑定快捷键，用户在浏览器的快捷键设置里自己绑（[extension.md §7.1](extension.md)）。

### 2.4 页面主体

- 页面主体指页面上的“文章”区块，识别规则同 [capture.md §6.2](capture.md)；页面上有多个时取文字最多的一个。主体里有评论区时，评论属于主体（[capture.md §3.3](capture.md)）。没有 `article`、`main` 一类候选的页面（用表格排版的论坛与博客）怎么确定主体见 Q-30。
- 找不到时提示“没找到正文，请把指针停在正文上选一个区块”，不下载。

### 2.5 进度与结果

页面里出现一条提示条，样式同剪藏的提示条：

| 状态 | 提示                                                                               |
| ---- | ---------------------------------------------------------------------------------- |
| 进行 | 「正在下载 3/12 · 取消」，n 是已处理的媒体数，N 是总数                             |
| 完整 | 「已下载 · 显示文件」，在系统的文件管理器里显示这次下载                            |
| 部分 | 「部分下载：N 项媒体未保存」，未保存的项在 README 里                               |
| 失败 | 本地化的原因短句，依据稳定的错误码生成，不显示浏览器的原始信息；给“重试”，正文不丢 |

- 一次只进行一个下载，跨标签页也是；进行中再触发，提示“上一个还在进行”。
- **取消**：停止取回，取消在途的文件，删除已经写好的文件；浏览器已建好的空文件夹留下，提示里写明。取消后不留下 Markdown 与媒体，也不再发出请求。

## 3. 资料库里的下载

本节的规则按可测的结果写：每一条都能在浏览器里量出来或操作出来（验收见 §9）。

### 3.1 单个条目

- **入口**：详情抽屉头部与阅读视图顶栏各有一个「下载」，图标加文字，剪藏与截图条目都有（[extension.md §4.1、§4.2](extension.md)）。它下载这个条目的 Markdown 文件夹，提示文字是“下载为 Markdown”。
- **与下载图片分开**：截图卡片悬停时的按钮和抽屉图片节里的按钮下载的是图片本身，显示文字与读屏名称都是“下载图片”（[extension.md §2.3、§4.1](extension.md)）。同一屏上的两个下载，从名称上就分得清各自下载什么。
- **一条直接开始**，不弹准备态；形态与“同时下载媒体”取设置里的值。
- **状态条**：进度与结果显示在内容区底部居中的一条状态条里，浮在列表、抽屉与阅读正文之上，不推动它们的位置。多选的进度与结果在下载对话框里（§3.3），不用状态条。

| 状态 | 状态条                                                           | 何时消失           |
| ---- | ---------------------------------------------------------------- | ------------------ |
| 进行 | 「正在下载 3/12 · 取消」，n 是已处理的媒体数，N 是总数           | 结束时换成下面三种 |
| 完整 | 「已下载 · 显示文件」                                            | 几秒后自行消失     |
| 部分 | 「部分下载：N 项媒体未保存 · 显示文件」，未保存的项在 README 里  | 用户关闭           |
| 失败 | 本地化的原因短句与「重试」，依据稳定的错误码生成；已选的条目不丢 | 用户关闭或重试     |

- 一次只进行一个下载；进行中再点任何下载入口，状态条提示“上一个还在进行”，不开始新的。
- 进行与完整用状态播报，失败用提醒播报；状态条出现时不抢走焦点，其中的按钮在 `Tab` 顺序里。

### 3.2 多选

- **入口**：全部、剪藏、截图三个视图的页头右侧，搜索框之后有「选择」，当前视图里没有条目时它不可用；高亮、属性与设置视图没有。进入之后它留在原位，显示为按下的状态（`aria-pressed`），再点一次退出；进入时已打开的详情抽屉关闭。
- **选择条取代筛选条**：进入选择模式时，筛选条的位置换成选择条，退出时换回，筛选条的内容原样不变。两者同高：进入与退出选择模式，列表里每张卡片的位置与大小都不变。选择条不是网格里的一个单元，也不在筛选条之外另占一行。
- **选择条固定**：列表滚动时选择条留在滚动区的顶部，卡片从它下面经过。
- **一行排完**，从左到右：退出（图标按钮，读屏名称“退出选择”）、「已选 N 条」、「全选 M 条」、「清除」，行尾是唯一的动作「下载所选」，主按钮。放不下时先省略说明文字，再把「全选 M 条」缩成「全选」，不折行。
- **数量与可用性**：「已选 N 条」是状态播报，每次变化后播报最新的数。N 为 0 时「清除」与「下载所选」不可用，「下载所选」的提示文字是“先选择条目”。「全选 M 条」选中当前列表（搜索与筛选之后）的全部 M 条，不只是已经加载的几页。
- **搜索与筛选不可用**：选择条取代了筛选条；页头的搜索框置灰（`aria-disabled`），说明是“选择时无法搜索”，`/` 不响应。选择因此始终对应眼前这一份列表；退出后搜索词与筛选原样保留。从导航切到别的视图会退出选择并清空；选择状态不写进地址。
- **卡片**：整张卡片是一个点击目标，点击切换选中，不打开抽屉；卡片里的标签与属性小标签不单独响应（不触发筛选）；截图卡片悬停时的下载图片与删除隐藏。
- **选中标记**：每张卡片的左上角有一个圆形标记，圆心落在卡片的角上，是自绘的，不用浏览器原生的复选框。它盖住的只是卡片的外角：标题、标签与预览文字不被遮挡，缩略图只被遮住最外角的一小块；它不改变卡片的布局。
- **选中态不只靠颜色**（[visual.md §4](visual.md)）：已选中的卡片，标记变成实心并带对勾，卡片的边框加粗，读屏读出“已选中”。五种状态彼此看得出来：未选中、悬停（标记描边加深）、键盘焦点（卡片外加焦点环）、已选中、选满上限后未选中的卡片（标记置灰、卡片变淡、`aria-disabled`）。抽屉里正在查看的卡片是另一种样式（描边加光晕），选择模式里没有打开的抽屉。
- **鼠标**：点击切换；`Shift` 加点击选中上一次点击的卡片到这张卡片之间、按列表顺序的全部卡片，不取消已选的。
- **键盘**：卡片都在 `Tab` 顺序里，读屏角色是复选框（`aria-checked`），名称是卡片的标题与来源；`Space` 切换焦点所在的卡片；`Shift` 加 `Space` 同 `Shift` 加点击；`Ctrl` / `⌘` 加 `A` 同「全选 M 条」（焦点在输入框里时除外）；`Esc` 退出并清空，有对话框打开时先关对话框；选择条是一个工具栏。进入选择模式后焦点留在「选择」上，退出后回到它。
- **上限**：一次最多选择 200 条。「全选 M 条」在 M 超过 200 时不可用，选择条的说明写“一次最多选 200 条”；选满 200 条后其余卡片不可再选，说明写“已选满 200 条”；`Shift` 加点击的区间超出上限时，选到上限为止。

### 3.3 下载对话框

- 沿用“导出内容”对话框的壳与键盘行为（[extension.md §2.2](extension.md)）：打开时焦点落在对话框里，`Tab` 在其中循环，关闭后焦点回到「下载所选」。头部是标题「下载所选条目」与一个状态标签（准备、进行中、完整、部分、失败、已取消）。
- **准备态**：一行摘要“N 条 · 剪藏 X · 截图 Y，预计约 F 个文件”；形态（文件夹或 ZIP 的分段选择，默认取设置）；「同时下载媒体」（图片、视频与音频，需要联网，默认取设置；离线时不可选，说明“当前离线，只保存 Markdown”）；按钮「取消」与「下载」，焦点先落在「下载」上。预计文件数超过 100 时，形态下方出现一行建议“文件较多，建议选 ZIP”，不自动切换。
- **进行态**：进度条与 n/N（同 §2.5），一句当前阶段（取回媒体、写入文件），按钮只有「取消」。联网取回可以取消，这一点不同于整库导出的“开始即完成”。进行中 `Esc` 与点遮罩都不关闭对话框，只有「取消」停止下载，避免误触丢掉一次长下载；取消的结果见 §2.5。
- **结果**：完整（「显示文件」「完成」）；部分（未保存的前几项连同原因，完整清单在 README；「显示文件」「完成」）；失败（本地化的原因短句；「重试」「关闭」）；已取消（写明已写好的文件已删除；「关闭」「重新下载」）。横幅的样式同“导出内容”。
- 对话框关闭之后，选择模式与已选的条目保持原样，便于改形态后重新下载；要结束选择，用选择条的退出或 `Esc`。

### 3.4 内容

- 读取已保存的条目与图片；frontmatter 与章节同整库导出（[storage.md §6](storage.md)），高亮写成 `==…==`。
- 截图条目用已保存的图片字节，不联网。剪藏里的远程媒体联网取回（§5.3）；取消勾选或断网时只写 Markdown，媒体保留原地址，README 说明。
- 条目的正文是入库时已经转换好的 Markdown，下载不重新转换：拿到的是入库的写法与内容（受 [capture.md §3.1](capture.md) 的上限与过滤约束），不是 [capture.md §3.3](capture.md) 的下载写法，要完整的页面内容就回到原页面下载；转换规则的变化只体现在之后剪藏的条目里。

## 4. 产物

### 4.1 形态

| 形态           | 落到哪里                            | 说明                                                                                                                                          |
| -------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件夹（默认） | 浏览器下载目录下的 `AnnHub/<标题>/` | 一批独立的下载，由浏览器逐个写入；先写媒体、最后写 Markdown，Markdown 里的链接按媒体落盘后的实际文件名写；同一个标题再次下载时文件夹加 ` (2)` |
| ZIP            | `AnnHub/<标题>.zip`                 | 一个文件，内容是同一棵目录树，一次下载                                                                                                        |

- 设置页有一张「下载」卡片（[extension.md §2.5](extension.md)）：形态（文件夹或 ZIP，默认文件夹）和“同时下载媒体”（默认开）；资料库的下载对话框可以临时改（§3.3）。
- 文件夹形态的代价：浏览器设置了“下载前询问每个文件的保存位置”时，每个文件都会弹出保存对话框（[market.md §4.7](market.md)）。设置页在形态旁写明这一点，并建议此时改用 ZIP。多个文件连续下载的实际表现见 Q-25。
- 扩展不弹自己的另存为对话框，同截图与录屏的下载（[annotate.md §2.1](annotate.md)）。
- 不直接写入用户选定的文件夹（Q-22）。

### 4.2 目录结构

```text
AnnHub/<标题>/                       文件夹形态；ZIP 形态是 AnnHub/<标题>.zip 里的同一棵树
├── <标题>.md                        frontmatter + 正文，媒体用相对链接
├── assets/                          img-001.jpg … video-001.mp4（序号 + 响应类型决定的扩展名）
└── README.md                        只在有未保存的媒体时出现：每一项的原地址与原因

AnnHub/AnnHub-download-YYYY-MM-DD/   资料库多选（文件夹形态）；ZIP 形态是 AnnHub-download-YYYY-MM-DD.zip
├── README.md                        条目清单与失败清单
├── <条目标题 A>/ …                  每条一个同样结构的文件夹
└── <条目标题 B>/ …
```

页面里没有可取的媒体时没有 `assets/`。日期是下载当天的本地日期。

### 4.3 Markdown 的内容

- **页面下载**：frontmatter 有 `title`、`source`、`author`、`published`、`created`、`description`，键名对齐 Obsidian Web Clipper 的默认模板（同 [storage.md §6](storage.md)）；`title` 取页面标题，区块或主体文章是 X 的帖子或长文时取平台规则给出的标题；`author`、`published` 也以平台规则为先（[capture.md §3.2、§5](capture.md)）；`source` 取区块的来源地址并去掉带令牌特征的参数（[capture.md §5](capture.md)），`created` 是下载当天的本地日期；取不到的字段不写。正文是区块或主体文章转换出的 Markdown，转换规则同 [capture.md §3.1、§3.2](capture.md)，再加下载取用的规则（[capture.md §3.3](capture.md)）。
- **更多元数据**：frontmatter 还可以有 `site`（站点名）、`language`（页面语言）和 `image`（封面图的地址，只写地址，不取回，不进 `assets/`）；`author`、`published`、`description` 依次取平台规则、页面内嵌的结构化数据和页面 meta（[capture.md §3.2、§5](capture.md)）；取不到的字段不写。
- **X 的帖子与长文**：正文是平台规则组装的结果：被引用的帖子是引用块，没有头像、互动数与推广，长文只有正文；`assets/` 里只有 Markdown 引用的图片。
- **资料库条目**：frontmatter 与章节同整库导出，含 `annhub_` 键和全部属性。
- **媒体**：图片、视频与音频都写成指向 `assets/` 的相对链接的图片语法（`![标题](assets/video-001.mp4)`，阅读工具支持的内嵌播放就内嵌，不支持的显示为坏图）；没取到的媒体保留原地址。
- 页面下载的正文不截断，不受入库字数上限的限制（Q-17 是入库的口径）；公式、删除线与脚注用下载的写法（[capture.md §3.3](capture.md)，D-91）。

### 4.4 文件名

- 文件夹名与 Markdown 的文件名由标题清洗而来：去掉 `\ / : * ? " < > |` 与控制字符；折叠空白；去掉首尾的点和空格；避开 Windows 的保留名；最长 80 个字符；标题为空时用来源的主机名；同一批里重名加 ` (2)`。标题取 §4.3 的 `title`，资料库里取条目的标题；信息流里的帖子因此以自己的标题命名，不叫页面标题。
- 媒体的文件名只由序号和响应类型生成，永远不取自网页。
- 这与整库导出“路径只由受控 ID 生成”并存（[storage.md §6](storage.md)），整库导出不变。

## 5. 媒体

### 5.1 取哪些

- 只取页面自己声明的地址。`<img>` 有 `srcset`（含 `data-srcset`）时取其中最大的一项，按宽度描述符或像素密度比，不取当前屏幕选中的小档；`<picture>` 里取浏览器选中的那个 `<source>` 的 `srcset` 里最大的一项。没有 `srcset` 时顺序是：`currentSrc` → http(s) 的 `src` → `data-src` / `data-original` / `data-actualsrc` / `data-lazy-src`。`src` 是 `data:` 占位图时，用后面的地址。`<video>` 的 `poster` 按图片处理。
- 一张图有几个候选地址时（`srcset` 的各档、页面声明的其他地址），从大到小依次取：前一个取不到、超限或类型不符就试下一个，全部失败才算这一项未保存。
- 同一个地址只取一次；小于 16 像素的图和追踪像素不取。
- 取回的就是 Markdown 里写成图片语法的那些地址：Markdown 引用的每个远程媒体都取，`assets/` 里没有 Markdown 不引用的文件；转换时已经丢掉的图（头像、徽章、界面图标）和写成字符的表情小图不取。是否取回与元素当前是否显示无关：关闭的 `<details>` 与折叠面板里的图，只要 Markdown 引用了就取。
- 不改写地址去换更高清的版本（X 图片的档位见 D-90；`srcset` 里页面自己声明的更大一档不算改写），不猜测、不枚举页面没有引用的地址。

### 5.2 种类

| 种类       | 规则                                                                                                                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 图片       | 响应须是 `image/*`；SVG 不取（可以带脚本），保留链接；单张不超过 20 MB                                                                                                                        |
| 视频、音频 | 只取 http(s) 直链的 `<video>` `<audio>` `<source>`；响应须是 `video/*` 或 `audio/*`；单个不超过 200 MB；大体量文件的打包见 Q-26                                                               |
| 不取的     | `blob:` 与 `mediastream:` 地址、HLS（`.m3u8`）、DASH（`.mpd`）、受 DRM 保护的内容、`<iframe>` 嵌入的播放器。保留原链接，视频有封面（`poster`）时附封面图；嵌入的播放器写成 `[标题](嵌入地址)` |

### 5.3 怎么取

- 取回由扩展在用户点击之后进行；字节不经过网页，也不发往任何地方，只写进产物。
- 规则同截图代取页面图片（[screenshot.md §2](screenshot.md)）：只接受公网 http(s) 地址，拒绝本机、局域网、链路本地和带账号的地址，不带凭据；另外重定向之后重新检查，响应类型和大小在读取时校验。
- 不带 cookie；登录后才看得到的图保留原地址（Q-23）。
- 按 Referer 拦截的图床：扩展发出的取图请求目前不带页面的 Referer，这类图床可能拒绝；取不到的图保留原地址并写进 README。是否还原 Referer 另行交付（D-86），资料库条目届时用条目来源页的来源（D-89）；各图床的实际表现见 Q-24。
- 同时取回 4 个；一个请求 30 秒没有进展就放弃这一项；一次下载合计不超过 1 GB、最多 500 个文件。

### 5.4 取不到

- 单个媒体取不到、超限或类型不符：Markdown 保留原地址，README 列出这一项的原地址和原因，其余照常保存。
- 全部取不到：Markdown 照常保存，README 列全。断网：只保存 Markdown，README 说明。
- 不因为媒体失败而让整个下载失败，也不丢已经转换好的正文。按 Referer 或 cookie 拦截的图床是常见原因（RK-17）。

## 6. 权限与数据边界

### 6.1 权限

| 权限                      | 用途                                                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `downloads`               | 把产物写成下载目录下的相对路径文件；路径不含 `..`，不绕过浏览器的下载确认与危险文件拦截                                  |
| `offscreen`、`<all_urls>` | 取回与打包在扩展自己的后台文档里进行，与录屏共用同一个后台文档（Q-26）；`<all_urls>` 让取回绕开页面的 CORS，同截图的代取 |

- 页面下载不新增任何权限：`downloads`、`offscreen`、`<all_urls>` 都已为截图、录屏与导出申请过，这里只是新用途（[permissions.md §2、§3](permissions.md)）。
- 取图时把 Referer 还原为页面来源所需的 `declarativeNetRequestWithHostAccess` 尚未申请，与 `declarativeNetRequest`、`webRequest`、`cookies`、`debugger`、`scripting` 一样在本功能之外（D-86，[官方参考](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)）。

### 6.2 数据边界

- 页面内容与媒体只写到用户本机，不发往 AnnHub 或第三方；没有账号。
- 出站请求只发往页面自己引用的媒体主机，只在用户点击之后，同时取回不超过 4 个。
- 对方（图床）能看到：用户的网络地址、被请求的地址、页面的来源（Referer），以及请求可能显示为来自本扩展（Origin 带扩展 ID，Q-24 核实）。这些写进隐私政策（[permissions.md §6](permissions.md)）。
- 日志与指标不含地址、标题、正文和媒体（[metrics.md §9](metrics.md)）。

## 7. 本地指标

下载结束（完成、部分、失败或取消）后记录一个本地事件 `download.completed`，属性是 `source`（page / library）、`via`（capsule / block_mode / popup / command / drawer / reading / selection）、`scope`（block / page / entry / multi）、`form`（folder / zip）、`block_kind`、`result`（ok / partial / failed / cancelled）、`media` 与 `missing`（分桶数），不含地址、标题和正文；它服务下载使用率指标 M-32（[metrics.md §9](metrics.md)）。

## 8. 失败与降级

| 情况                                | 处理                                                                                                                    |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 受限页面（`chrome://`、扩展商店等） | 弹窗里“下载本页正文”不可用并写明原因；页面内入口不出现                                                                  |
| 没找到页面主体                      | 提示“没找到正文，请把指针停在正文上选一个区块”，不下载                                                                  |
| 上一个下载还在进行                  | 提示“上一个还在进行”，不开始新的                                                                                        |
| 个别媒体取不到、超限或类型不符      | 该项保留原地址，README 列出原因，其余照常                                                                               |
| 全部媒体失败                        | 仍保存 Markdown，README 列全                                                                                            |
| 断网                                | 只保存 Markdown（资料库里的截图用已保存的图片），README 说明                                                            |
| ZIP 打包失败                        | 提示“ZIP 打包失败，正文已保留。重试将改用文件夹下载。”；重试保留正文、条目选择与媒体选项，使用文件夹，不再依赖 ZIP 打包 |
| 浏览器拒绝或中断某个文件的下载      | 提示原因，给“重试”；已经写好的文件保留                                                                                  |
| 后台文档被浏览器关闭                | 这次下载失败，提示重试                                                                                                  |
| 页面很长                            | 正文完整保存，不截断；媒体仍受 §5.3 的合计上限                                                                          |
| 过滤后正文为空                      | 只按标签与角色去界面，重转一次；仍为空才降级为纯文本                                                                    |
| 取消                                | 见 §2.5                                                                                                                 |

上表里的提示都是本地化的短句，依据稳定的错误码生成，不显示浏览器的原始信息。

## 9. 验收与测试

- 10 张各不超过 2 MB 图片的文章页：从点击到文件落地的 95 分位小于 5 秒。
- 所有媒体都失败时，Markdown 仍然保存，README 逐项列全。
- 文件夹形态：落盘的文件清单与 Markdown 里的链接一致，包括浏览器给重名文件加序号之后；ZIP 形态：清单与链接一致。
- 取消之后不留下 Markdown 与媒体文件，也不再发出请求。
- X 帖子下载（正文两段、一条被引用的帖子、两张图）：被引用的帖子是 `>` 引用块；两段正文之间是空行；作者行有显示名、账号与日期；没有头像、互动数、浏览量，也没有“12h”这样的相对时间；`assets/` 里恰好是正文里的这两张图，没有头像；Markdown 里的每个图片链接都指向 `assets/` 里存在的文件，`assets/` 里的每个文件都被引用。
- X 长文下载：全文只有一个 `#` 标题，节标题是 `##`；代码块之前没有单独成段的语言标签；列表条目行不为空；加粗与斜体的记号最多三个星号，且不吞掉两侧的空格；没有作者卡、“更多文章”与升级提示。
- 信息流（如时间线）里的帖子：文件夹名与 `title` 是这条帖子自己的标题，不是页面标题；同一页里不同帖子的文件夹名不同。
- 平台规则用两种页面结构的真实页面做夹具（Q-27），两份的作者行、正文、引用块与图片一致；锚点找不到时退回通用转换，仍然保存。
- 长页：可见文字约 7 万字符、转换后的 Markdown 超过 10 万字符的页面（词条很长的百科页）：下载的 Markdown 完整，最后一节在，没有截断提示；同一页的剪藏仍在 100,000 字符处截断并提示。
- 评论：有 20 条以上评论的 issue 页：楼主与每条评论各有作者、时间与正文，没有头像、站点导航和写评论的表单；评论区在主体文章之外的博客页，下载主体文章不带评论。
- 结构：`figure` 里的多张图、表格、引用与图注，段落里的视频与嵌入，文档站的提示框（引用块），`dl`、从 3 开始的 `ol`、任务列表的勾选状态，在文件里各有对应的写法，顺序不变；带 `caption`、`rowspan`、`colspan` 的表，每一行的列数一致、表头对得上列，格子里的多个段落有可见的分隔。
- 公式、上下标、删除线与脚注：含 30 个以上公式的页面：公式是 `$…$` 或 `$$…$$` 里的 TeX，没有平铺成 `Erel2−…` 这样的文字；`10<sup>8</sup>` 写成 `10⁸`，`<del>` 写成 `~~…~~`；页内脚注是 `[^n]` 加文末的定义，不指向来源页；正文里的 `$` 与 `~` 已转义。
- 折叠与切换：关闭的 `<details>` 与 `aria-expanded="false"` 控制的面板里的文字和图都在文件里，`assets/` 里有这些图；标签页组只有显示的那一页。
- 代码块：页面自己标了语言的代码块（如文档站页面里的 19 个示例），每一个都带语言标记；页面没标的不写。
- 图片：有 `srcset` 的图取最大的一档，取不到时依次退到较小的；表情小图不在 `assets/` 里。
- 元数据：只有结构化数据带作者与发布日的页面，frontmatter 的 `author` 与 `published` 有值；有站点名、页面语言、封面图的页面有 `site`、`language`、`image`。
- 夹具：以上每条规则各有一份消毒后的最小页面夹具和一条用例；百科页、issue 页、文档站页各存一份真实页面的夹具做回归。
- 资料库多选 50 条（约 100 张图）可以完成，也可以中途取消；只用键盘能完成选择、下载与取消。
- 选择模式不改变列表：进入与退出时，每张卡片的位置与大小不变（0 像素偏差）；选择条在筛选条的位置、与它同高，不是网格里的一个单元；列表滚动时选择条留在滚动区顶部。
- 选中标记不遮挡任何卡片的文字：有标题与无标题、有标签与无标签的剪藏，以及截图，各量一次。已选中的卡片与未选中的，去掉颜色之后仍分得出来（对勾、边框、读屏的“已选中”）。
- 选择模式里卡片上的标签与属性小标签不触发筛选，搜索框置灰且 `/` 不响应；退出后搜索词与筛选原样保留。
- 单条下载的状态条出现与消失时，列表、抽屉与阅读正文的位置不变；同一屏上的“下载”与“下载图片”从名称上就能分清。
- 进行中的下载对话框不被 `Esc` 或点遮罩关闭。
- 页面下载不改变权限清单；Referer 还原作为后续交付（D-86），届时它的验收是：清单恰好多一项权限，安装时没有新的权限警告，并且规则不改动页面自己发出的请求。
- 浏览器设置“下载前询问”的开与关，文件夹形态各走一遍（Q-25）。
