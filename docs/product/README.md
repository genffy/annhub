# AnnHub 产品文档

> 状态：产品的行为、数据契约与验收；新功能在实现它的 PR 里写进来。工程约定从 [AGENTS.md](../../AGENTS.md) 进入。
> 更新：2026-10-24

AnnHub 是一个本地优先的浏览器扩展：把网页中值得留下的内容，用剪藏（选区或整块）和截图连同来源存进同一个本地库；再在库里阅读、划出高亮、加上可扩展的属性，之后可检索、回到来源或导出为 Markdown ZIP。产品不承诺从该 ZIP 恢复 AnnHub 数据库。

## 1. 五分钟读懂

| 问题     | 回答                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| 为谁     | 每周读大量网页资料、并要产出设计文档、方案或分析的工程师、产品/设计和研究者（[product.md §2](product.md)）       |
| 解决什么 | 保存之后找不回、分不清：书签、高亮、截图散在不同工具里，脱离了来源                                               |
| 怎么做   | 页面里剪藏（选区或整块）与截图，库里读剪藏并高亮；一种条目格式、可扩展的类型化属性、一个统一的资料库             |
| 在哪做   | 浏览器扩展                                                                                                       |
| 赢的标志 | 待定（[Q-08](validation.md)）                                                                                    |
| 不做什么 | 团队协作、手机端与桌面客户端、通用笔记、稍后读收件箱、AI 功能、网页上的高亮标记（[product.md §2.3](product.md)） |
| 底线     | 本地优先；断网也能采集和导出；失败不丢用户输入                                                                   |

```text
采集（剪藏 / 截图） -> 条目 -> 阅读与高亮、加属性 -> 检索、回看、导出
```

| 环节 | 用户动作                                   | 主要界面                       | 规则文档                                           | 关键指标   |
| ---- | ------------------------------------------ | ------------------------------ | -------------------------------------------------- | ---------- |
| 采集 | 选中内容、指一下整块或框选画面，点一下     | 选区菜单、区块入口、截图遮罩   | [capture](capture.md)、[screenshot](screenshot.md) | M-03       |
| 整理 | 在库里读剪藏并划出高亮；给条目加标签与属性 | 资料库的阅读视图、详情与属性页 | [extension §4](extension.md)、[entry](entry.md)    | M-21、M-20 |
| 找回 | 搜索、筛选、回到来源、导出                 | 资料库                         | [search](search.md)、[storage](storage.md)         | M-19       |

一条完整的走查见 [examples.md §2](examples.md)。

## 4. 术语表

| 术语               | 含义                                                                                                   | 数据字段或归属                    |
| ------------------ | ------------------------------------------------------------------------------------------------------ | --------------------------------- |
| 条目（Entry）      | 一次采集的结果：内容（Markdown 文字或图片）+ 来源 + 用户的备注和属性。剪藏与截图共用同一种记录         | [entry.md](entry.md)              |
| type（类型）       | 条目的类别，共两种：剪藏、截图；创建后不可改                                                           | `clip` / `screenshot`             |
| 剪藏（Clip）       | 保存一段选中的内容，或指一下保存一个整块（推文、文章），供之后阅读；一次点击完成，正文是 Markdown      | [capture.md §2](capture.md)       |
| 区块（Block）      | 指一下就能整体保存的内容单元，共七种：帖子、代码块、表格、图、引用、一节、文章；用于区块剪藏与元素截图 | [capture.md §6.2](capture.md)     |
| 高亮（Highlight）  | 用户在资料库里读剪藏时划出的标注（范围、颜色、备注），保存在这条剪藏里，不写进网页                     | [entry.md §4](entry.md)           |
| 阅读视图           | 资料库里显示一条剪藏正文的页面，可在其中选中文字创建高亮                                               | [extension.md §4.2](extension.md) |
| 截图（Screenshot） | 区域或元素截图，处理后的图片保存为条目                                                                 | [screenshot.md](screenshot.md)    |
| 属性（Property）   | 条目上带类型的短小键值；名称与类型全局绑定                                                             | [entry.md §5](entry.md)           |
| 类型预设           | 每种条目类型采集时自动附加的一组属性                                                                   | [entry.md §5.4](entry.md)         |
| 资料库（Library）  | 扩展里统一查看、检索和整理条目的应用页                                                                 | [extension.md §2.2](extension.md) |
| 语境 / 来源        | 能重新理解选区的最小上下文 / 页面地址；“回到来源”只打开来源页                                          | `context` / `sourceUrl`           |
| 导出内容           | 扩展生成的 Markdown（属性即 frontmatter）+ 原图 ZIP，供其他工具阅读，不可恢复 AnnHub 数据库            | [storage.md §6](storage.md)       |

## 6. 维护方式

- 字段、规则、页面流程各在上表的真源修改，其他文档只给摘要和链接。
- 新功能在实现它的 PR 里同时修改归属文档（契约、用户故事与验收、指标），产品负责人在评审里确认；拿不准的决策与阈值登记在 [validation.md](validation.md)。规则见 [AGENTS.md](AGENTS.md)。
- 新增条目类型或内置属性只在 [entry.md](entry.md) 登记，再补采集流程、故事和测试，清单见 [entry.md §8](entry.md)。
- [设计稿](../design/README.md)只做视觉与交互表达：文案和规则先改本目录，再同步设计稿，设计稿里不另写规则。
- 只用相对链接；移动文件时同步修复仓库内引用。修改日期写实际日期。
