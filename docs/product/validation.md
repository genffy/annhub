# 待决事项：决策、风险与开放问题

本文登记三类还没有结论的事：**等待产品负责人确认的决策**、**需要盯住的风险**、**尚无答案的开放问题**。已确认的结论只写在各自的真源文件里；本文的条目有了结论，就写进归属文件，并从本文删除。

## 1. 规则

1. 未确认的方案与阈值只在本文登记，不写进其他真源文件。其他文件需要引用时，只写条目 ID（如“见 Q-17”）。
2. 每个条目有稳定 ID：决策 `D-`、风险 `RK-`、开放问题 `Q-`。ID 不复用，不因排序变化。
3. 新功能不在这里排队：功能的契约、用户故事与验收和代码在同一个 PR 里修改，产品负责人在评审里确认（[AGENTS.md](AGENTS.md)）。实现中拿不准、又不必等回复的方案或阈值，登记为决策或开放问题，写明先按什么默认走。
4. 阈值是方向性判据，不是统计结论；报告比例时同时报告分母。
5. 外部事实类文档（[market.md](market.md)）每 90 天复核。

## 2. 决策登记

每条待确认的决策给出选项、推荐和“无回复时的默认”。实现不等回复，先按默认走；产品负责人确认的结果与默认不同，再调整。实现该决策的改动合并进 main 时，结论写进归属文档，并从本文删除该条目（合并进 main 即产品负责人确认）。

### D-86 还原 Referer 与新增的权限

背景：浏览器的“图片另存为”带着页面的 Referer 与 cookie，所以对按 Referer 拦截的图床有效；扩展页面发出的取图请求默认没有页面的 Referer（实际带什么以 Q-24 的实测为准），这类图床可能拒绝。公开反馈称部分图床拒绝空 Referer（[V2EX 讨论](https://www.v2ex.com/t/904989)、[一个下载脚本的修复](https://github.com/little-bodhisattva/little-bodhisattva.github.io/pull/2)），未必反映现状，本项目没有复现。还原 Referer 需要权限 `declarativeNetRequestWithHostAccess`：[官方参考](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)写明它安装时不显示权限警告，使用前须有主机权限，扩展已有 `<all_urls>`。
选项：A 不还原，权限不变，被拦的图保留原地址并写进 README；B 还原 Referer，新增这一项权限，用只在下载期间存在的规则给扩展自己发出的取图请求设置 Referer；C 在页面内取图，不加权限，但受页面 CORS 限制，跨域图床大多取不到。
默认：B，作为单独的一次交付，晚于页面下载本身；交付前先按 Q-24 验证，页面内取图或不带 Referer 的取图已能覆盖常见图床，就不新增这项权限。规则只作用于扩展自己发出的请求、本次下载涉及的图床主机，只设置 Referer 一个头，值是页面的来源，与浏览器显示该图时发的一致。
影响的文档：[download.md §5.3、§6.1](download.md)；[permissions.md §2、§3、§4、§7](permissions.md)；隐私政策页的权限表与数据流；商店的权限说明与隐私披露；[roadmap.md §4](roadmap.md) 里权限一致的门禁句。

### D-89 资料库里取图用的 Referer

背景：页面里的下载用当前页面的来源作 Referer（D-86）；资料库里没有那个页面，只有条目保存的来源地址。
选项：A 条目来源页的来源；B 图片自己所在站点的来源；C 不设置。
默认：A——与用户当时在那个页面看到图片时浏览器发的 Referer 一致。
影响的文档：[download.md §5.3](download.md)。

### D-90 X 的图片取原图档位

背景：X 页面里帖子的图片是缩略图档位——时间线与被引用的帖子里是小档，长文封面是中档。按页面声明的地址取，得到的就是缩略图：一张图的小档宽 680 像素，同一张的原图宽 1102 像素；一张长文封面的中档宽 1200 像素，原图宽 1983 像素。[download.md §5.1](download.md) 写着“不改写地址去换更高清的版本”，[download.md §6.3](download.md) 也把它列为守住的约束。
选项：A 不改写，取页面声明的地址（缩略图）；B 对 X 的图片按固定的平台规则取同一张图的原图档位：把地址里的档位参数改成原图，格式取 jpg 或 png（webp 格式的原图档位取不到：`format=webp&name=orig` 报错，`format=jpg&name=orig` 正常），原图取不到时回退页面声明的地址；只作用于 X 的图片，不改写其他站点的地址。
默认：B，作为单独的一次交付，可整体摘掉：商店审核对“改写地址”有异议时退回 A，不影响其余。理由：这是页面所在图床上同一张图的更大版本，不涉及登录与付费墙，也不枚举页面没有引用的图（RK-16）。
影响的文档：[download.md §5.1、§6.3](download.md)（“不改写地址”改为含这条平台规则）；RK-16 的对策。

### D-91 下载用比阅读视图更丰富的 Markdown 写法

背景：阅读视图、纯文本化与转换三处约定的写法很少：粗体、`==` 高亮、斜体、行内代码、链接、图片，以及段落、标题、代码块、引用、列表、表格、分隔线。下载的产物在别的工具里打开（Obsidian、Typora、VS Code），它们认得更多写法（`~~删除线~~`、`$公式$`、`[^脚注]`）。只用那一小套，公式会平铺成一串乱码，删除线与脚注的含义丢了；页内脚注的角标还指向来源页的锚点，断网时点不开。
选项：A 下载与剪藏共用那一小套写法，公式与删除线只留文字；B 下载用更丰富的写法，剪藏停在那一小套（[capture.md §3.3](capture.md) 的表）；C 让阅读视图也认得这些写法，两处共用，剪藏的存储契约与转义的约定一起改（Q-28）。
默认：B。下载是文件，剪藏是库里的记录，读的工具不同；C 的改动面大，还会让已存的剪藏与新写法混在一起。下载写法里正文的 `$` 与 `~` 也要转义。
影响的文档：[capture.md §3.1、§3.3](capture.md)；[download.md §4.3](download.md)。

### D-92 下载里的评论与讨论串

背景：转换按类名与 id 里的整词（`comment`、`reply`、`related`、`like`、`share`、`ad` 等）剔除页面的界面，评论区跟着被剔除。剪藏时少存无妨；下载时评论串常是内容本身：一个有二十多条评论的 issue 页只剩楼主的一条，论坛主题页的回复就是主体。反过来，有的博客把评论区放在 `article` 里面，一并下载会带上用户不要的内容。
选项：A 下载沿用剔除；B 用户指认的区块里有评论就下载，评论入口（表单、评论数的链接、回复与点赞按钮）仍去掉；C 默认不带，设置里加“下载时包含评论”的开关。
默认：B——用户指认的是什么就下载什么。评论区在主体文章之外的博客（常见的做法）不受影响，评论在主体之内的页面（issue、讨论串）得到完整内容；放宽带来的噪声多时退回 A（RK-19）。
影响的文档：[capture.md §3.1、§3.3](capture.md)；[download.md §2.4](download.md)。

### D-93 页面里不是 `<img>` 的图：内联 SVG 与 CSS 背景图

背景：文档里的架构图与图表常以内联 `<svg>` 出现，新闻站的头图常是 `div` 的 CSS 背景。这两种现在都不进产物，文章的图缺了一块。SVG 文件可以带脚本，所以 SVG 地址也不取（[download.md §5.2](download.md)）。
选项：A 不取（现状），继续是范围外；B 内联 SVG 按页面上显示的样子栅格化成 PNG 写进 `assets/`（不执行任何脚本；页面的样式要连同带上，否则与页面上看到的不一样），CSS 背景图按页面计算样式声明的地址取回；C 清理脚本之后保存 SVG 本身，保留矢量，但要做消毒。
默认：B，作为单独的一次交付，排在其余之后，可整体摘掉。初始值：栅格化取显示尺寸的 2 倍，长边不超过 4096 像素；只取有语义的图（`role="img"`、带标题或替代文字，边长不小于 64 像素，且不是按钮与链接里的图标），不取装饰。
影响的文档：[download.md §1.3、§5.1、§5.2](download.md)；RK-16 的对策。

### D-96 页面上取目标统一成截图取景的取法

背景：页面上有两套取目标的规则。区块胶囊与区块模式按七种区块识别（[capture.md §6.2](capture.md)），段落不是单元，指针停在一段正文上取它所在的一节或整篇文章，停约 400ms 才出现；截图取景取指针下最内层的块级元素，指针一动就描边，`↑↓` 沿祖先换层级（[screenshot.md §1.2](screenshot.md)），单击时放得进窗口就裁真实像素，而胶囊的截图一律克隆栅格化。产品负责人的判断是截图取景的选区又快又准。
选项：A 维持两套规则，只让胶囊的截图与编辑气泡跟描边一致，capture.md §6.2 写明首个标题之前的段落取文章；B 一条目标链，三个入口共用：以截图取景的取法起步（指针下最内层的块级元素，跳过外框相同的层），标题与段落平铺的页面上把一节作为一层插进链里（段落、一节、文章），帖子、代码块、表格、图、引用照识别规则各成一层；胶囊悬停、区块模式与截图取景都从最内层起，描边、剪藏、下载、截图只读同一个目标，截图放得进窗口裁真实像素、放不下再克隆；C 只把胶囊的截图改成和单击元素同一条截取路径，取目标的规则不变。
默认：B。指到哪一块就是哪一块，三个入口描出的范围相同；一节靠插进链里的那一层保住，平铺页面上从段落往外一层是一节，不会一步跳到整篇；首个标题之前的段落没有一节，外一层直接是文章。悬停不接管方向键（页面要用它们滚动），胶囊上加一个“外一层”按钮，按到最外一层后回到最内层，指针移到别的块上也回到最内层；停留时间与胶囊位置不变，不出现的情形与目标标注见 D-97。
影响的文档：[capture.md §6.2](capture.md)；[screenshot.md §1、§1.2、§1.4](screenshot.md)；[download.md §2.1、§2.2](download.md)；[user-stories.md](user-stories.md) 的 US-CAP-10、US-CAP-13、US-CAP-14、US-CAP-21。

### D-97 选区菜单与区块胶囊之间的误点

背景：选区菜单与区块胶囊都是深色、只有图标的胶囊，前两个按钮都是剪藏与截图（[extension.md §2.1](extension.md)）。点偏了选区菜单、落在页面上时，菜单收起、选区塌缩，指针再停约 400ms 胶囊就在附近出现；胶囊与描边不标目标，候选是整篇文章时描边远超窗口，用户以为还在用选区菜单，存下的是整篇。这类保存在指标里是 `capture.saved` 的 `via` 为 `block`、`block_kind` 为 `article`（[metrics.md §9](metrics.md)）。
选项：A 不变；B 选区菜单因点击页面收起、或选区塌缩之后约 1 秒内不出胶囊，描边上沿标出目标的类型与范围（如“文章 · 整篇”“一节 · 4.1 面向超节点的并行策略”），位置同截图取景的标签，块比窗口高时与胶囊一样贴着窗口可见部分的上沿；C 只加目标标注，不加冷却。
默认：B。冷却只挡紧跟在选区之后的那一下，有意的悬停多停一会儿照样出现；标注让人在剪走整篇之前看得见。1 秒是方向性的值，误挡多就缩短。
影响的文档：[capture.md §6.2](capture.md) 的悬停入口与不出现的情形；[extension.md §2.1](extension.md)；[user-stories.md](user-stories.md) 的 US-CAP-14。

## 5. 模板

**决策**：`D-xx` · 背景（两三句）· 选项表 · 推荐与理由 · 无回复时的默认 · 影响的文档。

**新功能规格**（写进 PR 的规格自检）：

1. 要解决的问题、为哪类核心用户（[product.md §2](product.md)），来源（issue、反馈或使用观察）。
2. 触发时机、前置条件和主流程，各状态下用户看到什么（含空、错误、降级）。
3. 范围内与范围外，各一句话；越过 [product.md §2.3](product.md) 的不做清单时，写明改哪一行。
4. 涉及的契约变化（字段、消息、导出、权限）。
5. 验收标准：可观察、可测试，写明数字。
6. 要记录的事件与对应指标（[metrics.md §9](metrics.md)）。
7. 断网时的行为。
