## 1. 规则

1. 未确认的方案与阈值只在本文登记，不写进其他真源文件。其他文件需要引用时，只写条目 ID（如“见 Q-17”）。
2. 每个条目有稳定 ID：决策 `D-`、风险 `RK-`、开放问题 `Q-`。ID 不复用，不因排序变化。
3. 新功能不在这里排队：功能的契约、用户故事与验收和代码在同一个 PR 里修改，产品负责人在评审里确认（[AGENTS.md](AGENTS.md)）。实现中拿不准、又不必等回复的方案或阈值，登记为决策或开放问题，写明先按什么默认走。
4. 阈值是方向性判据，不是统计结论；报告比例时同时报告分母。
5. 外部事实类文档（[market.md](market.md)）每 90 天复核。

### D-32 截图线宽的档位

背景：#88 要求画笔与荧光笔至少有 2–3 档线宽，没有给出数值。矩形、椭圆、箭头与画笔的线都是 3 CSS 像素。荧光笔要盖住一行正文：网页正文多是 14–18 像素的字、20–28 像素的行高。

| 选项 | 内容                                                                                |
| ---- | ----------------------------------------------------------------------------------- |
| A    | 三档。画笔与直线 2、3、6，荧光笔 12、20、32（CSS 像素，随设备像素比放大）；默认中档 |
| B    | 三档。画笔与直线 2、4、8，荧光笔同 A；默认中档，画笔的默认线宽比现在粗              |
| C    | 两档。画笔与直线 3、6，荧光笔 16、28                                                |

推荐：A。中档和现有的线一样粗，用惯的画笔不变；粗档是中档的两倍，一眼分得出。荧光笔中档 20 像素盖住一行常见正文的字高而不压到上下行，细档给小字与界面文字，粗档给标题。
无回复时的默认：A。
影响的文档：[screenshot.md §1.1](screenshot.md)。

### D-33 线宽作用于哪些工具

背景：#88 只要求画笔与荧光笔有线宽。直线也是一条线；矩形、椭圆、箭头的线宽固定。线宽是整个编辑界面一个档位，还是每个工具各记一个，#88 也没有说。

| 选项 | 内容                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------- |
| A    | 画笔、直线、荧光笔有线宽，三者共用一个档位：换工具不变，和颜色一样每次截图从默认开始；矩形、椭圆、箭头固定 3 像素 |
| B    | 同 A，但每个工具各记自己的档位                                                                                    |
| C    | 矩形、椭圆、箭头也有线宽，与画笔、直线共用档位；箭头头部的大小随线宽变化                                          |

推荐：A。直线是拉直的画笔，粗细同样可选；共用档位与颜色的用法一致，“粗”在三种工具上都是粗。形状的线宽不在 #88 的范围内，要改就连箭头头部的大小一起定。
无回复时的默认：A。
影响的文档：[screenshot.md §1.1](screenshot.md)。

### D-34 荧光笔的透明度与混合方式

背景：荧光笔要半透明，不能把正文遮死。普通叠加按不透明度把颜色盖上去，对五种颜色一视同仁。正片叠底（multiply）像纸上的荧光笔，浅底上的黑字完全不受影响；但白色的荧光笔什么也画不出，黑色的会把正文涂黑，深色页面上任何颜色都几乎看不出来。

| 选项 | 内容                                                                                                                        |
| ---- | --------------------------------------------------------------------------------------------------------------------------- |
| A    | 普通叠加，不透明度 40%：盖住的文字与底色保留 60% 的反差，五种颜色、浅色与深色页面都适用；一笔之内交叉不加深，两笔重叠处加深 |
| B    | 正片叠底，不透明：浅底深字的页面上最像荧光笔；白色无效、黑色遮字，要去掉这两种颜色                                          |
| C    | 普通叠加，不透明度 30% 或 50%：更淡、正文更清楚（反差留七成），或更显眼（反差只留一半）                                     |

推荐：A。只有它对五种颜色、浅色与深色页面都成立，“正文仍读得清”可以落成一个数：反差保留六成。40% 的黄色在白纸上仍是一眼看得出的淡黄。和底色同色的一笔（白纸上的白色、黑底上的黑色）用哪种方式都看不出涂过。
无回复时的默认：A。
影响的文档：[screenshot.md §1.1](screenshot.md)。

### D-35 直线按住 Shift 时的吸附

背景：划线、分隔要画得水平或竖直，单靠手很难对齐。多数绘图工具按住 `Shift` 把直线的角度吸附到 45° 的倍数。编辑界面里的箭头不吸附，`Shift` 在编辑界面里也没有别的用处。

| 选项 | 内容                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------- |
| A    | 直线按住 `Shift` 落在经过起点的水平、竖直或 45° 斜线中最近的一条上，终点取指针在这条线上的位置；箭头与荧光笔不变 |
| B    | 同 A，箭头也吸附                                                                                                 |
| C    | 同 B，荧光笔按住 `Shift` 画成直的一笔                                                                            |
| D    | 不吸附                                                                                                           |

推荐：A。吸附是直线的常见用法；箭头与荧光笔的行为不在 #88 的范围内，要不要吸附看反馈再定。
无回复时的默认：A。
影响的文档：[screenshot.md §1.1](screenshot.md)。

### D-36 截图荧光笔的图标

背景：截图工具栏的按钮只有图标，名称在提示和读屏里。资料库里的高亮用 `highlighter` 图标（[visual.md §3](visual.md)），网页上的高亮标记是明确不做的事（[product.md §2.3](product.md)）。荧光笔只画在截图上，和高亮无关；用同一个图标最好认，但可能让人以为它在网页上做了高亮。

| 选项 | 内容                                                                  |
| ---- | --------------------------------------------------------------------- |
| A    | 用 `highlighter` 图标，和资料库里的高亮相同；提示与读屏名称是“荧光笔” |
| B    | 换一个图标（如 `brush`），`highlighter` 只留给资料库里的高亮          |

推荐：A。工具栏的九个工具只靠图标区分，荧光笔的样子最容易认出；它只出现在截图编辑界面里，画的是截图，不在网页上留下标记。
无回复时的默认：A。
影响的文档：[visual.md §3](visual.md)、[screenshot.md §1.1](screenshot.md)。

### D-37 新入口的快捷键

背景：页面批注和录屏都要有键盘入口；录屏的快捷键还是用户在浏览器界面上开始录制的两种方式之一。浏览器给每个扩展最多 4 个带默认绑定的快捷键（[market.md §4.7](market.md)），现在用了 2 个（截图、区块模式）；常用的组合键多已被浏览器或网站占用，选错了会盖掉用户熟悉的操作。

| 选项 | 内容                                                                                                 |
| ---- | ---------------------------------------------------------------------------------------------------- |
| A    | 页面批注、录屏各注册一个快捷键，都不设默认绑定，用户在浏览器的快捷键设置页自己绑；主入口是工具栏弹窗 |
| B    | 设默认绑定（例如 `Alt+Shift+D`、`Alt+Shift+R`），用掉剩下的两个默认名额                              |
| C    | 不注册快捷键，只有弹窗入口                                                                           |

推荐：A。键盘用户能用，不和浏览器或网站已有的组合键冲突，也不占默认名额；看使用情况再决定要不要给默认绑定。
无回复时的默认：A。
影响的文档：[annotate.md §1.1、§2.1](annotate.md)、[extension.md §7.1](extension.md)。

### D-38 截进编辑器的墨迹怎样撤销

背景：从页面批注进入截图时，页面上的墨迹成为编辑器里的标注。编辑器的撤销是逐个标注退回的（[screenshot.md §1.1](screenshot.md)）；墨迹可能有几十笔。

| 选项 | 内容                                                     |
| ---- | -------------------------------------------------------- |
| A    | 全部墨迹算一步：撤销一次拿掉全部，之后的标注照常逐步撤销 |
| B    | 每一笔算一步，和在编辑器里画的一样                       |

推荐：A。墨迹是带进来的一整组，想重来时一步清掉最直接；要改其中一笔，回到页面批注里改再截。
无回复时的默认：A。
影响的文档：[annotate.md §1.3](annotate.md)。

### D-39 自动擦除

背景：讲解时画一笔、讲完就该消失，每次手动清空会打断讲解。自动擦除只作用于页面上的墨迹，已经截下的图片不受影响；时长没有依据，先给两档。

| 选项 | 内容                                         |
| ---- | -------------------------------------------- |
| A    | 默认关；可选 3 秒或 8 秒，每一笔画完到时消失 |
| B    | 默认开，3 秒                                 |
| C    | 不做                                         |

推荐：A。批注多半是为了截图，默认留着；演示时再打开。两档覆盖“指一下”和“讲一段”。
无回复时的默认：A。
影响的文档：[annotate.md §1.2](annotate.md)。

### D-41 录屏进不进资料库

背景：条目只有剪藏与截图两种（[entry.md §2](entry.md)），图片单张不超过 10 MB（见 Q-03）。录屏是几十到上百 MB 的视频；放进库要新的条目类型、存储与导出契约，也要处理配额。issue 要的产物是一段可以发给别人的视频。

| 选项 | 内容                                                                        |
| ---- | --------------------------------------------------------------------------- |
| A    | 不进：只下载到本机，不是条目，不进导出                                      |
| B    | 进：新增 `recording` 条目类型，视频存进本地数据库，资料库里可以回放与加属性 |

推荐：A。讲解视频的去处是发给别人，不是之后在库里找回；B 要改条目契约、存储配额与导出，代价远大于收益。有用户要在库里管理录屏时再议。
无回复时的默认：A。
影响的文档：[annotate.md §2.3](annotate.md)、[product.md §2.3](product.md)。

### D-43 麦克风在哪里请求授权

背景：浏览器只在用户看得见的页面上弹出麦克风授权；工具栏弹窗一失去焦点就关闭，录制所在的后台文档弹不出授权。在询问里选了允许，之后对扩展一直有效；只允许这一次的，过后会失效，要再问一次（[market.md §4.7](market.md)）。

| 选项 | 内容                                                               |
| ---- | ------------------------------------------------------------------ |
| A    | 设置页的“录制”一节：勾选“带麦克风”而还没有授权时打开它，在那里授权 |
| B    | 一个专门的“录制”页面，从弹窗打开，在那里开始录制并授权             |

推荐：A。只在需要授权时打开，用现有的设置页，不多一个页面；授权之后在弹窗里勾选即可。
无回复时的默认：A。
影响的文档：[annotate.md §2.1](annotate.md)、[extension.md §2.5](extension.md)。

### D-45 录制中切到别的标签页

背景：录制绑定在开始时的那个标签页上。用户切到别的标签页时，可以继续录开始时的那个，也可以停止。

| 选项 | 内容                                     |
| ---- | ---------------------------------------- |
| A    | 继续录开始时的标签页；弹窗写明在录哪一个 |
| B    | 自动停止并下载                           |

推荐：A。讲解中途切出去查个东西很常见，自动停止会把一段视频切成几段；后台标签页画面变卡的问题在弹窗里说明。
无回复时的默认：A。
影响的文档：[annotate.md §2.2](annotate.md)。

### D-46 录制的上限

背景：录到的视频停止之前一直在内存里，录得越久，浏览器被关掉时丢得越多、占的内存也越大。讲解一段操作多在几分钟之内。

| 选项 | 内容                                             |
| ---- | ------------------------------------------------ |
| A    | 15 分钟或约 500 MB，先到为准；到了自动停止并下载 |
| B    | 30 分钟或约 1 GB                                 |
| C    | 不设上限                                         |

推荐：A。覆盖常见的讲解长度，内存占用可控；到了自动保存，不会白录。
无回复时的默认：A。
影响的文档：[annotate.md §2.1](annotate.md)。

### D-48 录制中的批注控件放在哪里

背景：录屏录的是标签页里的一切，页面上的批注工具栏也会被录进视频。扩展的工具栏弹窗在浏览器界面上，不会被录进去，但一点页面就会关闭。

| 选项 | 内容                                                           |
| ---- | -------------------------------------------------------------- |
| A    | 录制中页面上不显示工具栏，用单键切换工具与颜色；弹窗里列出按键 |
| B    | 照常显示工具栏，接受它出现在视频里                             |
| C    | 工具栏缩成页面边上的一个小圆点，点开再选                       |

推荐：A。视频里只有讲解的内容；单键比来回点工具栏更快，讲解时手不用离开页面。没有工具栏时不易发现按键，所以弹窗里列出来。
无回复时的默认：A。
影响的文档：[annotate.md §3.1](annotate.md)、[extension.md §2.6、§7.1](extension.md)。

### D-42 滚动长图的宽度

背景：滚动长图只拼纵向。页面常有左右边栏，用户可能只想要中间正文那一列；选列要在开拍前多一步框选，并且要处理边栏在滚动中变化。

| 选项 | 内容                                                       |
| ---- | ---------------------------------------------------------- |
| A    | 整个窗口的可见宽度，不能先选列；要裁可以拼完后再截一次区域 |
| B    | 先框一列，再只拼这一列的高度                               |

推荐：A。一步就能开始，拼接和吸顶元素的处理最简单；选列等用户反馈再加。
无回复时的默认：A。
影响的文档：[screenshot.md §1.5](screenshot.md)。

### D-49 滚动长图的像素面积上限

背景：长图在编辑器里整张放在内存里，预览、入库与复制下载各要一份。Retina 屏上一屏约 460 万像素，拼满 30 屏约 1.4 亿像素，每一份都要五百多 MB，标签页可能因内存不足崩溃；画标注、打马赛克时整张重画，也会变得不跟手。浏览器的画布本身也有上限：单边 65535 像素，面积约 2.68 亿像素（[market.md §4.7](market.md)）。

| 选项 | 内容                                                    |
| ---- | ------------------------------------------------------- |
| A    | 约 4000 万像素：普通屏上 30 屏先到，Retina 屏上约九屏   |
| B    | 约 8000 万像素：Retina 屏上约十八屏，编辑更慢、更占内存 |
| C    | 只按屏数（30 屏）限制                                   |

推荐：A。常见的 8 GB 内存电脑上编辑仍然跟手；Retina 屏上九屏覆盖多数文章的主体，更长的可以分两次拼。真机上量过编辑的流畅度再调。
无回复时的默认：A。
影响的文档：[screenshot.md §1.5](screenshot.md)。

### D-52 录制中弹窗里被录标签页标题的摆法

背景：弹窗底部只有约 276px 宽。状态、时长与标题挤在一行时，标题只剩约 80px，读不出是哪个标签页；评审量到录制中的状态文字与单键提示叠印。

| 选项 | 内容                                                    |
| ---- | ------------------------------------------------------- |
| A    | 状态、标题与时长同一行（`● 正在录制：<标题> · <时长>`） |
| B    | 状态与时长一行，标题独占下一行（单行省略号）            |

推荐：B。标题一行约有 250px，多数标签页标题读得出来；状态行保持简短。
无回复时的默认：B。
影响的文档：[extension.md §2.6](extension.md)。

### D-53 受限页弹窗里原因的呈现

背景：受限页（`chrome://` 等）上批注与录制入口灰显，原因只写在按钮的 `title` 里，键盘和触屏用户看不到；页脚仍写“选中网页文字即可保存”，在此页做不到。

| 选项 | 内容                                                               |
| ---- | ------------------------------------------------------------------ |
| A    | 原因只留在按钮 `title` 与读屏名称里                                |
| B    | 按钮上方常驻一行原因，页脚换成此页做得到的事（去资料库读已存内容） |
| C    | 只加原因行，页脚不动                                               |

推荐：B。规格写的是“写明原因”，常驻一行对键盘和触屏同样可见；页脚不再承诺此页做不到的事。
无回复时的默认：B。
影响的文档：[extension.md §2.6](extension.md)。

### D-65 页内浮层面板的外观

背景：截图选区阶段的提示条与尺寸标签、批注的提示条、美化面板写死深色（`#252b31`、`#1b1f2a`），同一条流程里的比例条、确认条、工具条却是浮层令牌（亮色白）。亮色用户看到深色提示压在白色工具条旁；[visual.md §2](visual.md) 写的是两套令牌成对、跟随系统。

| 选项 | 内容                                               |
| ---- | -------------------------------------------------- |
| A    | 提示条、尺寸标签、美化面板都改用浮层令牌，亮浅暗深 |
| B    | 提示条、尺寸标签用令牌，美化面板保持设计稿的恒深色 |
| C    | 全保持写死的深色                                   |

## 5. 模板

**决策**：`D-xx` · 背景（两三句）· 选项表 · 推荐与理由 · 无回复时的默认 · 影响的文档。

**新功能规格**（写进 PR 的规格自检）：

1. 要解决的问题、为哪类核心用户（[product.md §2](product.md)），来源（issue、反馈或使用观察）。
2. 触发时机、前置条件和主流程，各状态下用户看到什么（含空、错误、降级）。
3. 范围内与范围外，各一句话；越过 [product.md §2.3](product.md) 的不做清单时，写明改哪一行。
4. 涉及的契约变化（字段、消息、导出、权限）。
5. 验收标准：可观察、可测试，写明数字。
6. 要记录的事件与对应指标（[metrics.md §9](metrics.md)）。
7. 断网时的行为。
