# 产品定位

> 层级：vision
> 状态：产品定位真源
> 更新：2026-10-08

本文定义 AnnHub 为谁服务、解决什么问题、为什么不是另一个笔记软件，以及从现有产品中借鉴和拒绝什么。

## 1. 一句话定位

**AnnHub 是一个本地优先的浏览器扩展：把网页中值得留下的内容，用剪藏（选区或整块）和截图连同来源存进同一个本地库；再在库里阅读、划出高亮、加上可扩展的属性，把它们变成自己的；需要时检索、回到来源，或导出为 Markdown。**

对外短句：

> 保存很容易。难的是之后找得回、分得清。

## 2. 目标用户

### 2.1 核心用户

首版只为以下三类重度知识工作者优化。下表是待校正的假设画像，不是调研结论；招募条件与校正方式见 [validation.md §2](validation.md)。

| 用户                | 高频材料                           | 日常产出                                  | 现有替代                       | 失败的代价                                         |
| ------------------- | ---------------------------------- | ----------------------------------------- | ------------------------------ | -------------------------------------------------- |
| 软件工程师 / 架构师 | 技术文档、源码说明、RFC、事故复盘  | 设计文档、技术方案、Code Review、故障分析 | 书签加笔记工具，截图散在文件夹 | 写方案时重新搜索同一批资料；记不清某张图出自哪一页 |
| 产品经理 / 设计师   | 行业文章、竞品、研究报告、设计案例 | PRD、决策记录、方案比较、设计说明         | 截图加文档链接                 | 方案缺证据；截图找不到出处                         |
| 研究者 / 分析师     | 论文、报告、新闻、数据解释         | 分析文章、研究笔记、观点论证、结论汇报    | 文献管理器加笔记               | 引用时丢失来源页面与位置                           |

共同特征：每周阅读大量网页材料；已经用过笔记、书签、高亮或稍后读工具；真正的问题不是无法保存，而是保存后散落各处、脱离来源，之后找不回、分不清；主要工作设备是桌面浏览器。研究者的主要来源可能是 PDF，网页是否足够见 [H-15](validation.md)。

### 2.2 暂不优化的人群

- 需要团队 Wiki、实时协作和权限管理的组织。
- 以手机为主要采集设备的用户。
- 需要完整学术引用格式和文献管理的人。
- 以做图为主的内容创作者：截图提供复制、下载格式、署名水印、比例预设和极简美化（背景、留白、圆角、阴影），不做封面模板、文案卡和平台发布。

### 2.3 明确不做的事

| 不做                          | 原因                                                                                   | 详见                                |
| ----------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------- |
| 团队 Wiki、实时协作、权限管理 | 单人本地优先是核心验证；协作引入账号、权限与冲突                                       | —                                   |
| 手机端与独立的桌面应用        | 先把桌面浏览器里的采集与找回闭环验证清楚                                               | —                                   |
| AI 摘要、问答与模型接入       | 与“内容不离开本机”的承诺冲突；核心价值在采集、阅读与找回，不预留入口                   | [permissions.md §1](permissions.md) |
| 通用笔记与自由白板            | 避免成为另一个笔记软件                                                                 | §4                                  |
| 稍后读收件箱与整页阅读器      | 阅读视图只显示用户自己剪藏的内容（选区或一个区块）；不抓取整页，不做待读队列和阅读进度 | —                                   |
| 网页上的高亮标记              | 高亮在资料库里读剪藏时完成，不改动网页                                                 | [entry.md §4](entry.md)             |
| 整页剪藏与模板系统            | 当前保存选区或一个区块，不保存整页；是否需要见 Q-10、Q-11                              | [validation.md §7](validation.md)   |
| 平台发布与账号授权            | 真实发布动作不进入扩展域                                                               | [screenshot.md §1.1](screenshot.md) |
| 封面、文案卡与设备外框模板    | 截图首先是资料，不是设计稿；美化只做背景、留白、圆角与阴影                             | [screenshot.md §4.4](screenshot.md) |

## 3. 核心 Jobs-to-be-Done

- **Job A：浏览时留下来，不被打断。** 当我在网页里看到值得留下的文字或画面时，我希望一步保存，连同来源，不打断阅读；遇到一条推文、一篇文章这样的整体，指一下就能留下。
- **Job B：留下之后读懂它。** 当我回到一条剪藏，我希望在原文里划出重点、写下自己的想法，把它变成自己的，而不是又一条躺着的链接。
- **Job C：之后找得回、分得清。** 当我准备写方案、做比较或解释问题时，我希望在一个库里按来源、标签和自己的属性找到它们，一步回到原页面。

| Job                  | 现有替代                     | 失败的代价                                       | 成功信号                              | 指标       |
| -------------------- | ---------------------------- | ------------------------------------------------ | ------------------------------------- | ---------- |
| A 浏览时留下来       | 书签、复制进笔记、截图       | 内容留下了，来源丢了；或被表单打断而放弃         | 一次点击保存；之后仍知道它出自哪      | M-03       |
| B 留下之后读懂它     | 回到原网页重读、在网页上划线 | 保存了却不再读，内容躺在库里；划线绑在某个网页上 | 在库里读并高亮；阶段 V 访谈           | M-21       |
| C 之后找得回、分得清 | 重新搜索、翻笔记和文件夹     | 重复检索同一批资料；记不清出处                   | 搜索加筛选后一步回到来源；阶段 V 访谈 | M-19、M-20 |

## 5. 核心差异化

- **一个库，三种动作，两种条目**：剪藏、截图在页面里留下内容，高亮在库里读剪藏时划出；它们不是三个互不相通的工具，而是同一个库：条目用同一套属性，一起检索和导出（[entry.md](entry.md)）。
- **指一下就能留下整块**：除了选中文字，指在一条推文、一篇文章上就能一次保存整块，存成保留链接与标题层级的 Markdown。
- **来源永远可追溯**：每条条目都带来源 URL，随时回到原页面；不在网页上留任何标记。
- **属性可扩展，且开放**：属性是带类型的短小键值，名称与类型全局绑定；导出的 Markdown 把属性写成 frontmatter，放进 Obsidian 就能用。
- **本地优先但不封闭**：断网时仍可采集、查询和编辑；内容和图片可导出为 Markdown ZIP，供其他工具阅读，不作为 AnnHub 数据库的恢复格式。

### 核心赌注与证伪信号

AnnHub 押注下面三件事。每一件都写明“如果错了会看到什么”，验证方式见 [validation.md](validation.md)。

| 赌注                  | 具体表述                                                                                                        | 支持证据                                                              | 证伪信号                                                                  | 退路                             |
| --------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------- |
| B1 一个库胜过三个工具 | 把剪藏、高亮、截图放进同一个带来源的库，找回比分散保存更快；剪藏之后会在库里读并划重点（[H-19](validation.md)） | 同类产品把剪藏、高亮与属性做成一条链路（[market.md §4.2](market.md)） | 伙伴采集之后很少回来找（[H-16](validation.md)），或从不在库里高亮（H-19） | 评估价值是否其实在导出到笔记工具 |
| B2 属性值得花那几秒   | 用户愿意给少数重要条目加标签与属性，并靠它们找回                                                                | Obsidian 把属性做成库的核心结构（[market.md §4.2](market.md)）        | 属性几乎没人用（[H-17](validation.md)）                                   | 收窄为标签与备注                 |
| B3 本地优先建立信任   | 数据留在本地并可开放导出，降低迁入顾虑                                                                          | Omnivore、Pocket 的关停（[market.md §4.1](market.md)）                | 用户更在意手机与云同步，压过本地信任（阶段 V 访谈）                       | 评估同步与移动端                 |

## 6. 产品原则

1. **保存先于整理**：采集一步完成，不被表单打断；阅读、高亮、标签和属性都放到保存之后。
2. **原文永远可追溯**：来源与语境随条目保存，找得到出处；网页保持原样。
3. **失败不丢输入**：网络、写入和配额失败都保留用户已输入的内容。
4. **属性小而原子**：短值、有类型、同名同类型；长文字放备注。
5. **默认界面克制**：所有页面左导航右内容，主流程不要求用户理解数据库或存储细节。

## 7. 主要风险与应对

完整风险登记（可能性、影响、预警信号）见 [validation.md §6](validation.md)；下表只保留产品层面的应对。

| 风险               | 表现                                                                       | 产品应对                                                                                         |
| ------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 采集摩擦过高       | 用户因为多一步操作而放弃保存                                               | 剪藏（选区或区块）一次点击保存，不开窗口；阅读、高亮与整理放到保存之后                           |
| 与现成剪藏工具同质 | 用户认为 Obsidian Web Clipper 等免费工具已经够用（[RK-11](validation.md)） | 把截图、剪藏和库内高亮放进同一个本地库；不依赖笔记软件也能阅读、检索与整理；导出对 Obsidian 友好 |
| 结构化数据不透明   | 用户担心被产品锁定                                                         | Markdown + 原图 ZIP，属性即 frontmatter，清楚说明的导出范围和缺失项                              |

## 8. 成功定义

AnnHub 成功不是用户存了很多内容，而是形成以下重复行为：

```text
工作中顺手采集少量内容
  -> 在库里读一遍、划出重点
  -> 写方案或做决策时搜到并用上
  -> 回到来源核对
```

对应用户故事见 [用户故事与验收](user-stories.md)，指标定义见 [体验与指标](metrics.md)。这些行为是否真的出现，由 [validation.md](validation.md) 的阶段 V 回答。
