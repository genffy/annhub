# 验证计划与决策登记

> 层级：product
> 状态：持续维护；本目录中唯一存放**未确认内容**的文件
> 更新：2026-10-07

本文回答三个问题：**哪些判断还没有证据**（假设）、**打算怎样验证**（实验）、**哪些决定在等待产品负责人确认**（决策）。已确认的结论只写在各自的真源文件里；本文的条目被采纳后迁入真源，并在此标注结果。

## 1. 规则

1. 未确认的想法、阈值和方案只在本文登记，不写进其他真源文件。其他文件需要引用时，只写条目 ID（如“见 D-05”）。
2. 每个条目有稳定 ID：假设 `H-`、实验 `E-`、决策 `D-`、风险 `RK-`、开放问题 `Q-`。ID 不复用，不因排序变化；条目被移除后，缺号保留。
3. 状态词：假设为 `待验证` → `验证中` → `通过` / `未通过`；决策在“待确认”中登记，确认后移入第 5 节的“已决”表（采纳或拒绝，保留一两句原因，不另建变更记录）。
4. **阈值是方向性判据，不是统计结论**。内测人数在个位数到几十人之间，结论用来决定“继续、修订还是停止”，不用来宣称显著性。所有比例必须同时报告分母。
5. 晋升流程：假设 → 实验 → 证据 → 决策 → 产品负责人确认 → 迁入归属文件 → 记入“已决”表。证据不足时不得跳步。
6. 评审节奏：内测期间每周一次指标回顾（30 分钟），每两周一次决策评审；外部事实类文档（[market.md](market.md)）每 90 天复核。

## 8. 模板

**假设**：`H-xx` · 优先级 · 一句话假设 · 通过判据（含分母和阈值）· 验证方式 · 不通过时的动作 · 关联文档。

**决策**：`D-xx` · 背景（两三句）· 选项表 · 推荐与理由 · 无回复时的默认 · 影响的文档。

**新功能规格**（进入真源文件前自检）：

1. 要解决的问题与证据来源（假设 ID 或访谈）。
2. 触发时机、前置条件和主流程，各状态下用户看到什么（含空、错误、降级）。
3. 范围内与范围外，各一句话。
4. 涉及的契约变化（字段、消息、导出）。
5. 验收标准：可观察、可测试，写明数字。
6. 要记录的事件与对应指标（[metrics.md §9](metrics.md)）。
7. 断网时的行为。
