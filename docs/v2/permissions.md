# 权限与数据边界

> 层级：core
> 状态：权限与数据出站的唯一真源；商店的权限说明和隐私政策从这里取材
> 更新：2026-10-11

本文回答两个问题：**扩展申请了哪些权限、为什么**，以及**用户的数据会不会离开浏览器**。这是产品对用户的承诺，所以放在产品文档里；清单里的具体写法以源码为准。页面里的交互见 [扩展](extension.md)，存储见 [存储](storage.md)。官网自己的访问数据见第 8 节。

## 1. 数据边界

1. 采集只在用户主动选中、指一下或框选截图时读取页面内容，不读取用户没有指认的内容。
2. 条目、图片、设置和本地指标只保存在浏览器本地（[storage.md §1](storage.md)）。不把页面内容、URL、标题或用户整理的内容发往 AnnHub 或任何第三方服务；没有账号、云端和 AI 服务。
3. 采集唯一会产生的出站请求，是截图时由扩展后台代取页面里的跨域图片：目标就是页面自己引用的那张图，不带凭据，只接受公网地址（[screenshot.md §2](screenshot.md)）。剪藏里的图片只保留原地址，阅读视图不联网加载（[capture.md §3.1](capture.md)）。
4. 扩展页面只执行扩展自带的脚本，不加载远程代码。
5. 阶段 V 的本地指标只在本机计算，以聚合数字展示、不展示正文，也不新增导出或上传入口（[metrics.md §10](metrics.md)）；实验同样不上传正文、URL 或标题（[validation.md §4](validation.md)）。

## 2. 权限

| 权限        | 用途                                                                                                                                                             | 去掉的后果                   |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `storage`   | 偏好（默认高亮颜色、区块入口开关与已停用的网站、截图的匿名、下载格式、水印、比例预设与美化默认样式等）和本地指标。条目与图片放在浏览器自己的数据库里，不需要权限 | 设置与指标无法保存           |
| `commands`  | 键盘快捷键：区域截图、区块模式                                                                                                                                   | 快捷键失效，鼠标入口不受影响 |
| `downloads` | 把截图和“导出内容”的 ZIP 保存为本地文件                                                                                                                          | 无法下载截图与导出           |

## 3. 主机权限

| 范围         | 用途                                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<all_urls>` | 扩展的页面脚本在用户读的任意网页上工作（选区菜单、区块入口、截图遮罩）；截取发起截图的那个标签页的可见区域；后台代取跨域图片的字节，绕开页面的 CORS 才能保存原图 |

## 4. 刻意没有申请

- `tabs`、`activeTab`：`<all_urls>` 已经包含它们能给的一切（读取标签的 URL 与标题、截取可见标签），重复申请只会增加安装时的警告。
- `scripting`：不申请。它此前的用途是快捷键的兜底触发，但页面脚本由扩展清单静态注册、覆盖所有页面，兜底没有实际接收者；内容脚本尚未就绪的页面上刷新一次即可，`chrome://` 等受限页面由工具栏弹窗兜底（[extension.md §2.6](extension.md)）。
- `history`、`bookmarks`、`cookies`、`webRequest`、`nativeMessaging`、`clipboardRead`：用不到。
- `clipboardWrite`：不申请。截图的“复制”发生在用户在页面里点击或按键之后，由页面里的脚本直接写入剪贴板，不需要这项权限，安装时也就没有它带来的权限警告（依据与验证见 [market.md §4.4](market.md)）。代价是 `http:` 页面上浏览器不开放剪贴板接口，复制改为提示下载（[screenshot.md §4.2](screenshot.md)）。
- `unlimitedStorage`：截图入库前先检查配额，不足时提示导出，而不是静默申请更大的空间（[storage.md §3](storage.md)）。

## 5. 最低浏览器版本

最低支持 Chrome 114，高于所用接口的要求、留有余量；更低的版本不测试，也不承诺。

## 6. 商店与对外页面

- 商店的权限说明取自第 2 至 4 节，隐私披露取自第 1 节。
- 隐私政策与服务条款是两个对外页面（中英双语，商店填写它们的公开地址，见 [website.md §17](website.md)）。政策里的权限表必须与扩展清单一致（有自动检查），数据流的描述必须与第 1 节和第 8 节一致；任何一边变化，同步另一边并更新页面日期。
- 商店的名称与描述有长度上限（有自动检查）；截图与宣传图从真实扩展截取，中英文各一套，英文商店页配英文截图。
- 分发范围：阶段 V 先用商店的私有可见性（[roadmap.md V 节](roadmap.md)）。

## 7. 改动清单

新增、删除或扩大任何权限，都要同时更新：本文、商店的权限说明、隐私政策页里的权限表，以及 [roadmap.md](roadmap.md) 里“商店要求的隐私披露与权限说明”一项。开启、改变或停用官网的统计，同时更新第 8 节与隐私政策。

## 8. 官网的访问数据

官网是公开的产品介绍页，与扩展不共享任何数据。隐私政策第 9 节向访客说明本节内容。

1. 访问统计用 Cloudflare Web Analytics，只得到聚合数字：访问与页面浏览数，可按页面路径（不含查询参数）、来源网站、国家或地区、浏览器、操作系统与设备类型分列，以及页面性能（[market.md §4.6](market.md)）。不用 Cookie 或本地存储识别访客，不做指纹识别。统计脚本由页面按访客的选择加载，不由 Cloudflare 代理注入：代理注入的脚本无法按访客的选择开关。
2. 统计全部访客，欧洲访客先征得同意。欧盟把在访客浏览器里运行、回传数据的统计脚本视为读取访客设备，不用 Cookie 也需要事先同意（[market.md §4.6](market.md)）：
   - Cloudflare 按 IP 地址判断访客在欧盟、欧洲经济区、英国或瑞士（含欧盟在其他大洲、有自己国家代码的地区），或者判断不出国家（没有经过代理、没有数据、Tor）时，访客先看到同意卡片（[website.md §19](website.md)），选“允许”才加载统计脚本；不作选择就不统计。页面是静态的，由官网的服务端读 Cloudflare 给出的国家（[market.md §4.6](market.md)），只用于这一判断，不保存。
   - 不在上述国家的访客，服务端写一个会话 Cookie 告诉页面可以不问直接统计。它只有这一个标记，不含国家；先问的访客不会收到它，访客到了要先问的国家时服务端把它删掉。
   - 其他访客默认统计；浏览器发出 Global Privacy Control（GPC）信号的，默认不统计。
   - 访客自己的选择优先于默认，任何访客都能从页脚的“统计设置”改变选择。
   - “允许”从当前页面开始统计，12 个月后重新询问。“不允许”从下一个页面起生效（已运行的脚本无法撤回），直到访客改变选择。
   - 选择连同日期存在浏览器的本地存储里，不含识别访客的信息。
   - 没有统计令牌的构建（本地构建与预览）不加载统计脚本，不写上面的 Cookie，也不显示同意卡片和“统计设置”。
3. 不接入广告、跨站追踪或营销脚本，不统计站内的点击与操作。除统计脚本外，页面的字体、图片和脚本都从官网自己的域名加载。
4. 没有统计或广告 Cookie。官网只有两个会话 Cookie：第 2 项里“不必先问”的标记；记住语言的那个，访客打开的语言版本与浏览器语言不一致时才写入。
5. 改变统计的范围、规则或服务之前，先改隐私政策第 9 节并更新页面日期；政策中“不使用分析、追踪或遥测”的说法限定为扩展。
