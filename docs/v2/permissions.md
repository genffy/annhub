# 权限与数据边界

> 层级：core
> 状态：权限与数据出站的唯一真源；商店的权限说明和隐私政策从这里取材
> 更新：2026-10-08

本文回答两个问题：**扩展申请了哪些权限、为什么**，以及**用户的数据会不会离开浏览器**。这是产品对用户的承诺，所以放在产品文档里；清单里的具体写法以源码为准。页面里的交互见 [扩展](extension.md)，存储见 [存储](storage.md)。

## 1. 数据边界

1. 采集只在用户主动选中、指一下或框选截图时读取页面内容，不读取用户没有指认的内容。
2. 条目、图片、设置和本地指标只保存在浏览器本地（[storage.md §1](storage.md)）。不把页面内容、URL、标题或用户整理的内容发往 AnnHub 或任何第三方服务；没有账号、云端和 AI 服务。
3. 采集唯一会产生的出站请求，是截图时由扩展后台代取页面里的跨域图片：目标就是页面自己引用的那张图，不带凭据，只接受公网地址（[screenshot.md §2](screenshot.md)）。剪藏里的图片只保留原地址，阅读视图不联网加载（[capture.md §3.1](capture.md)）。
4. 扩展页面只执行扩展自带的脚本，不加载远程代码。
5. 阶段 V 的本地指标只在本机计算，以聚合数字展示、不展示正文，也不新增导出或上传入口（[metrics.md §10](metrics.md)）；实验同样不上传正文、URL 或标题（[validation.md §4](validation.md)）。

## 2. 权限

| 权限        | 用途                                                                                                                             | 去掉的后果                   |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `storage`   | 偏好（默认高亮颜色、区块入口开关与已停用的网站、截图的匿名、下载格式、水印、比例预设与美化默认样式等）和本地指标。条目与图片放在浏览器自己的数据库里，不需要权限 | 设置与指标无法保存           |
| `commands`  | 键盘快捷键：区域截图、区块模式                                                                                                   | 快捷键失效，鼠标入口不受影响 |
| `downloads` | 把截图和“导出内容”的 ZIP 保存为本地文件                                                                                          | 无法下载截图与导出           |

## 3. 主机权限

| 范围         | 用途                                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<all_urls>` | 扩展的页面脚本在用户读的任意网页上工作（选区菜单、区块入口、截图遮罩）；截取发起截图的那个标签页的可见区域；后台代取跨域图片的字节，绕开页面的 CORS 才能保存原图 |

## 4. 刻意没有申请

- `tabs`、`activeTab`：`<all_urls>` 已经包含它们能给的一切（读取标签的 URL 与标题、截取可见标签），重复申请只会增加安装时的警告。
- `scripting`：不申请。它此前的用途是快捷键的兜底触发，但页面脚本由扩展清单静态注册、覆盖所有页面，兜底没有实际接收者；内容脚本尚未就绪的页面上刷新一次即可，`chrome://` 等受限页面由工具栏弹窗兜底（[extension.md §2.6](extension.md)）。
- `history`、`bookmarks`、`cookies`、`webRequest`、`nativeMessaging`、`clipboardRead`：用不到。
- `clipboardWrite`：不申请。截图的“复制”发生在用户在页面里点击或按键之后，由页面里的脚本直接写入剪贴板，不需要这项权限，安装时也就没有它带来的权限警告（依据与验证见 [market.md §4.4](market.md)）。代价是 `http:` 页面上浏览器不开放剪贴板接口，复制改为提示下载（[screenshot.md §4.2](screenshot.md)）。
- `unlimitedStorage`：截图入库前先检查配额，不足时提示导出，而不是静默申请更大的空间（[storage.md §3](storage.md)）。

## 5. 最低浏览器版本

最低支持 Chrome 114，高于所用接口的要求、留有余量；更低的版本不测试，也不承诺。

## 6. 商店与对外页面

- 商店的权限说明取自第 2 至 4 节，隐私披露取自第 1 节。
- 隐私政策与服务条款是两个对外页面（中英双语，商店填写它们的公开地址，见 [website.md §17](website.md)）。政策里的权限表必须与扩展清单一致（有自动检查），数据流的描述必须与第 1 节一致；任何一边变化，同步另一边并更新页面日期。
- 商店的名称与描述有长度上限（有自动检查）；截图与宣传图从真实扩展截取，中英文各一套，英文商店页配英文截图。
- 分发范围：阶段 V 先用商店的私有可见性（[roadmap.md V 节](roadmap.md)）。

## 7. 改动清单

新增、删除或扩大任何权限，都要同时更新：本文、商店的权限说明、隐私政策页里的权限表，以及 [roadmap.md](roadmap.md) 里“商店要求的隐私披露与权限说明”一项。
