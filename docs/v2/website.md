# 网站内容蓝图

> 层级：website
> 状态：产品方向展示，可持续调整
> 更新：2026-10-07

本文把产品定位和用户故事转换为产品展示页的信息架构与内容来源。它不是当前网站实现说明：实现位于 `website/`（中文路由 `/zh-CN`，英文路由 `/en`），仍必须以本文和上游真源为准。

## 1. 页面目标

当前主操作是查看项目进展与公开路线图；页面展示真实产品工作流与当前实现状态，不把尚未交付的能力写成已完成，也不展示定价、会员、购买或付费申请。阶段 V 的内测构建仅限受邀分发（[D-08](validation.md) 已采纳），在公开分发被决定之前，页面不出现下载入口；有可公开下载的构建后再增加指向它的入口。

## 2. 核心受众

首版页面只对高级工程师、架构师和技术负责人说话。访客应在首屏内确认：这是一个浏览器扩展；它把剪藏、高亮、截图放进同一个本地库，不是另一个收藏夹；保存的内容带着来源，能按标签和属性找回；数据默认在本地，可导出为 Obsidian 读得懂的 Markdown。产品经理、设计师和研究者出现在后续用例区，不占据首屏。

## 4. Hero

H1 是品牌名 `AnnHub`；支持文案紧随其后，不把两句话都标成 H1：

```text
把网页里值得留下的内容，存进同一个本地库。
剪藏、高亮、截图，带着来源和属性，
需要时再找回，也能带去 Obsidian。
本地优先。
```

主 CTA 是“查看项目进展”，辅助 CTA 是“查看 90 秒工作流”。

## 5. Hero 视觉

使用真实产品场景，不使用抽象渐变或装饰性插画；采用“产品画板 / 作品集画廊”，而不是常见的深色 SaaS 左文右图模板。

- 浅灰紫画布和白色产品窗口为主，紫色只作操作与品牌强调；悬浮白色导航；一张大型选中场景加两张不等高辅助场景，非对称层叠。
- 背景是一张清晰的技术文档页面，选区上出现选区菜单（剪藏、高亮、截图），后景自然露出资料库里同一条条目的详情与属性面板，展示同一条条目从网页进入资料库。
- 不使用渐变球、发光背景、玻璃拟态大卡和每屏重复的“眉题 + 巨型标题 + 四张卡”；工具窗口圆角不超过 8px；首屏底部露出下一节。

## 6. 问题区

标题：**保存很容易。难的是之后找得回、分得清。**

1. **散落各处**：书签、高亮、截图分在不同的工具和文件夹里。
2. **脱离来源**：只剩一段文字或一张图，不知道出自哪一页、在页面的哪里。
3. **难以归类**：没有统一的标签和属性，找回只能靠记忆。

不使用“信息过载”“第二大脑”等泛化措辞作为主要问题。

## 7. 三种采集与统一的库

标题：**三种方式留下内容，一个库找回它们**。三块各一句：

- **剪藏**：一次点击，连同来源与语境存下来。
- **高亮**：在页面上留痕，回访时恢复。
- **截图**：框选或点选，原位标注，遮住身份信息。

收束：它们是同一种条目，用同一套属性分类，在同一个资料库里检索，导出为带 frontmatter 的 Markdown。本节对应[产品定位 §5](product.md) 与[条目契约](entry.md)，文案变化不能修改类型与属性的语义。

## 8. 主用例：从一篇技术文章到一份带属性的 Markdown

```text
读一篇关于失败重试的技术文章
  -> 剪藏一段、高亮三步做法、截取一张延迟曲线图
  -> 给它们加上标签和 project 属性
  -> 写方案时搜索并按属性筛选，回到来源核对
  -> 导出 Markdown，属性就是 frontmatter，放进 Obsidian 即可使用
```

需要的截图：选区与选区菜单；“已剪藏 · 撤销 · 编辑”提示；资料库的筛选结果；条目详情与属性面板；导出的 Markdown 在 Obsidian 里的属性视图。

## 9. 差异化区

- **不是又一个收藏夹**：三种采集是同一种条目，都带来源和定位，按类型与属性整理。
- **不依赖笔记软件**：不装 Obsidian 也有完整的库；装了，导出的 Markdown 直接可用。
- **属性小而明确**：有类型、同名同类型，长文字写在备注里。
- **本地优先且可阅读**：核心链路离线可用；内容和已保存图片可导出为 Markdown ZIP。

禁止使用无法证明的绝对化文案，例如“唯一”“最先进”“永不丢失”“完全准确”。

## 10. 产品界面区

展示：选区菜单的三项动作与悬停提示；剪藏的撤销与编辑、高亮的页面标记、截图的原位编辑；资料库（左导航 + 右内容）里的筛选与搜索、条目详情与属性面板、“回到来源”和 ZIP 导出。界面截图必须来自真实构建，不使用无法实现的概念稿冒充现有功能；目标态功能标记“开发中”。

## 11. 信任区

标题：**你的材料，不应该成为使用工具的代价**。要点：浏览器本地存储（IndexedDB 与 `chrome.storage`）；核心链路断网可用；不默认上传正文、URL 和用户整理的内容；Markdown + 原图 ZIP 导出（目标态，按实现进度标注）；ZIP 供其他工具阅读，不宣称可还原 AnnHub 数据库。只有代码已经实现并验证的能力才能使用完成时态。

## 12. 使用证据

没有真实用户证据前，不展示评价和用户数量。可使用的真实证明：设计伙伴的具名案例（经授权）；“从一篇 RFC 到一组可检索的条目”的案例；本地指标的匿名聚合结果（用户明确同意后）；开放导出、离线和隐私的技术说明。

## 13. FAQ

- **它和 Obsidian Web Clipper 有什么区别？** Obsidian Web Clipper 把网页存成 Obsidian 库里的笔记，用模板和属性整理，免费且开源。AnnHub 把剪藏、高亮、截图放进浏览器里一个独立的本地库，不需要 Obsidian 也能检索和整理，也能把带属性的 Markdown 导出给它。对外的对比表述必须出自 [market.md](market.md) 的已核对事实并带核对日期。
- **它和 Readwise 有什么区别？** Readwise 是云端的阅读与高亮服务；AnnHub 的数据留在浏览器本地，覆盖剪藏、高亮与截图，按类型与属性检索。
- **必须使用 Obsidian 吗？** 不需要。库在浏览器里就能用；导出的 Markdown 只是让你需要时能带走。
- **数据保存在哪里？** 浏览器的本地存储里，不会上传到任何 AnnHub 服务器。
- **为什么没有手机端？** 当前产品集中在桌面浏览器里的采集，避免在核心体验验证前分散到更多客户端。
- **能导出吗？** 目标是在扩展中一键下载 Markdown 与已保存图片组成的 ZIP，属性写成 frontmatter。它适合其他工具阅读，不是可恢复的 AnnHub 数据库备份；页面上线时按实际实现状态表述。
