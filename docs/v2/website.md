# 网站内容蓝图

> 层级：website
> 状态：产品方向展示，可持续调整
> 更新：2026-10-04

本文把产品定位和用户故事转换为产品展示页的信息架构与内容来源。它不是当前网站实现说明。

当前实现位于 `website/`，默认中文路由 `/zh-CN`，英文路由 `/en`。实现仍必须以本文和上游真源为准。

## 1. 页面目标

当前主操作是查看项目进展与公开路线图；页面展示真实产品工作流与当前实现状态。已有可公开下载的构建时可增加下载入口，但不能把尚未交付的能力写成已完成。页面不展示定价、会员、购买或付费申请。阶段 V 的内测构建仅限受邀分发（[D-08](validation.md) 已采纳），在公开分发被决定之前，页面不出现下载入口。

## 2. 核心受众

首版页面只对高级工程师、架构师和技术负责人说话。

访客应在首屏内确认：

- 这是浏览器扩展 + macOS Desktop。
- 它不是另一个网页收藏夹。
- 它帮助把技术资料用于设计和决策。
- 数据默认保存在本地。

产品经理、设计师和研究者可以出现在后续用例区，不占据首屏。

## 5. Hero 视觉

Hero 使用真实产品场景，不使用抽象渐变或装饰性插画。首版视觉方向采用“产品画板 / 作品集画廊”，而不是常见的深色 SaaS 左文右图模板。

视觉语言：

- 浅灰紫画布和白色产品窗口为主，紫色只作为操作与品牌强调色。
- 悬浮白色导航，避免整条深色导航压住页面。
- 一张大型选中场景 + 两张不等高辅助场景，形成非对称层叠。
- 产品截图承担主要叙事，文案更像编辑标注，不重复堆砌卖点卡片。
- Fragment 类型和用户故事使用不等高内容块，接近灵感画板而不是四宫格功能列表。
- 不使用渐变球、发光背景、玻璃拟态大卡和每屏重复的“眉题 + 巨型标题 + 四张卡”。
- 工具窗口圆角不超过 8px，阴影柔和但保持边界清晰。

推荐视觉：

- 背景是一张清晰的浏览器技术文档页面。
- 文本选区上出现 AnnHub HoverMenu。
- 右侧或后景自然露出 Desktop 今日页和 Fragment 详情。
- 展示同一条 Fragment 从网页进入 Desktop，而不是并排两张无联系截图。
- 首屏底部露出下一节内容，避免独占全屏。

## 6. 问题区

标题：

```text
收藏没有失败。失败的是收藏之后没有下一步。
```

三列问题：

1. **失去语境**：只剩一句摘录，不知道当时为什么重要。
2. **缺少加工**：原样搬运，没有留下自己的理解和用法。
3. **没有提取**：反复阅读，却从未主动回忆。

不使用“信息过载”“第二大脑”等泛化措辞作为主要问题。

## 7. 工作流区

标题：

```text
从一次选区，到一次主动回忆
```

三步：

### 1. 连同语境采集

自动保留选区、上下文、标题、来源和定位。

### 2. 留下自己的理解

先解释和判断，再查看原文或模型建议。

### 3. 在合适时间重新提取

不是重新阅读，而是解释概念、重建步骤和回忆理由。

这一节对应 [学习模型](learning-model.md)，文案变化不能修改 L1~L3 语义。

## 8. 主用例：从技术资料到主动回忆

  -> 写下它与当前内存问题的关系

  -> 发现理解有误，回到来源修正

## 9. 差异化区

### 不是网页收藏夹

Highlight 和 Clip 可以很多，Fragment 必须包含应用。

### 不是需要自己拼装的插件系统

采集与复习使用同一份领域模型。

### 不让 AI 替你理解

AI 只提供核验建议，用户先生成，建议经你确认才生效。

### 本地优先且可阅读

核心链路离线可用；扩展内容和已保存图片可导出为 Markdown ZIP。

禁止使用无法证明的绝对化文案，例如“唯一”“最先进”“永不丢失”“完全准确”。

## 11. 信任区

标题：

```text
你的材料，不应该成为使用工具的代价
```

要点：

- IndexedDB + SQLite 本地存储。
- 核心链路断网可用。
- LLM 默认关闭或 BYOK。
- 不默认上传正文、URL 和用户产出。
- 不依赖 Desktop 的 Markdown + 原图 ZIP 导出（目标态，按实现进度标注）。
- ZIP 供其他工具阅读，不宣称可还原 Desktop 复习状态。

只有代码已经实现并验证的能力才能使用完成时态。

## 13. FAQ

### 它和 Obsidian 有什么区别？

Obsidian 提供通用本地知识库和插件平台；AnnHub 提供从网页采集、主动加工到复习的一条固定工作流。AnnHub R1 目标是导出 Markdown + 已保存原图的 ZIP，不试图替代 Obsidian 编辑器。

### 它和 Readwise 有什么区别？

Readwise 重点是阅读、高亮和重现；AnnHub 重点是带语境的知识碎片和按类型提取。

### 它和 Anki、RemNote 有什么区别？

Anki 与 RemNote 擅长把已有材料做成记忆卡并按间隔复习。AnnHub 的起点是网页里的真实材料：采集时先写下理解与应用，复习题面按碎片类型给出。AnnHub 不以卡片数量为中心，也不是通用闪卡工具。

### 它和 Recall 这类 AI 知识库有什么区别？

AI 知识库偏重自动摘要、自动图谱和问答来提高整理效率。AnnHub 把“用户先生成”放在 AI 之前，AI 只提供建议，经你确认才生效。

对外的对比表述必须出自 [market.md](market.md) 的已核对事实并带核对日期。

### 必须使用 AI 吗？

不需要。采集、核验、复习和扩展内容导出都必须可以离线运行。

### 数据保存在哪里？

Extension 使用浏览器本地存储，Desktop 使用本地 SQLite；两端通过本机接口交付数据。

### 为什么没有手机端？

当前产品集中在桌面浏览和深度工作闭环，避免在核心体验验证前分散到更多客户端。

### 能导出吗？

R1 目标是在扩展中一键下载 Markdown 与已保存图片组成的 ZIP，不要求安装 Desktop。该 ZIP 适合其他工具阅读，不是可恢复 Desktop 学习状态的数据库备份；页面上线时按实际实现状态表述。
