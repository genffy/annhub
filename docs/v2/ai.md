# 可选 AI 能力

> 层级：core
> 更新：2026-10-04

## 1. 定位

LLM 是摘要提取与核验的可选加速器，不是产品主链路的必需品。

| 层  | 可选作用       | 关闭后的替代             |
| --- | -------------- | ------------------------ |
| L1  | 提取摘要或结构 | 用户确认和手工编辑       |
| L2  | 提供核验建议   | 原文、参考资料、手工总结 |
| L3  | 不参与调度     | 纯本地题型与调度器       |

关闭全部模型能力后，采集、保存、复习和 Markdown ZIP 导出必须继续可用。

## 2. 最小外发

| 用途     | 允许发送                       | 不发送                       |
| -------- | ------------------------------ | ---------------------------- |
| 核验     | 当前碎片、必要上下文、用户问题 | 完整页面、浏览历史、其他碎片 |
| 摘要提取 | 用户明确选择的内容块           | 页面其余正文                 |

URL、页面标题、附件原文件和凭据默认不外发。确有必要时必须由具体功能单独说明并让用户确认。

## 3. 结构化输出

业务调用必须返回结构化 JSON，并经过 schema 校验：

```text
request -> parse -> validate -> domain result
                        |
                        v
                     fallback
```

- 解析或校验失败时，不把原始模型文本直接写入业务字段。
- 失败重试最多一次，之后进入手工或本地降级。
- 截断、超时、鉴权失败和 schema 失败使用不同错误码。
- Prompt 版本和模型标识随结果记录；用户修改后的核验结果保留 `basedOnModel` 来源，便于追踪但不把它当作未经修改的模型原文。

## 4. 来源透明

`verified.source` 必须明确区分：

- `source-material`：来自原始材料或可信引用。
- `manual`：用户手工填写。
- `llm`：模型生成或整理。

模型建议不会自动完成核验；用户明确确认后才记录 `confirmedAt`。建议可以被用户修改，修改后应记录为人工确认结果并保留 `basedOnModel`，不继续宣称完全由模型生成。摘要与备注不因调用模型而变成必填。

## 5. 隐私与密钥

- 需要外发的能力默认关闭。
- API key 不进入日志、导出、同步事件或错误上报。
- 日志只记录调用阶段、错误码、耗时和 token 统计，不记录完整正文。
- 各端直连用户选择的 Provider，不通过学习数据中枢转发。
- 批量调用逐条裁剪上下文，不整页打包。
- 核验建议由用户开启；单次外发前可预览本次选中的内容，关闭某项能力不自动开启其他外发能力。

## 6. 成本控制

- 缓存相同输入与 Prompt 版本的结果。
- 本地规则能完成的任务不调用模型。
- 设置页展示 Provider、模型和最近错误，不隐藏成本来源。
- Provider 的类型见第 8 节；设备端模型同样遵守本文的全部规则。

## 7. 非目标

- 不让模型替用户生成 `processing.use`。
- 不在后台静默处理整库内容。
- 不把模型可用性作为复习队列的前置条件。

## 8. Provider 类型

[D-06](validation.md) 已采纳：除用户自带云端密钥外，提供设备端模型（浏览器内置模型）作为可选 Provider。两类 Provider 遵守同一套规则（第 2–5 节）。

| 类型                                      | 内容去向                                | 前提                                                   | 状态            |
| ----------------------------------------- | --------------------------------------- | ------------------------------------------------------ | --------------- |
| 用户自带云端密钥                          | 发往用户选择的服务商，按第 2 节最小外发 | 用户自备密钥                                           | 可用            |
| 浏览器内置模型（扩展，Chrome 138 及以上） | 留在本机，不外发                        | 模型首次使用时下载，有存储与硬件要求；运行时检测可用性 | 阶段 V 之后提供 |

规则：

- 所有 Provider 默认关闭；核验建议由用户开启（第 5 节）。
- 设备端模型的输出同样只是建议：带来源标签与模型、prompt 版本，用户确认后才生效（第 3、4 节）。
- 设备端不可用（系统版本、硬件、功能未启用或模型未下载）时，界面说明原因并回到手工或本地路径，不阻塞主流程（第 1 节）。
- [H-13](validation.md) 通过之前，界面不把设备端选项标为“推荐”。
- 日志仍只记录调用阶段、错误码和耗时，不记录正文。

事实依据与核对日期见 [market.md §4.2](market.md)。故事与验收见 [US-DATA-06](user-stories.md)。
