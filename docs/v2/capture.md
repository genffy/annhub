# 采集规则

> 层级：core
> 更新：2026-10-08

## 1. 职责

采集层把用户的一次“留下这个”的指认，转换为来源明确、语境尽量完整的条目（[条目契约](entry.md)）并保存到本地。

核心不变量：**每条条目都带来源 URL；语境尽力保存，提取失败不阻塞保存。** 采集不改网页：页面上没有标记，入口与描边都是扩展自己的浮层（[D-19](validation.md)）。

页面级交互以 [扩展 PRD](extension.md) 为准。

## 2. 两种采集，一种内化

| 动作 | 用户意图                         | 入口                                                                                           | 产出                         | 保存方式                                       |
| ---- | -------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------- |
| 剪藏 | 保存一段内容供之后阅读           | 选区菜单“剪藏”（选区剪藏）；悬停在整体内容上的“剪藏”（区块剪藏，细节见 [D-20](validation.md)） | `clip` 条目（Markdown）      | 一次点击，不打开窗口                           |
| 截图 | 保存网页某处的画面               | 选区菜单“截图”；快捷键                                                                         | `screenshot` 条目 + 图片资产 | 选区内编辑后确认，见 [截图采集](screenshot.md) |
| 高亮 | 读懂并划出重点，把内容变成自己的 | 不在页面里：在资料库打开一条剪藏，选中原文（[extension.md §4.2](extension.md)）                | 这条剪藏里的一条高亮         | 一次点击；契约见 [entry.md §4](entry.md)       |

页面上只有剪藏与截图两种采集，选区菜单只有这两项；高亮不是采集，页面里没有高亮入口，没有页面标记，也没有回访恢复和连续高亮模式。保存之后不转换类型：没有“升级”或“改存为”。

## 3. 通用流程

```text
指认内容（选区 / 区块 / 区域 / 元素）
  -> 提取 content（剪藏转为 Markdown，截图为图片）
  -> 提取 context（仅选区剪藏）
  -> 记录来源
  -> 附加类型预设属性
  -> 校验并落库
  -> 提示结果（可撤销，可编辑）
```

自动能力失败时降级，而不是丢弃：缺语境、缺页面 meta 都照样保存。

### 3.1 转换为 Markdown

选区与区块都转换成 Markdown 保存（[D-19](validation.md)），转换规则只在共享领域层实现一次：

- **保留**：标题层级、段落与换行、有序与无序列表、引用、行内代码与代码块、强调、链接。相对链接解析为绝对 http(s)，其他协议的链接只保留文字。
- **图片**：保留替代文字与原地址，不下载、不内联（见 [D-21](validation.md)）。
- **丢弃**：脚本、样式、表单控件、隐藏内容、扩展自己的界面，以及原始 HTML。
- **上限**：超过 50,000 个字符时，在块边界截断保存前面的部分，提示里写明“内容过长，只保存了前 50,000 个字符”。
- 转换失败时降级为纯文本，仍然保存。
- 渲染（阅读视图、导出）同样不解析原始 HTML；链接只允许 http(s)，在新标签页打开并带 `rel="noopener noreferrer"`。

## 4. 语境提取

`context` 是能让用户重新理解这段内容的最小上下文，不等于整个页面正文。只有选区剪藏保存它；区块剪藏的内容本身就是一个完整的单元，不再保存 `context`。

- 必须包含选区的纯文本；选区本身超过上限时不保存 `context`。
- 优先取完整句或语义段，避免按固定字数生硬截断；超长时围绕选区向两侧截断，保证目标内容仍在结果里。
- 不把导航、按钮、页脚、广告和扩展自身 UI 混进上下文。
- 提取失败时省略 `context`，条目仍可保存。

## 5. 来源与页面元数据

采集层记录 `sourceUrl`、`sourceHost` 和创建时间，并从页面得到 `title`、`author`、`published`、`description` 四个属性的初值（[entry.md §5.4](entry.md)）。

- **永久链接**：信息流页面应尽力解析内容项的永久链接作为 `sourceUrl`（区块剪藏时取该区块自己的永久链接，如一条推文的地址），而不是只保存列表页地址。平台规则集中维护，新增站点通过追加规则实现，不散落在业务模块里。解析失败时使用当前页面 URL。
- **页面 meta**：作者、发布日期、描述取自页面 meta（含 Open Graph 与标准 meta），取不到就不设置；`title` 取页面标题。
- **回到来源**：只打开 `sourceUrl`，不在原页面里定位，也不恢复任何标记。

## 6. 剪藏的细节

剪藏有两个入口，保存后的提示、撤销和编辑完全一致。

### 6.1 选区剪藏

- 选中文字后，在选区菜单点击“剪藏”立即保存，不打开窗口。
- 保存后出现约 3 秒的提示“已剪藏 · 撤销 · 编辑”：撤销删除刚保存的条目；编辑在选区旁打开小气泡，可改标题、标签和备注（[extension.md §3](extension.md)）。

### 6.2 区块剪藏

- 指针停在页面里一个整体内容（一条推文或帖子、一篇 `article`、带标题的一节等）上时，区块旁出现“剪藏”入口；点击一次保存整块，不需要选中任何文字。
- 以下情形不出现：页面上有选区、正在拖选或滚动、焦点在输入框里、指针在扩展自己的界面上。入口只是浮层，不改网页内容。
- 保存内容是该区块的 Markdown；`sourceUrl` 取区块自己的永久链接。
- 哪些区块算“整体内容”、入口怎样出现、默认是否打开，尚未确认，见 [D-20](validation.md)。

### 6.3 高亮在这里没有入口

在页面里划线保存的需求由“剪藏”承担；读的时候划重点在资料库里完成，见 [extension.md §4.2](extension.md)。

## 7. 失败处理

| 失败点                     | 处理                                         |
| -------------------------- | -------------------------------------------- |
| 上下文提取失败             | 省略 `context`，继续保存                     |
| 永久链接解析失败           | 使用当前页面 URL                             |
| Markdown 转换失败          | 降级为纯文本，继续保存                       |
| 内容超过上限               | 保存前 50,000 个字符，并在提示里说明         |
| 页面 meta 缺失             | 对应属性不设置                               |
| 图片保存失败               | 保留截图预览并允许重试                       |
| 条目落库失败（含配额不足） | 显示可读错误并允许重试；不显示成功；选区保持 |

任何自动步骤都不能导致用户已经输入的备注、标题或属性丢失。

## 8. 非目标

- 不做无确认的一键批量保存；不默认保存整页正文（区块剪藏保存的是用户指认的一个整体内容，整页正文见 [Q-11](validation.md)）。
- 不在网页上留任何标记，不做回访恢复。
- 不把截图字节放进条目消息；图片通过 `assetId` 引用独立保存的字节。
- 不让站点适配逻辑散落在各业务模块里。
- 不做重复检测与提示：同一内容在不同语境里价值不同，可以多次保存，需要时在资料库里删除。
