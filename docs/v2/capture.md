# 采集规则

> 层级：core
> 更新：2026-10-08

## 1. 职责

采集层把用户的一次“留下这个”的指认，转换为来源明确、语境尽量完整的条目（[条目契约](entry.md)）并保存到本地。

核心不变量：**每条条目都带来源 URL；语境尽力保存，提取失败不阻塞保存。** 采集不改网页：页面上没有标记，入口与描边都是扩展自己的浮层。

页面级交互以 [扩展 PRD](extension.md) 为准。

## 2. 两种采集，一种内化

| 动作 | 用户意图                         | 入口                                                                            | 产出                         | 保存方式                                       |
| ---- | -------------------------------- | ------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------- |
| 剪藏 | 保存一段内容供之后阅读           | 选区菜单“剪藏”（选区剪藏）；指向一个区块后的“剪藏”（区块剪藏，见 §6.2）         | `clip` 条目（Markdown）      | 一次点击，不打开窗口                           |
| 截图 | 保存网页某处的画面               | 选区菜单“截图”；快捷键；区块胶囊里的“截图”                                      | `screenshot` 条目 + 图片资产 | 选区内编辑后确认，见 [截图采集](screenshot.md) |
| 高亮 | 读懂并划出重点，把内容变成自己的 | 不在页面里：在资料库打开一条剪藏，选中原文（[extension.md §4.2](extension.md)） | 这条剪藏里的一条高亮         | 一次点击；契约见 [entry.md §4](entry.md)       |

页面上只有剪藏与截图两种采集，选区菜单只有这两项；高亮不是采集，页面里没有高亮入口，也不留任何标记。条目保存之后不转换类型。

## 3. 通用流程

```text
指认内容（选区 / 区块 / 区域 / 元素）
  -> 提取 content（剪藏转为 Markdown，截图为图片）
  -> 提取 context（仅选区剪藏）
  -> 记录来源
  -> 附加类型预设属性
  -> 校验并落库
  -> 提示结果（可撤销，可编辑）
```

自动能力失败时降级，而不是丢弃：缺语境、缺页面 meta 都照样保存。

保证采集可用的页面范围：普通文章、信息流和 SPA 页面，以及同源 iframe 与 open shadow root 里的选区和区块（识别沿 `composedPath` 穿透 shadow 边界）。跨源 iframe、closed shadow root、可编辑区（输入框与 `contenteditable`）和严格内容安全策略的页面里不出现入口、不报错；`chrome://`、浏览器商店页这类受限页面同样没有入口，由工具栏弹窗兜底（[extension.md §2.6](extension.md)）；PDF 是否进入范围见 [H-15](validation.md)。

### 3.1 转换为 Markdown

选区与区块都转换成 Markdown 保存，转换规则只在共享领域层实现一次：

- **保留**：标题层级、段落与换行、有序与无序列表、引用、行内代码与代码块（保留语言标记）、表格、强调、链接。相对链接解析为绝对 http(s)，其他协议的链接只保留文字。
- **图片**：保留替代文字与原地址，不下载、不内联。阅读视图里只显示占位（替代文字、“图片未保存”和“打开原图”），不联网加载；需要保留画面时用截图，区块胶囊里就有“截图”。
- **页面自己的界面**：区块里常混着页面的界面，转换前先去掉：按钮与工具栏、点赞与分享条、会员与订阅提示、相关文章与推荐、评论入口、广告。X 的帖子按平台规则组装：作者与账号、发布时间、正文、图片的替代文字与原地址、卡片链接、被引用的帖子（以引用块保存）。
- **丢弃**：脚本、样式、表单控件、隐藏内容、扩展自己的界面，以及原始 HTML。
- **隐藏内容与标签页**：隐藏的内容不保存。标签页组（如同一个示例的多种语言）里只保存当前显示的那一页，想要另一页就切到那一页再剪；否则一页文档会带上全部语言的隐藏代码，字数膨胀几倍，个别页面约二十倍（[market.md §4.3](market.md)）。
- **上限**：转换后的 Markdown 超过 100,000 个字符时，在块边界截断保存前面的部分，提示里写明“内容过长，只保存了前 100,000 个字符”，并建议改选其中一节再剪藏。上限是初始值，见 [Q-17](validation.md)。
- 转换失败时降级为纯文本，仍然保存。
- 渲染（阅读视图、导出）同样不解析原始 HTML；链接只允许 http(s)，在新标签页打开并带 `rel="noopener noreferrer"`。

## 4. 语境提取

`context` 是能让用户重新理解这段内容的最小上下文，不等于整个页面正文。只有选区剪藏保存它；区块剪藏的内容本身就是一个完整的单元，不保存 `context`。

- 必须包含选区的纯文本；选区本身超过上限时不保存 `context`。
- 优先取完整句或语义段，避免按固定字数生硬截断；超长时围绕选区向两侧截断，保证目标内容仍在结果里。
- 不把导航、按钮、页脚、广告和扩展自身 UI 混进上下文。
- 提取失败时省略 `context`，条目仍可保存。

## 5. 来源与页面元数据

采集层记录 `sourceUrl`、`sourceHost` 和创建时间，并从页面得到 `title`、`author`、`published`、`description` 四个属性的初值（[entry.md §5.4](entry.md)）。

- **永久链接**：信息流页面应尽力解析内容项的永久链接作为 `sourceUrl`，而不是只保存列表页地址。区块剪藏取该区块自己的永久链接：帖子取帖子的地址（X 取自帖子里发布时间的链接）；一节取页面地址加该节标题的锚点（标题或包住它的元素有 `id` 时），“回到来源”因此直接落在这一节；其余区块取页面地址。平台规则集中维护，新增站点通过追加规则实现，不散落在业务模块里。解析失败时使用当前页面 URL。
- **页面 meta**：作者、发布日期、描述取自页面 meta（含 Open Graph 与标准 meta），取不到就不设置；`title` 取页面标题。
- **来源地址里的 query 与 hash**：保存前去掉带令牌特征的参数，其余保留，包括区块剪藏用的标题锚点。清理规则只在共享领域层实现一次：query 与 hash 里以 `?` / `&` 分隔的参数，名称不区分大小写并去掉首尾空白后属于令牌名清单的，整段删除；hash 里非查询参数形式的部分（路径与锚点）原样保留；清理后留下空的 `?` 或 `#` 时一并去掉；清理后的地址仍必须是绝对 http(s) 链接。令牌名清单：`token`、`access_token`、`refresh_token`、`id_token`、`code`、`session`、`session_id`、`sessionid`、`auth`、`auth_token`、`api_key`、`apikey`、`secret`、`sig`、`signature`、`jwt`。
- **回到来源**：只打开 `sourceUrl`，不在原页面里定位，也不恢复任何标记。

## 6. 剪藏的细节

剪藏有两个入口，保存后的提示、撤销和编辑完全一致。

### 6.1 选区剪藏

- 选中文字后，在选区菜单点击“剪藏”立即保存，不打开窗口。
- 保存后出现约 3 秒的提示“已剪藏 · 撤销 · 编辑”：撤销删除刚保存的条目；编辑在选区旁打开小气泡，可改标题、标签和备注（[extension.md §3](extension.md)）。

### 6.2 区块剪藏

指一下就剪整块，不需要先选中文字。入口有两个，保存的结果完全相同：**悬停入口**（鼠标）和**区块模式**（键盘）。

**区块有哪几种。** 指针下满足条件的最内层单元就是目标，表里靠前的更小：

| 单元   | 怎样识别                                                                                                                                                                                              | 例子                              |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| 帖子   | 平台规则：X 时间线或详情页里的一条帖子，含图片、卡片和被引用的帖子                                                                                                                                    | 一条推文                          |
| 代码块 | `pre`                                                                                                                                                                                                 | 文档里的示例代码                  |
| 表格   | 有表头，或至少两行两列的数据表；包住整篇正文的布局表格不算                                                                                                                                            | 参数对照表                        |
| 图     | `figure`，或宽度不小于 200px 的图片                                                                                                                                                                   | 带图注的图表                      |
| 引用   | `blockquote`，不少于 20 个字符                                                                                                                                                                        | 文章里的引文                      |
| 一节   | 从一个标题（`h1` 至 `h4`）到下一个同级或更高级标题之间的内容；页面用 `section` 包住各节时取这个 `section`                                                                                             | 文档里的“安装”一节                |
| 文章   | `article`、`[role=article]`；没有时取正文容器：`main`、`[role=main]` 和常见的内容容器（如 `.entry-content`、`.post-content`、`.markdown-body`）；仍没有时取直接包含至少三个有文字量的段落的最内层容器 | Medium 文章、博客文章、文档页正文 |

一节和文章都要求正文不少于 120 个字符，按字符数而不是词数计，中文同样适用。段落、列表项和标题本身不是单元：指针停在一段正文上时，目标是它所在的一节，页面没有标题时是文章。帖子（X）和文章（Medium）有平台规则，集中维护；新增站点靠追加规则，不改通用识别。识别规则的依据和页面抽样见 [market.md §4.3](market.md)。

**层级。** 同一个指针位置有几层目标时，先取最内层；“上一级”按钮（⌃）和 `↑` 选外面一层，`↓` 回到里面一层。顺序是：帖子、代码块、表格、图、引用 → 一节 → 文章。

**悬停入口。** 指针在一个区块上停下约 400ms，区块出现描边，旁边出现胶囊：「剪藏」「截图」「上一级」「更多」。指针离开约 150ms 后收起；开始滚动、按键或拖选时立刻收起。

- 「剪藏」保存这个区块；「截图」以这个区块为目标元素进入原位编辑（[screenshot.md §1](screenshot.md)）；「更多」里有“在此网站停用”“关闭区块剪藏入口”“设置…”。
- **位置**：优先放在区块的右上角；区块比窗口高时，贴着窗口里可见部分的上沿，这样指针在一篇长文里的任何位置，胶囊都在视野里。胶囊都跨在区块的边缘上，一半在区块外。右上角被页面自己的链接、按钮或菜单占住时（时间线帖子的“更多”按钮、代码块的“复制”按钮），依次试左上角、右下角、左下角，选第一个不盖住页面控件的位置；都被占住时放在指针旁。

**区块模式。** 快捷键进入（默认 `Ctrl+Shift+E` / `Cmd+Shift+E`，可在浏览器的快捷键设置里改），页面里的链接在模式里暂不响应点击。指针悬停时，描边跟着指针；键盘上 `Tab` / `Shift+Tab` 移到下一个或上一个同层单元，`↑` / `↓` 换层级，`Enter` 剪藏，`S` 截图，`Esc` 退出。模式胶囊用文字说明当前的区块类型和这些按键，读屏会读出区块类型与摘要。

**不出现**：页面上有选区或正在拖选、焦点在输入框或可编辑区、指针在扩展自己的界面上、`nav` `header` `footer` `aside`、表单与对话框里、不可见的元素、文字不足的容器。入口只是扩展自己的浮层，不改网页内容。识别只在指针停下之后运行，只检查指针下的祖先链，不整页扫描，所以不拖慢滚动；open shadow root 里的区块同样可以识别。

**保存。** 区块转为 Markdown（§3.1）；`sourceUrl` 取区块自己的永久链接（§5）；不保存 `context`。保存后的提示、撤销与编辑和选区剪藏完全一致。

**默认与开关。** 悬停入口默认开启，设置里可整体关闭，也可在胶囊的“更多”里按网站停用，已停用的网站在设置里管理（[extension.md §2.5](extension.md)）。区块模式是用户明确发起的，不受这个开关影响。

### 6.3 高亮在这里没有入口

在页面里划线保存的需求由“剪藏”承担；读的时候划重点在资料库里完成，见 [extension.md §4.2](extension.md)。

## 7. 失败处理

| 失败点                     | 处理                                         |
| -------------------------- | -------------------------------------------- |
| 上下文提取失败             | 省略 `context`，继续保存                     |
| 永久链接解析失败           | 使用当前页面 URL                             |
| Markdown 转换失败          | 降级为纯文本，继续保存                       |
| 内容超过上限               | 保存前 100,000 个字符，并在提示里说明        |
| 页面 meta 缺失             | 对应属性不设置                               |
| 平台规则失效（站点改版）   | 退回通用识别，内容可能带页面的界面；仍然保存 |
| 页面里没有符合的区块       | 不出现入口；选区剪藏照常可用                 |
| 图片保存失败               | 保留截图预览并允许重试                       |
| 条目落库失败（含配额不足） | 显示可读错误并允许重试；不显示成功；选区保持 |

任何自动步骤都不能导致用户已经输入的备注、标题或属性丢失。

## 8. 非目标

- 不做无确认的一键批量保存；不默认保存整页正文（区块剪藏保存的是用户指认的一个整体内容，整页正文见 [Q-11](validation.md)）。
- 不在网页上留任何标记。
- 不自动展开线程或评论串：一次剪一个帖子，想要整串时逐条剪，或者截图。
- 不把截图字节放进条目消息；图片通过 `assetId` 引用独立保存的字节。
- 不让站点适配逻辑散落在各业务模块里。
- 不做重复检测与提示：同一内容在不同语境里价值不同，可以多次保存，需要时在资料库里删除。
