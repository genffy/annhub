# 采集规则

> 层级：core
> 更新：2026-10-07

## 1. 职责

采集层把用户的一次“留下这个”的指认，转换为来源明确、语境尽量完整的条目（[条目契约](entry.md)）并保存到本地。

核心不变量：**每条条目都带来源 URL；语境尽力保存，提取失败不阻塞保存。**

页面级交互以 [扩展 PRD](extension.md) 为准。

## 2. 三种采集

| 类型 | 用户意图                   | 入口                         | 产出                         | 保存方式                                       |
| ---- | -------------------------- | ---------------------------- | ---------------------------- | ---------------------------------------------- |
| 剪藏 | 保存一段内容供之后查阅     | 选区菜单“剪藏”               | `clip` 条目                  | 一次点击，不打开窗口                           |
| 高亮 | 在页面上留下标记，回访恢复 | 选区菜单“高亮”；连续高亮模式 | `highlight` 条目 + 页面标记  | 一次点击，不打开窗口                           |
| 截图 | 保存网页某处的画面         | 选区菜单“截图”；快捷键       | `screenshot` 条目 + 图片资产 | 选区内编辑后确认，见 [截图采集](screenshot.md) |

三种采集共用第 3 至 5 节的来源、语境、定位与属性规则。保存之后不转换类型：没有“升级”或“改存为”。

## 3. 通用流程

```text
指认内容（选区 / 区域 / 元素）
  -> 提取 content（截图为图片）
  -> 提取 context
  -> 记录来源与定位
  -> 附加类型预设属性
  -> 校验并落库
  -> 提示结果（可撤销，可编辑）
```

自动能力失败时降级，而不是丢弃：缺语境、缺定位、缺页面 meta 都照样保存。

## 4. 语境提取

`context` 是能让用户重新理解这段内容的最小上下文，不等于整个页面正文。

- 必须包含 `content` 的归一化结果；选区本身超过上限时不保存 `context`。
- 优先取完整句或语义段，避免按固定字数生硬截断；超长时围绕选区向两侧截断，保证目标内容仍在结果里。
- 不把导航、按钮、页脚、广告和扩展自身 UI 混进上下文。
- 提取失败时省略 `context`，条目仍可保存。

## 5. 来源、定位与页面元数据

采集层记录 `sourceUrl`、`sourceHost`、`pageUrl`（与 `sourceUrl` 不同时）、`locator` 和创建时间，并从页面得到 `title`、`author`、`published`、`description` 四个属性的初值（[entry.md §5.4](entry.md)）。

- **永久链接**：信息流页面应尽力解析内容项的永久链接作为 `sourceUrl`，而不是只保存列表页地址，列表页地址记入 `pageUrl`。平台规则集中维护，新增站点通过追加规则实现，不散落在业务模块里。解析失败时使用当前页面 URL。
- **DOM selector** 的优先级：稳定测试属性、稳定 ID、过滤后的 class、结构路径。生成失败使用 `{ type: 'none' }`，不阻塞保存。
- **页面 meta**：作者、发布日期、描述取自页面 meta（含 Open Graph 与标准 meta），取不到就不设置；`title` 取页面标题。
- **高亮恢复**：回访页面时，按当前 URL 同时匹配 `pageUrl` 与 `sourceUrl` 取出该页的高亮；先按 selector 与 `textOffset` 定位，失败再按 `before` / `after` 在正文里搜索；SPA 页面的延迟内容需要重试。实现策略见 [页面标注架构](../annotation-architecture-refactor.md)。

## 6. 剪藏与高亮的细节

**剪藏**

- 点击“剪藏”立即保存，不打开窗口。
- 保存后出现约 3 秒的提示“已剪藏 · 撤销 · 编辑”：撤销删除刚保存的条目；编辑在选区旁打开小气泡，可改标题、标签和备注（[extension.md §3](extension.md)）。

**高亮**

- 点击“高亮”创建页面标记并保存；可以加备注；颜色默认取设置里的默认高亮色，之后可改。
- 连续高亮模式：`Alt+H` / `Cmd+Shift+H` 进入，每次选中创建一条，`Esc` 退出。
- 删除高亮必须恢复页面的原文本结构；标记不得嵌套，扩展界面不得被序列化进页面正文。

## 7. 失败处理

| 失败点                     | 处理                                                             |
| -------------------------- | ---------------------------------------------------------------- |
| 上下文提取失败             | 省略 `context`，继续保存                                         |
| 永久链接解析失败           | 使用当前页面 URL                                                 |
| 定位符生成失败             | 保存 `none`；高亮仍保存，只是回访时无法恢复标记                  |
| 页面 meta 缺失             | 对应属性不设置                                                   |
| 图片保存失败               | 保留截图预览并允许重试                                           |
| 条目落库失败（含配额不足） | 显示可读错误并允许重试；不显示成功；高亮同时撤掉刚创建的页面标记 |

任何自动步骤都不能导致用户已经输入的备注、标题或属性丢失。

## 8. 非目标

- 不做无确认的一键批量保存；不默认保存整页正文（整页剪藏见 [Q-11](validation.md)）。
- 不把截图字节放进条目消息；图片通过 `assetId` 引用独立保存的字节。
- 不让站点适配逻辑散落在各业务模块里。
- 不做重复检测与提示：同一内容在不同语境里价值不同，可以多次保存，需要时在资料库里删除。
