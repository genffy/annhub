# 产品路线图

> 层级：vision
> 状态：当前计划；交付状态的唯一入口
> 更新：2026-10-04

本文是阶段顺序、发布范围、交付状态和发布门禁的唯一真源。页面体验见 [扩展](extension.md) 与 [Desktop](desktop.md)，字段和算法见 [Fragment 契约](fragments.md)、[复习](review.md)和[存储](storage.md)。尚未验证的假设与待确认的路线调整见 [validation.md](validation.md)。

## 1. 排期原则

1. R1 先完成通用文本 Fragment 的端到端闭环，并纳入网页截图的基础 `visual`；其他内容形态后续增加。
2. 先把采集、加工、复习的闭环做扎实，再扩展自动化。
3. 每个版本都必须在关闭 LLM、断网和无 Desktop 连接的部分场景下可降级运行。
4. 当前没有需要兼容的用户存量数据；直接实现最新契约。导出、测试和文档是功能的一部分，不在版本末尾补做。
5. 不为未进入当前版本的能力提前增加 UI 入口。
6. 交付完成不等于验证完成。自动化测试通过只说明“做出来了”；用户是否真的使用，由 [validation.md](validation.md) 的阶段 V 回答。

| 版本 | 用户结果 | 状态 | 备注 |
| ---- | -------- | ---- | ---- |

| R1 通用文本与基础 `visual` 闭环 | 用户能从网页文本、灵感和截图创建 Fragment，在 Desktop 复习；没有 Desktop 也能导出 | 范围完成 | 真机走查待补，见第 5 节 |

| R4 视觉增强与音视频来源 | 图像遮挡复习；视频、音频区间可保存为 `media-clip` | 范围完成 | — |

**状态词**：`未开始` → `进行中` → `范围完成`（清单全部勾选且验收条件满足，尚未经真实用户验证）→ `已验证`（对应假设在 validation.md 中通过）。`未触发` 表示已决定做，但进入条件尚未满足。R2 已取消（[D-10](validation.md)），版本号不复用。

## R1：通用文本与基础 visual Fragment 闭环

**产品承诺**：用户可以从网页文本或截图创建知识碎片。扩展离线保存后逐条写入 Desktop 本地服务，Desktop 可查看和复习；即使没有 Desktop，扩展也能将本地内容与已保存图片导出为一份可供其他工具阅读的 Markdown ZIP。该 ZIP 不承诺恢复 Desktop 学习状态。

### R1.1 最新数据契约（P0）

- [x] 用 `excerpt / concept / claim / procedure / decision / question / inspiration / visual` 建立当前启用的 kind 契约。
- [x] 实现对应 `DetailOf`、`VerifiedResult`、视觉图片定位符和运行时校验器；核验须用户明确确认并保存时间与来源，摘要和备注可选。
- [x] 将应用校验改为通用规则，移除固定语言 token 门槛。
- [x] 将 Fragment wire schema 切换到 v4；旧记录与旧 JSON 导出不做迁移，也不为新契约沿用旧 exportVersion。
- [x] 同步 TypeScript、Swift、IndexedDB、SQLite 和单条写入 fixture（含图片字节与拒绝案例，两端字节级一致）。
- [x] 按统一检索契约实现基础搜索、筛选和稳定排序。
- [x] 扩展本地写入与 OutboxEvent 同事务，为断线重试保留待发送记录。
- [x] 截图元数据与原图 `Blob` 同事务保存；Desktop 的 `assets` 表存原图 `BLOB`，两端按稳定 ID 和哈希校验。
- [x] 删除或隔离不再属于当前产品的旧消息、设置和测试入口（旧词表标注层的隔离处置见第 5 节）。

**验收**：七种文本 kind 和基础 `visual` 可经本地接口逐条落库；重复请求与断线重试不重复写入，扩展更新不覆盖 Desktop 的复习状态。

### R1.2 Extension 采集（P0）

- [x] HoverMenu 明确显示 Fragment、Highlight、Clip、Screenshot 四种动作。
- [x] 实现标准模式“核验 -> 应用”。
- [x] 实现深度模式“理解 -> 核验 -> 应用”。
- [x] 按 kind 显示不同提问、detail 字段和校验提示。
- [x] 碎片库支持无需网页选区的新建 `inspiration`，填写原创内容和触发背景。
- [x] 允许修正 content、excerpt、source 和 kind（保护字段修改须重新核验，captureRevision 递增）。
- [x] LLM 不可用时可手工完成（采集链路不依赖 LLM；核验为用户显式确认）。
- [x] 保存失败、返回和关闭时保留输入（表单状态短防抖写入会话级存储，同一浏览器会话内可恢复）。
- [x] 高亮和 Clip 可从详情升级为 Fragment。
- [x] 按[截图契约](screenshot.md)完成微信截图式选区内编辑的边界验收，以及区域/元素截图的统一 Blob 入库、共享资产 ID、`visual` 转换与 Desktop 图片交付。
- [x] 提供唯一的“导出内容”命令，生成 Fragment、Highlight、Clip、截图 Markdown 与已保存原图组成的 ZIP。

**验收**：在普通文章、信息流和 SPA 页面中创建文本 Fragment；区域与元素截图都能完成匿名、预览、入库并转为 `visual`。断开 Desktop 后仍能保存、查看和导出，ZIP 图片链接有效；连接恢复后逐条交付 Fragment 与原图。

### R1.3 Desktop 基础闭环（P0）

- [x] 一级导航为今日、碎片库、系统。
- [x] 今日页展示到期复习和最近写入的碎片。
- [x] 碎片库实现 kind/source/tag 筛选；review 状态在 Desktop 数据回传后启用。
- [x] 详情页按“用户应用 -> 核验 -> 原文 -> 复习历史”展示。
- [x] 七种文本 kind 和基础 `visual` 使用对应复习题型；附件不可用时仍可查看文字与加工内容。

- [x] 系统页展示本地服务、连接、交付错误与契约版本；R1 不提供第二种用户导出或旧 JSON 导入。

**验收**：扩展离线采集后，Desktop 启动本地服务并接收写入；用户可查看 Fragment、完成首次复习并在重启后恢复会话。

### R1.4 激活与质量（P1）

- [x] 增加 1 万条 Fragment 的查询性能基准，满足首屏 200ms 内返回的目标。

## R3：双向本地收敛

**产品承诺**：在 R1 单向交付基础上，Desktop 的复习结果可回传扩展；两端各自保留本地删除选择。

### R3.1 增量同步（P0）

- [x] 沿用 R1 的本地写入与 OutboxEvent 原子事务。
- [x] Desktop 幂等接收事件（按设备与事件 ID 去重，未知目标跳过并报告）。
- [x] Desktop 提供按游标的增量变更拉取（单调序号，扩展持久化游标，批量应用后前进）。
- [x] 数据回传后，Extension 卡片可显示最近复习状态。
- [x] 确认后裁剪 outbox，失败按周期退避重试。
- [x] 采集字段与复习字段按归属合并；同域并发冲突生成可见报告，不能整条 Fragment LWW 覆盖。
- [x] 扩展与 Desktop 的本地删除标记分别阻止旧 ID 在本端复活，删除动作不跨端传播。

### R3.2 导出内容补全（P1）

- [x] 双向收敛稳定后，把 Desktop 回传的复习摘要加入同一种 Markdown ZIP 的可阅读视图。
- [x] 保留 source、processing 和 review 摘要；仍不宣称 ZIP 可无损恢复数据库。

**验收**：重复回传不产生重复实体；本地删除不会被对端旧记录复活；ZIP 仍只有一种用户可见格式。

## R5：截图编辑增强

**进入条件**：阶段 V 结束。R5 按 [D-02](validation.md) 拆成两条互相独立的线：

| 条目 | 性质 | 进入条件 | 状态 |
| ---- | ---- | -------- | ---- |
| R5.3 精确选区 | 截图采集的精度改进，惠及所有截图用户 | 阶段 V 结束后即可排期，无其他门槛 | 未开始 |
| R5.1 美化与品牌、R5.2 导出增强 | 面向内容创作者的成品图能力，目标用户不在三类核心用户之内 | [H-14](validation.md) 通过 | 后置 |

**产品承诺（完整范围）**：用户在扩展内就能把网页截图加工成可直接使用的成品图——精确选中目标内容、加上衬底与个人品牌水印，并按目标平台常用尺寸导出。这是截图编辑器的像素处理能力增强，不是社交分享功能：真实的发布动作不进入扩展域，产物以本地下载与截图集入库为终点。

### R5.1 美化与品牌（P2，后置）

- [ ] 衬底背景（无 / 纯色 / 渐变）、内容内边距、圆角、边框与阴影。
- [ ] 输出画布比例（原始 / 1:1 / 3:4 / 4:5 / 16:9），非原始比例时内容等比完整置入，不裁切。
- [ ] 文字水印与 LOGO 图章（仅存扩展本地），位置九宫格、透明度与边距；设置页新增“截图品牌”一节，管理 LOGO 的上传、更换与移除。
- [ ] 品牌预设保存与一键套用；编辑器里只套用与保存，重命名与删除在设置页的“截图品牌”一节。
- [ ] 合成沿用非破坏式重绘；美化参数不进入标注撤销栈。

**验收**：启用衬底与水印后，原位预览即时反映合成结果；画布超出视口时按比例缩小预览但保存完整像素；截图集入库与 ZIP 中的图片为合成后的完整结果；关闭美化面板后所有行为与 R1 截图链路一致；设置页能上传、更换、移除 LOGO，并重命名、删除预设。

### R5.2 导出增强（P2，后置）

- [ ] 下载格式 PNG（默认）/ JPEG（默认质量 0.9）/ WebP；截图集入库统一 PNG。
- [ ] 以 PNG 复制到剪贴板，新增 `clipboardWrite` 权限。
- [ ] 平台尺寸预设：小红书 3:4（1080×1440）、1:1（1080×1080）；X 16:9（1600×900，单图不超过 5MB）；在美化面板“输出”区、比例选择的下面选择。

**验收**：三种格式下载可用且扩展名正确；剪贴板可粘贴到外部编辑器；尺寸预设只影响输出尺寸，编辑器内不出现任何平台上传或账号操作。

### R5.3 精确选区（P1）

- [ ] 拖拽实时吸附元素边缘并高亮提示，起止点可吸附元素矩形。
- [ ] 选区确认前八向手柄二次调边；方向键微调 1 像素（`Shift` 每次 10 像素）。
- [ ] 比例锁定：`Shift` 临时锁定，或按预设比例拖拽。
- [ ] 选区确认：拖拽松开后选区保持可调，出现“确认选区 / 取消”；`Enter` 或点击确认后进入原位编辑，`Esc` 取消；单击元素路径不变。

**验收**：吸附、手柄与微调在普通页面和 SPA fixture 可用，与单击元素截图共存不冲突；比例锁定下拖拽始终输出目标比例；拖拽后须确认选区才进入编辑，`Esc` 取消会话。

**明确不做**：真实发布/分享动作、平台 API 与社媒账号授权；文案卡与封面模板、设备边框、模板市场；多选区拼接与整页滚动截图；品牌素材跨端同步。

## 4. 通用发布门禁

每个版本必须同时满足：

- TypeScript compile 通过。
- TypeScript 领域逻辑全量单测通过。
- Swift 全量单测通过。
- Desktop 构建通过。
- Extension 关键路径 E2E 通过。
- 当前契约的单条消息和图片字节跨语言 fixture 通过。
- Markdown ZIP 的内容、来源与图片相对链接检查通过；无 Desktop 时可独立导出。
- 对外分发的构建可由目标用户自行安装：扩展已通过商店审核（可见性按分发范围选择），Desktop 安装包已签名并公证。
- 受影响文档和错误恢复路径更新。
- 关闭 LLM 的主流程回归通过。
