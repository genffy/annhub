# 浏览器扩展 PRD

> 层级：product
> 状态：目标体验真源
> 更新：2026-10-04

本文定义浏览器扩展的产品职责、信息架构、交互流程、状态和验收标准。DOM 与消息实现见根目录 `AGENTS.md`。

## 1. 产品职责

Extension 只负责四件事：

1. 在原始网页中指认内容。
2. 保留来源、上下文和定位。
3. 完成一次最小主动加工。
4. 本地保存后，通过 Desktop 提供的本地服务接口交付 Fragment。

Extension 不提供完整复习和通用笔记编辑器。

## 2. 信息架构

### 2.1 页面内入口

用户选中文本后显示 HoverMenu：

| 操作（中文 / English） | 图标          | 结果                                                                                             |
| ---------------------- | ------------- | ------------------------------------------------------------------------------------------------ |
| 碎片 / Fragment        | `brain`       | 打开采集 Modal，进入学习核心                                                                     |
| 高亮 / Highlight       | `highlighter` | 创建视觉标记，可添加备注                                                                         |
| 剪藏 / Clip            | `bookmark`    | 快速保存原文和上下文，不进入复习                                                                 |
| 截图 / Screenshot      | `scan`        | 进入区域或元素截图                                                                               |
| 媒体片段 / Media clip  | `film`        | 页面存在可捕获的 `<video>/<audio>` 时追加显示：标记时间区间并手工转写，保存为 `media-clip`（R4） |

界面文案按语言本地化（[D-11](validation.md)）：中文界面把 Fragment 称为“碎片”，英文界面保留 “Fragment”；字段名、实体名和文档里的概念名不变。下文引用的中文按钮文案同理。

默认排序：Fragment、Highlight、Clip、Screenshot；无媒体的页面只显示前四项。菜单必须使用图标加短文本，不依赖位置测试。

```text
选中文本后，在选区旁出现：
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ [brain] 碎片 | [highlighter] 高亮 | [bookmark] 剪藏 | [scan] 截图 | [film] 媒体片段* │
└──────────────────────────────────────────────────────────────────────────────────────┘
* 仅当页面存在可捕获的 <video> / <audio> 时出现
```

悬停或键盘聚焦约 300ms 后，动作旁出现一句后果，格式为“耗时 · 产物 · 是否进入复习”，让三条保存路径的差别在入口就看得见（[US-CAP-01](user-stories.md)）：

| 动作     | 提示（中文）                               |
| -------- | ------------------------------------------ |
| 碎片     | 理解并应用 · 约 30–90 秒 · 进入复习        |
| 高亮     | 只在页面留痕，可加备注 · 不进入复习        |
| 剪藏     | 保存原文和语境，之后查阅 · 不进入复习      |
| 截图     | 框选区域或单击元素 · 先进入截图集          |
| 媒体片段 | 标记起止时间，手工转写 · 保存为 media-clip |

这组文案是否让用户分清三条路径，由 [H-05](validation.md) 的首次使用走查（E-03）验证，未通过时先调整文案与菜单排序。英文界面使用对应的英文译文，语言选择见 [D-15](validation.md)。

### 2.2 扩展页

扩展内部只有三个一级页面：

```text
碎片库
截图集
设置
```

高亮列表和剪藏列表是碎片库中的独立视图，计数与搜索口径单独标识，不再扩张为新的一级导航。设置只通过一级导航进入，更多菜单不重复这个入口。
碎片库提供“新建灵感”命令，无需网页选区即可打开 `inspiration` 表单。

界面语言随浏览器界面语言（[D-15](validation.md)）：中文系语言显示中文，其他语言显示英文，没有手动切换。弹窗、页面内菜单与采集窗口、扩展页、截图工具栏、错误提示和 Markdown ZIP 的章节标题都按这个语言显示；扩展清单里的名称、描述和快捷键说明也有两种语言。保存到 Fragment 的用户内容不翻译。本文的中文文案是界面的中文版本，英文版与它一一对应。

### 2.3 工具栏弹窗

点击浏览器工具栏图标打开一个最小弹窗；它也是 `chrome://` 等页面内入口失效时的兜底。

```text
┌ AnnHub ──────────────────────────────────────────────────────────┐
│ (o) 已连接 / 2 分钟前交付                                        │
├──────────────────────────────────────────────────────────────────┤
│ [lightbulb] 新建灵感                                    无需选区 │
│ [library]   打开碎片库                                    128 条 │
│ [images]    打开截图集                                     24 张 │
├──────────────────────────────────────────────────────────────────┤
│ Desktop 上有 5 条到期复习                         [打开 Desktop] │
│ 预计 4 分钟 / 数据来自最近一次回传                               │
├──────────────────────────────────────────────────────────────────┤
│ 选中网页文字即可保存 / Cmd+Shift+S 截图                          │
└──────────────────────────────────────────────────────────────────┘
```

- 顶部显示连接状态，沿用第 6 节的四种状态。
- 三个入口分别打开“新建灵感”、碎片库和截图集；弹窗不提供复习、编辑或设置。
- “Desktop 上有 N 条到期复习”只在已连接且 Desktop 数据已回传（R3）时显示；未连接或没有回传数据时这一块整体不出现，不用空数字占位，也不使用红色徽标。深度操作仍进入 Desktop（[product.md §8](product.md)）。

## 3. 保存分流

### 3.1 Fragment

适合：用户希望理解、记住或后续使用的内容。

硬要求：

- 有可理解的上下文。
- 选择或确认 kind。
- 完成核验。
- 写下非空应用。

### 3.2 Highlight

适合：只需在原页面保留视觉位置和备注。

- 不创建 ReviewState。
- 不出现在今日队列。
- 后续可从高亮详情“升级为碎片”。

### 3.3 Clip

适合：保存一段内容供搜索或查阅，但暂不投入学习成本。

- 保存速度优先。
- 不要求用户加工。
- 保存后出现约 3 秒的提示“已剪藏 · 不进入复习”，期间可“撤销”，撤销会删除刚保存的这条剪藏。
- 后续可在碎片库的剪藏列表中“转为碎片”。

这个分流是缓解采集摩擦的主要机制，不新增“未加工 Fragment”。

## 4. Fragment 采集流程

### 4.1 Modal 总体结构

```text
顶部：来源标题 + host + 回到原文
正文：选区 + 可编辑上下文
类型：kind segmented control / menu
步骤区：理解（深度模式） -> 核验 -> 应用
底部：同时高亮原文 / 取消 / 保存
```

Modal 最大宽度 560px；在小视口中占据除 16px 边距外的可用宽度。步骤切换不能改变 Modal 的外框尺寸。

来源条的“回到原文”会把窗口收成屏幕底部的一条并把页面滚到选区，已填内容保留，再点一次展开。核验要求用户回看来源，窗口不应挡住原文（[H-10](validation.md)）。

标准模式、核验步骤的布局（概念类 Fragment）：

```text
┌ 最大 560px ────────────────────────────────────────────────────────────────────┐
│ Backpressure in Streams       engineering.example.com   回到原文               │
├────────────────────────────────────────────────────────────────────────────────┤
│ 选区    「...the consumer signals demand upstream so the producer...」         │
│ 上下文  > 前后各一句，可编辑                                                   │
│ 类型    [概念] 论点 方法 决策 问题 灵感 视觉 摘录   <- 自动推断，可改          │
├────────────────────────────────────────────────────────────────────────────────┤
│  理解（仅深度模式）  >  (o) 核验  >  应用                                      │
│                                                                                │
│  对照定义、边界和示例                                                回看来源  │
│  ┌ 来源语境 ──────────────────────────────────────────────────────────────┐    │
│  │ ...Instead of letting buffers absorb the mismatch indefinitely,        │    │
│  │ 「the consumer signals demand upstream so the producer slows down」... │    │
│  └────────────────────────────────────────────────────────────────────────┘    │
│  [+ 摘要（可选）]  [+ 备注（可选）]                                            │
│  [ ] 确认已核对                  核验来源： (o) 原文   ( ) 手工   ( ) 模型建议 │
├────────────────────────────────────────────────────────────────────────────────┤
│ [x] 同时高亮原文                          [取消]       [下一步  Cmd+Enter]     │
└────────────────────────────────────────────────────────────────────────────────┘
```

核验步骤默认显示来源语境对照卡：选区高亮、前后文淡出；深度模式把用户在“理解”步骤写下的内容并排放进卡片，方便对照。摘要与备注默认折叠为“＋ 摘要（可选）”“＋ 备注（可选）”，点开再填，降低采集摩擦（[H-01](validation.md)）。

各步骤的前进条件与界面状态：

| 步骤               | 内容                                      | 前进条件                 | 失败或降级                                                                            |
| ------------------ | ----------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------- |
| 理解（仅深度模式） | 该 kind 的第一问，见 [kinds.md](kinds.md) | 数据层可选               | —                                                                                     |
| 核验               | 对照来源语境卡；摘要、备注默认折叠，可选  | 点击“确认已核对”         | 模型建议出错时显示“重试”和“手工核对”，不阻塞                                          |
| 应用               | 该 kind 的应用提示                        | 非空且不等于内容或上下文 | 输入不足时显示针对该 kind 的具体提示                                                  |
| 保存               | 本地写入                                  | 写入成功                 | 失败时保留全部输入和当前步骤，显示错误与重试，窗口不关闭，并提供保底出口（见第 9 节） |

关闭时有未保存的输入，必须出现确认，并提供安全出口：

```text
┌────────────────────────────────────────────────┐
│ 放弃已填写的内容？                             │
│ [继续编辑]  [改存为高亮]  [改存为剪藏]  [放弃] │
└────────────────────────────────────────────────┘
```

“改存为高亮 / 剪藏”不创建 ReviewState，也不会自动升级为 Fragment（[US-CAP-01](user-stories.md)）。选择记入 `capture.exited` 的 `fallback`（[M-16](metrics.md)）。

### 4.2 模式

| 模式     | 流程                 | 适用                                 |
| -------- | -------------------- | ------------------------------------ |
| 标准模式 | 核验 -> 应用         | 用户已明确知道为何保存               |
| 深度模式 | 理解 -> 核验 -> 应用 | 概念陌生、观点有争议、需要先形成判断 |

深度模式是全局偏好，也可在单次 Modal 中临时切换。切换后不得丢失已填内容。

### 4.3 自动预填

打开 Modal 时立即显示本地可得字段，不等待模型：

- `content`
- `context.excerpt`
- `sourceUrl`
- `sourceTitle`
- `sourceHost`
- `locator`
- 根据结构和关键词推断的 kind 候选

kind 自动推断只是默认选择，必须允许用户修正。“新建灵感”没有网页选区时不推断网页字段，使用本地来源并由用户填写想法与触发背景。

### 4.4 按 kind 的表单

每种 kind 的提问、应用提示、必填字段与示例集中在 [kinds.md](kinds.md)（§1 总览，§4 卡片），本文不重复。表单遵循三条规则：

1. 只显示该 kind 的必要字段，其余字段在详情中编辑（降低采集摩擦，见 [product.md §8](product.md)）。
2. 提问文案取自 kinds.md 的“采集提问”；“新建灵感”没有网页选区，需要用户填写想法与触发背景。
3. 输入不足时给出针对该 kind 的具体提示，而不是只显示“太短”（§4.6）。

### 4.5 核验来源

按顺序使用：

1. 原始上下文中的明确解释。
2. 用户手工输入或引用。
3. 用户启用后的 LLM 建议。

用户必须明确点击“确认已核对”才能进入保存；仅确认原文时无需另写摘要或备注。确认记录至少包含时间和来源，LLM 建议未被用户接受时不得自动确认。LLM 错误时展示“重试”和“手工核对”，不阻塞用户确认。修改内容、语境、来源或 kind 后清除确认并要求重做；结果来源标签始终可见。

### 4.6 应用校验

通用规则：

- 非空。
- 不能与 content 或 excerpt 完全相同。
- 必须包含动作、目标、问题或使用场景中的至少一种。

首版不使用固定字数作为统一门槛。输入不足时显示针对 kind 的具体提示，而不是只显示“太短”。

### 4.7 保存成功

成功状态持续约 700ms，显示：

```text
已保存为「概念」
[在碎片库查看] [继续阅读]
```

默认继续阅读并关闭 Modal；查看碎片库在新扩展页打开。保存后创建高亮失败不回滚 Fragment，但要展示可重试提示。

## 5. 碎片库

### 5.1 顶部

- Fragment 全文搜索，字段、匹配和排序以 [检索契约](search.md) 为准。
- “新建灵感”命令；手工输入的 Fragment 仍需填写触发背景与应用方向。
- 当前与 Desktop 的连接状态。
- “打开 Desktop”主按钮。
- 更多菜单提供唯一的“导出内容”命令（生成 Markdown + 图片 ZIP；R1 不提供旧 JSON 导入），以及高亮列表、剪藏列表两个入口。

### 5.2 筛选

首版筛选维度：

- kind
- sourceHost
- tags
- capturedAt
- review 状态（R3 双向收敛后启用）

同维度 OR，跨维度 AND；搜索再与筛选取 AND。筛选条件写入 URL，刷新后可恢复。

### 5.3 卡片信息

每张卡片只显示：

- kind 图标和 content
- 一行 excerpt
- sourceHost 和相对时间
- 复习状态（仅在 Desktop 数据回传后显示）
- tags

详情中才展示完整加工字段和修改历史。

```text
┌ 碎片库 ────────────────────────────────────────────────────────────────────────────────────────┐
│ [搜索碎片...                     ] [新建灵感]  (o) 已连接 / 2 分钟前交付  [打开 Desktop] [...] │
│ 类型 v   来源 v   标签 v   时间 v                      共 128 条    清除筛选                   │
├────────────────────────────────────────────────────────────────────────────────────────────────┤
│ [概念]  Backpressure                                                                           │
│         下游通过需求信号、暂停、缓冲或丢弃，把压力传回上游...                                  │
│         engineering.example.com / 3 天前                  #streams #reliability                │
│ [方法]  Production incident triage                                                             │
│         确认影响 -> 限制扩散 -> 保存证据 -> ...                                                │
│         sre.example.org / 昨天                                                                 │
└────────────────────────────────────────────────────────────────────────────────────────────────┘
[...] 菜单：导出内容 / 高亮列表 / 剪藏列表
```

### 5.4 允许的编辑

- 修正 kind。
- 修正上下文和来源。
- 编辑理解、核验、应用和标签。
- 定位回原文。
- 删除本地 Fragment 或导出；删除不向 Desktop 发送请求，已交付的 Desktop 副本保持原状。

扩展不提供完整复习评分。

## 6. Desktop 连接

R1 只定义扩展到 Desktop 的单向逐项交付：扩展先写本地库和待发送任务，再分别写入一条 Fragment 与它引用的图片。Desktop 未启动或接口失败时，记录和图片留在扩展并显示待发送状态；恢复连接后重试。Desktop 的复习结果不回传扩展，因此 R1 扩展不显示到期评分。Markdown ZIP 供其他工具阅读，不参与跨端交付。Desktop 到扩展的回拉与冲突处理属于 R3。

扩展删除只移除本地记录和该 ID 的待发送任务，不删除 Desktop 副本。即使 R3 回传启用，扩展的本地删除标记也要阻止该 ID 被自动带回。

**首次连接**（可随时跳过，不影响本地使用）：

1. 下载并启动 Desktop。
2. 在 Desktop 的“系统”页复制配对码。
3. 在扩展的设置中输入配对码，状态变为“已连接”，待发送项目开始逐条写入。

配对码轮换后旧客户端须重新配对，本地数据与待发送任务保留（[storage.md §8](storage.md)）。配对码保存后不再显示，设置页只提示“已保存”，并可取消配对；接口地址只接受本机回环地址，配对码不会发往本机以外。连接摩擦是否可接受见 [H-08](validation.md)。

**演进路线**（[D-05](validation.md) 已采纳）：当前保持手工输入配对码。若 H-08 未通过，升级为自动发现本机 Desktop、只需核对确认码；仍不达标才评估免配对的系统级连接，那需要重新评估安全模型。

状态：

| 状态     | 表现                     | 操作                     |
| -------- | ------------------------ | ------------------------ |
| 未配置   | 本地保存正常             | 显示配对入口             |
| 已连接   | 状态点 + 最近交付时间    | 允许立即重试待发送项目   |
| 有待发送 | 显示记录和图片的待发送数 | 后台重试                 |
| 交付错误 | 明确错误摘要             | 重试、查看详情、导出内容 |

任何连接状态都不能阻塞本地保存。

## 7. 截图

截图采用选区内原位预览与贴边工具栏，可直接添加形状、画笔、文字和马赛克，撤销标注后再确认入库或单独下载。R5.3 计划增加更精确的选区（吸附、手柄微调、比例锁定，拖拽后需确认选区才进入编辑），阶段 V 之后排期；美化与品牌面板（衬底、圆角、输出比例、文字水印与 LOGO 图章、品牌预设）和 PNG/JPEG/WebP 下载、复制到剪贴板后置，以 [H-14](validation.md) 为门槛（LOGO 与品牌预设在设置页的“截图品牌”一节管理）；真实发布动作不在扩展域内。截图默认只进入截图集；用户填写关键细节说明、语境与应用并确认核验后，才转为 `visual` Fragment。图片暂时不可用时文字仍可阅读并提示重试。区域/元素截取、匿名、编辑、美化合成和资产保存的完整契约见 [截图采集](screenshot.md)；图像遮挡复习属于 R4。

## 8. 空状态

### 首次使用

```text
选中网页中的一段内容，保存你的第一个知识碎片。
[打开示例页面]
```

首次使用路径：

1. 安装后碎片库显示上面的引导卡，并用三句话说明 Highlight、Clip、Fragment 的区别；引导卡可关闭。
2. “打开示例页面”进入一段带概念文字的页面。演示数据只存在于独立的演示模式，不混入用户的库。
3. 保存第一个 Fragment 后，出现一条不阻塞的提示：“连接 Desktop 开始复习”，附三步连接说明（见第 6 节），可以跳过。
4. 跳过连接不改变任何本地功能；之后在设置和碎片库顶部仍可连接。

激活口径见 [metrics.md §2](metrics.md)，首次理解成本的验证见 [H-05](validation.md)。

### 无搜索结果

保留当前筛选器，并提供“清除筛选”，不显示导入或营销信息。

### 无 Desktop

强调扩展仍可独立工作，并提供 Desktop 下载/启动说明；不制造数据会丢失的恐慌。

## 9. 错误与恢复

- Modal 中任一字段有改动时，关闭必须确认。
- 保存失败保留所有输入和当前步骤，窗口不关闭；除“重试”外提供三个保底出口：复制我的输入、改存为剪藏、导出内容。保存前先做配额校验，不先显示成功再失败（[storage.md §5](storage.md)）。
- 有输入后以约 300ms 防抖写入 `chrome.storage.session`，键包含 tab ID、来源 URL 和一次选区的 draft ID；该表单状态不进入 Fragment 库、复习或待发送队列。
- Service Worker 重启或同一浏览器会话中的页面导航后，重新打开同一来源时提示恢复未提交表单；成功保存或明确放弃后清理。浏览器完整退出会清除 session 草稿，界面不得承诺跨浏览器重启恢复。
- 页面卸载不依赖最后一刻的异步写入；无法拦截的导航以已完成的防抖自动保存为准，不自动提交 Fragment。多标签页草稿互不覆盖。
- 图片或 Markdown ZIP 生成失败时显示原因和未导出项，不把不完整 ZIP 标记为成功。

## 10. 快捷键

| 快捷键                         | 功能                               |
| ------------------------------ | ---------------------------------- |
| `Alt+H` / `Cmd+Shift+H`        | 连续高亮模式                       |
| `Ctrl+Shift+S` / `Cmd+Shift+S` | 截图模式                           |
| `Esc`                          | 关闭菜单、取消截图或请求关闭 Modal |
| `Cmd/Ctrl+Enter`               | 当前步骤通过校验后继续或保存       |

### 10.1 可访问性

- 采集窗口、截图工具栏和碎片库的主流程都能只用键盘完成。
- 窗口打开时焦点进入窗口并被限制在其中，关闭后回到触发位置。
- 颜色不是状态的唯一表达，如连接状态、核验是否已确认。
- 屏幕阅读器能读出 kind、当前步骤和来源。

## 11. 验收标准

1. 在普通文章、信息流和 SPA 页面均可创建带上下文和永久链接的 Fragment。
2. 用户可在 Highlight、Clip 和 Fragment 之间做明确选择。
3. 七种文本 kind（含 `inspiration`）和基础 `visual` 都有专属提示和校验，不出现旧场景文案。
4. 关闭 LLM 后可以完成整个采集流程。
5. 模型、保存或 Desktop 交付失败不丢失输入与已提交数据。
6. 扩展断开 Desktop 时仍能查询、编辑、导出和继续采集；连接恢复后可逐项写入 Desktop。
7. ZIP 在没有 Desktop 时可生成，包含已提交的 Fragment、Highlight、Clip、截图说明与已保存原图；Markdown 图片链接均有效。
8. Fragment 保存后的 95 分位本地写入时间小于 300ms，不含可选模型请求。
9. 从选区出现到 Modal 首屏可交互小于 150ms。
10. 放弃采集窗口时出现确认，并提供“改存为高亮 / 剪藏”的安全出口，不丢失已输入的内容。
11. [examples.md §5](examples.md) 的场景 A、B 通过。
12. 浏览器界面为英文时，扩展的每个界面都显示英文，不出现中文；为中文时不出现英文的 “Fragment”（数据实体名与 `media-clip` 这类契约名除外）。
