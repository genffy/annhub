# 用户故事与验收

> 层级：product
> 状态：持续维护
> 更新：2026-10-07

本文把产品定位转换为可设计、可开发、可测试和可度量的用户故事。页面细节见 [扩展 PRD](extension.md)，核心用户见 [product.md §2.1](product.md)；每条故事对应的版本、路线图条目、指标和假设集中在第 5 节。

## 1. 维护规则

- 每条故事有稳定 ID，不因排序变化而修改；被移除的编号（US-CAP-03 到 09、US-DATA-06）不复用（[D-18](validation.md)）。
- 故事只描述用户价值与最小验收，不写实现方案，**不记录进度**：交付状态归 [roadmap.md](roadmap.md)，验证状态归 [validation.md](validation.md) 的假设。
- 自动化测试通过只说明“做出来了”，不说明用户需要它：验收分工程验收（本文的清单）与真实用户验证（相关假设通过）两层。

## 2. Epic A：采集

### US-CAP-01：选择保存方式

> 作为正在浏览资料的知识工作者，当我选中一段内容时，我希望一眼分清“留下文字（剪藏）”“在页面留痕（高亮）”“保存画面（截图）”，并一步完成，不被表单拖住。

- 选区菜单展示三项动作：剪藏、高亮、截图，顺序固定，文案不混用。
- 悬停或键盘聚焦约 300ms 后出现一句后果。
- 剪藏与高亮一步完成，不打开窗口。
- 三种采集保存为同一种条目，只有 `type` 不同；保存之后不能转换类型。

### US-CAP-02：保存来源与语境

> 作为工程师，当我从网页保存内容时，我希望系统同时记录选区、所在语境、页面标题、永久链接和定位信息，以便离开原网页后仍能理解和回溯。

- `context` 包含归一化后的 `content`；选区本身过长时不保存 `context`。
- 信息流页面优先保存内容项永久链接；定位符生成失败不阻塞保存。
- 页面 meta 里的作者、发布日期和描述取得到就写入对应属性，取不到不设置。

### US-CAP-11：剪藏

> 作为正在读资料的用户，当我读到值得留下的一段话，我希望一次点击把它连同来源与语境存下来，之后能查到，误点时能立刻撤销。

- 一次点击保存，不打开窗口；约 3 秒内可撤销，撤销删除刚保存的条目。
- 提示里的“编辑”可在原处改标题、标签和备注。
- 保存失败显示原因与“重试”，不显示成功；本地写入的 95 分位小于 300ms。

### US-CAP-12：高亮

> 作为需要在原页面留下标记的用户，我希望回访页面时高亮恢复，能加备注，连续高亮多段时不用反复点菜单。

- 高亮保存为 `highlight` 条目，颜色保存为 `color` 属性。
- 回访同一页面时标记恢复，包含 SPA 的延迟内容；信息流页面按 `pageUrl` 与 `sourceUrl` 都能命中。
- 可添加备注；`Alt+H` / `Cmd+Shift+H` 进入连续高亮，每次选中创建一条，`Esc` 退出；删除高亮后页面文本结构恢复。

### US-CAP-13：截图

> 作为需要记住图表或界面细节的用户，当我截取网页内容时，我希望直接在原位标注、遮住身份信息，再存进资料库。

- 区域拖拽与元素单击都能截图；匿名默认开启，预览里可增删马赛克。
- 确认入库后保存为 `screenshot` 条目，出现在“截图”视图；图片字节单独保存，条目只引用 `assetId`。
- 单独下载失败不回滚已入库的结果；入库失败不显示成功，并保留预览与标注。
- 页面脚本伪造的事件不能启动或推进截图会话。

### US-CAP-10：精确选取截图区域

> 作为需要截取网页中某个具体图表或界面细节的用户，当我拖拽框选区域时，我希望选区自动贴合页面元素的边缘，并能在确认前精细调整，从而不必反复重选，也不会多截或少截一圈。

- 吸附、八向手柄与方向键微调、比例锁定、选区确认的行为以 [screenshot.md §1.2](screenshot.md) 为准。
- 在普通页面和 SPA 页面均可用，并与单击元素截图共存、互不冲突。

指标：确认前重新框选的比例、手柄调边与方向键微调的使用率。

## 3. Epic B：属性与资料库

### US-PROP-01：查看与编辑条目属性

> 作为需要整理资料的用户，我希望给条目加标签和自己的属性（如项目、是否读过），并用它们筛选和导出。

- 详情抽屉的属性面板显示内置与自定义属性，每行是类型图标、名称和值编辑器。
- 添加属性时从注册表补全；注册表里没有的名称要先选类型，创建后进入注册表。
- 值按类型校验；条目内名称唯一，同名同类型；保留名与超限值被拒绝并说明原因。
- 清空值等于未设置；保存失败保留已输入的内容。

### US-PROP-02：管理属性定义

> 作为长期使用者，我希望看到有哪些属性、各被多少条目使用，并为每种采集类型选好自动附加的属性。

- 属性页列出名称、类型、默认值、使用数和三列预设；`tags` 固定存在，不可删除、不可改类型。
- 使用数大于 0 的属性不可删除、不可改类型；“删除未使用”一次清理使用数为 0 的自定义属性。
- 新建剪藏、高亮、截图时，按预设附加属性并带上默认值。

### US-LIB-01：检索与筛选

> 作为要写方案的用户，我希望在一个库里搜索，并按类型、来源、标签、时间和属性筛选，快速找回条目并回到来源。

- 搜索覆盖原文、语境、备注、来源和文本与列表属性；筛选维度含类型、来源、标签、时间和属性（运算符按属性类型）。
- 同维度 OR、跨维度 AND；条件写入 URL，刷新后恢复。
- “回到来源”打开来源页并尽力定位；无结果时保留筛选并提供“清除筛选”。

### US-LIB-02：所有页面同一套壳

> 作为用户，我希望扩展的每个页面都是左边导航、右边内容，切换视图时位置不变，不必重新找入口。

- 资料库的全部、剪藏、高亮、截图、属性、设置视图和工具栏弹窗都使用左导航 + 右内容；没有顶部导航。
- 窗口变窄时导航折叠为左侧图标栏，仍可键盘操作。
- 当前视图用 `aria-current` 标出且不只靠颜色；导航项的顺序与文案在所有页面一致。

## 4. Epic C：本地优先与数据控制

### US-DATA-01：离线工作

> 作为重视隐私的用户，我希望断网时仍能采集、查询和导出，不需要上传整库内容才能使用核心功能。

- 断网时仍能采集、查询、编辑和导出。

### US-DATA-03：可独立阅读

> 作为长期用户，我希望能把扩展内容和已保存图片一次导出为可独立阅读的文件，从而避免被工具锁定。

- 一个 ZIP 包含全部条目的 Markdown（属性写成 frontmatter）和处理后的图片原字节；图片相对链接有效，缺失图片有明确报告。
- 不提供第二种 JSON / CSV 用户导出，也不宣称该 ZIP 可恢复扩展的数据库。

### US-DATA-05：图片资产可引用且不丢失

> 作为截取网页图表的用户，我希望截图在扩展内可查看，并能在导出的 ZIP 中找到同一张图片。

- 图片元数据、字节与 `screenshot` 条目一致提交；删除条目时图片同事务删除。
- 图片暂时缺失时，条目的标题、备注与属性仍可阅读；ZIP 只写一份原图。
