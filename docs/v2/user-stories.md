# 用户故事与验收

> 层级：product
> 状态：持续维护
> 更新：2026-10-10

本文把产品定位转换为可设计、可开发、可测试和可度量的用户故事。页面细节见 [扩展 PRD](extension.md)，核心用户见 [product.md §2.1](product.md)；每条故事对应的版本、路线图条目、指标和假设集中在第 5 节。

## 1. 维护规则

- 每条故事有稳定 ID，不因排序变化而修改，编号不复用。
- 故事只描述用户价值与最小验收，不写实现方案，**不记录进度**：交付状态归 [roadmap.md](roadmap.md)，验证状态归 [validation.md](validation.md) 的假设。
- 自动化测试通过只说明“做出来了”，不说明用户需要它：验收分工程验收（本文的清单）与真实用户验证（相关假设通过）两层。

## 2. Epic A：采集

### US-CAP-01：选择保存方式

> 作为正在浏览资料的知识工作者，当我选中一段内容时，我希望一眼分清“留下文字（剪藏）”和“保存画面（截图）”，并一步完成，不被表单拖住。

- 选区菜单展示两项动作：剪藏、截图，顺序固定，文案不混用；菜单里没有高亮。
- 悬停或键盘聚焦约 300ms 后出现一句后果。
- 剪藏一步完成，不打开窗口。
- 两种采集保存为同一种条目，只有 `type` 不同；保存之后不能转换类型。
- 输入框、`textarea` 与可编辑区（`contenteditable`）里选中文字时不出现选区菜单，也不拦截任何按键；菜单出现但还没有聚焦任何动作时，`Enter` 不触发保存。

### US-CAP-02：保存来源与语境

> 作为工程师，当我从网页保存内容时，我希望系统同时记录内容、所在语境、页面标题和永久链接，以便离开原网页后仍能理解和回溯。

- 选区剪藏的 `context` 包含选区的纯文本；选区本身过长时不保存 `context`。
- 信息流页面优先保存内容项永久链接；解析失败时使用当前页面地址。
- 页面 meta 里的作者、发布日期和描述取得到就写入对应属性，取不到不设置；过长或不合规时丢弃该项（标题与描述这类自由文本按上限截断），剪藏照常保存。
- 语境是选区所在的完整句或段：三击选中整段、选区落在链接、加粗或代码这类行内元素里，语境仍是所在的句或段，不是整个容器，也不是选区自己。

### US-CAP-11：剪藏

> 作为正在读资料的用户，当我读到值得留下的一段话，我希望一次点击把它连同来源与语境存下来，之后能查到、能读，误点时能立刻撤销。

- 选中文字后一次点击保存，不打开窗口；约 3 秒内可撤销，撤销删除刚保存的条目。
- 内容以 Markdown 保存，保留链接、标题层级与列表；页面上不出现任何标记。
- 提示里的“编辑”可在原处改标题、标签和备注；它只改用户改动过的字段，采集时自动写入的属性保持不变；写入失败时气泡保留已输入的内容，给出原因与重试。
- 保存失败显示原因与“重试”，不显示成功；本地写入的 95 分位小于 300ms。
- 服务进程空闲一段时间后的第一次保存，与连续保存一样快；保存之后服务进程被回收，提示里的撤销与编辑照常生效。

### US-CAP-14：区块剪藏

> 作为刷到一条推文、读到一篇好文章或一段示例代码的用户，我希望指一下就能把整块内容留下，不用先把它整个拖选出来。

- 没有选区时，指针在一个区块上停下约 400ms，区块出现描边和胶囊「剪藏 | 截图 | 上一级 | 更多」；点一次“剪藏”保存整块，不需要选中。区块有七种：帖子、代码块、表格、图、引用、一节、文章（[capture.md §6.2](capture.md)）。
- 先取指针下最内层的区块，“上一级”（或 `↑`）选外一层，`↓` 回到里面一层；段落本身不是区块，指在正文上选中的是它所在的一节或整篇文章。
- 胶囊不盖住页面自己的按钮、链接和菜单；区块比窗口高时胶囊始终在窗口里可见。
- 有选区、正在拖选或滚动、焦点在输入框里时不出现；入口只是浮层，不改网页内容，也不在页面上留下记号。
- 键盘用户用区块模式（`Ctrl/Cmd+Shift+E`）：`Tab` 在同层区块间移动，`↑` `↓` 换层级，`Enter` 剪藏，`S` 截图，`Esc` 退出；不需要先移动鼠标，打开后就有一个目标区块（起点与顺序见 D-27）。
- 标题与段落同级的文档页、只有 `div` 的博客页、带多个类名的正文容器上，同样识别出一节与文章；识别过程不在宿主页面里报错。
- 保存的内容与提示、撤销、编辑同选区剪藏；X 的帖子保存作者、时间、正文、图片的替代文字与被引用的帖子；`sourceUrl` 取该区块自己的永久链接。
- 默认开启，设置里可整体关闭，也可以在胶囊的“更多”里按网站停用。

### US-CAP-13：截图

> 作为需要记住图表或界面细节的用户，当我截取网页内容时，我希望直接在原位标注、遮住身份信息，再存进资料库。

- 区域拖拽与元素单击都能截图，区块胶囊里的“截图”直接以该区块为目标；匿名默认开启，预览里可增删马赛克。
- 拖拽前可选比例预设（1:1、4:5、3:4、16:9 等，哪些出现由设置决定），选中后拖拽始终输出该比例（R2）。
- 确认入库后保存为 `screenshot` 条目，出现在“截图”视图；图片字节单独保存，条目只引用 `assetId`。
- 单独下载失败不回滚已入库的结果；入库失败不显示成功，并保留预览与标注。
- 页面脚本伪造的事件不能启动或推进截图会话。
- 单击元素选取目标时，这次点击不触发页面自己的动作：链接不跳转，按钮不响应。

### US-CAP-15：截图输出

> 作为要把截图放进文档、聊天或社交平台的用户，我希望一键复制，或按我设好的格式、署名和样式下载，而不是每次都先存文件再找文件，再到别的工具里加背景。

- 工具栏的“复制”把当前结果以 PNG 写进剪贴板（`Ctrl/Cmd+C` 等价），可直接粘贴；`http:` 页面上提示“请下载”，下载照常可用（R1）。
- 设置里选下载格式（PNG、JPEG、WebP，JPEG 与 WebP 可调质量）和品牌水印（文字、图片、位置、大小、透明度）（R2）。
- 工具栏上的美化面板给复制与下载的图片加背景、内边距、圆角、阴影，并可按比例预设输出画布；面板里的改动即时预览、可复原；默认是否开启与初始样式在设置里（R2）。
- 水印与美化只加在复制与下载的图片上，入库的图片保持原样；`W` 关掉本次的水印。
- 复制、下载失败时保留图片与全部标注，给出原因和重试；单独的复制或下载失败不影响已经成功的入库。

指标：近 14 天内截过图的用户里，复制或下载过截图的占比（M-22），其中带美化输出过的占比（M-24）。

### US-CAP-10：精确选取截图区域

> 作为需要截取网页中某个具体图表或界面细节的用户，当我拖拽框选区域时，我希望选区自动贴合页面元素的边缘，并能在确认前精细调整，从而不必反复重选，也不会多截或少截一圈。

- 吸附、八向手柄与方向键微调、`Shift` 锁定比例、选区确认、元素层级选择（`↑` `↓`）的行为以 [screenshot.md §1.2](screenshot.md) 为准。
- 在普通页面和 SPA 页面均可用，并与单击元素截图共存、互不冲突。

指标：确认前重新框选的比例、手柄调边与方向键微调的使用率。

### US-CAP-16：重拍同一块区域，产物完全一致

> 作为要把同一个界面在不同状态下截成一组图的用户（切换套餐周期、主题、语言），我希望每张图的取景一模一样——同样的尺寸，同样的边距——而不是每次靠手去对。

- 选中一个元素后可以加固定边距（0、8、16、24、32 CSS 像素或自定义）：取景框 = 元素外框向四周外扩这个边距；`↑` `↓` 在元素层级间移动，直接选到包含切换条与全部卡片的容器。
- 同一标签页、同一网页里，下次截图时上次的取景框直接作为待确认的选区出现，`Enter` 确认；取景框记的是元素：滚动、改窗口大小、内容刷新之后仍框住同一块内容。
- 同一个取景框输出的像素尺寸完全相同，边距环里的像素一致；元素找不到时沿用上次的位置与尺寸并提示；取景框比窗口大时提示。
- 验收用带切换条的夹具页：三种状态各截一张，尺寸相同、边距环无差异（[roadmap.md R3](roadmap.md)）。

指标：同一网页里第二张及以后的截图中沿用上次取景框的占比（M-25）。

## 3. Epic B：阅读、属性与资料库

### US-LIB-03：阅读与高亮

> 作为把资料剪下来之后要读懂它的用户，我希望在资料库里打开一条剪藏，选中原文划出重点、写下自己的想法，不必回到原网页。

- 在阅读视图或详情抽屉的原文里选中文字，出现颜色点和“备注”；点颜色立即创建一条高亮，键盘上选中后按 `H` 以默认颜色创建。
- 高亮可改颜色、写备注、删除；删除后约 3 秒内可撤销；刷新后仍在；与已有高亮重叠的新选区合并为一条。
- “高亮”视图以高亮为单位按剪藏分组列出，点一行在阅读视图里定位；搜索覆盖引文与备注。
- 有高亮的剪藏原文只读并说明原因；删除剪藏前提示将一并删除的高亮数。
- 高亮只存在于 AnnHub 里：网页上没有标记，“回到来源”只打开原页面；导出时写成 `==…==`。
- “返回”或 `Esc` 回到之前的列表与位置；阅读视图的地址写进 URL，刷新后仍在阅读视图里。
- 表格里、三击选中的整段、跨加粗、链接或代码的选区，以及页面文字里被转义的字符（`*`、`==`、反斜杠）之后的选区，都能创建高亮，位置正确；引文是渲染后的纯文字，不带 Markdown 记号，跨段的引文在段与段之间有空格。
- 阅读视图按原意渲染：段内换行显示为空格，`<br>` 硬换行显示为换行，含括号的链接目的地完整。
- 输入中的备注在关闭浮层、抽屉或阅读视图时不丢；备注输入中点击删除或颜色，这次点击照常生效。

### US-PROP-01：查看与编辑条目属性

> 作为需要整理资料的用户，我希望给条目加标签和自己的属性（如项目、是否读过），并用它们筛选和导出。

- 详情抽屉的属性面板显示内置与自定义属性，每行是类型图标、名称和值编辑器。
- 添加属性时从注册表补全；注册表里没有的名称要先选类型，创建后进入注册表。
- 值按类型校验；条目内名称唯一，同名同类型；保留名与超限值被拒绝并说明原因。
- 清空值等于未设置；保存失败保留已输入的内容。
- 六种类型的属性都能添加（含日期、日期时间），添加时不写入空值；值在失焦或确认时保存，不在每次按键时保存；清空备注与属性值会真正清除；标题不可清空。
- 列表类型的项数与单项长度按列表类型自己的上限，标签更紧的上限只适用于 `tags`。
- 输入中的值（含列表里已键入、还没按回车的文字）在关闭抽屉或阅读视图、返回、提交失败时都不丢；超限的项给出提示，不悄悄丢弃；复选框这类没有输入框的属性行不会让抽屉无法关闭。
- 在阅读视图的右栏改属性，面板与标题栏立即显示最新值，连续两次编辑不会覆盖前一次；点属性名只聚焦输入，不改动它的值。

### US-PROP-02：管理属性定义

> 作为长期使用者，我希望看到有哪些属性、各被多少条目使用，并为每种采集类型选好自动附加的属性。

- 属性页列出名称、类型、默认值、使用数和两列预设（剪藏、截图）；`tags` 固定存在，不可删除、不可改类型。
- 使用数大于 0 的属性不可删除、不可改类型；“删除未使用”一次清理使用数为 0 的自定义属性。
- 使用数按整个库计算，不受列表分页影响。
- 新建剪藏、截图时，按预设附加属性并带上默认值；内置属性（`title`、`tags` 固定附加除外）的预设也可勾选。

### US-LIB-01：检索与筛选

> 作为要写方案的用户，我希望在一个库里搜索，并按类型、来源、标签、时间和属性筛选，快速找回条目并回到来源。

- 搜索覆盖正文、语境、备注、高亮的引文与备注、来源和文本与列表属性；筛选维度含类型、来源、标签、时间和属性（运算符按属性类型）。
- 同维度 OR、跨维度 AND；条件写入 URL，刷新后恢复。
- “回到来源”打开来源页；无结果时保留筛选并提供“清除筛选”。
- 条目多于一页时可以浏览到最后一条（形式见 D-28）；来源与标签的候选来自整个库，而不是当前页。
- “高亮”视图同样支持搜索与筛选（颜色、来源、标签、时间、属性），条件写入 URL，刷新后恢复；时间按高亮自己的创建时间。
- 删除或编辑条目后，列表、总数和导航上的数字立即反映；关闭抽屉或阅读视图后，列表保持已加载的页数和位置。
- 库很大时（以 1 万条、含长正文为界）资料库照常载入：导航计数、来源与标签候选齐全，首次引导只在库为空时出现。
- 键入搜索词时界面不卡顿：结果随输入更新，但不为每个按键各做一次完整查询。
- 正文里带下划线、星号等字符的标识符（如 `user_id`、`MAX_RETRIES`、`2*3`）能被搜到。

### US-LIB-02：所有页面同一套壳

> 作为用户，我希望扩展的每个页面都是左边导航、右边内容，切换视图时位置不变，不必重新找入口。

- 资料库的全部、剪藏、高亮、截图、属性、设置视图、阅读视图和工具栏弹窗都使用左导航 + 右内容；没有顶部导航。
- 窗口变窄时导航折叠为左侧图标栏，仍可键盘操作；图标栏里每个入口都能分辨（图标加可读名称），不隐藏导出结果等状态信息，阅读视图的右栏移到正文下方而不是消失。
- 当前视图用 `aria-current` 标出且不只靠颜色；导航项的顺序与文案在所有页面一致。

## 4. Epic C：本地优先与数据控制

### US-DATA-01：离线工作

> 作为重视隐私的用户，我希望断网时仍能采集、阅读、查询和导出，不需要上传整库内容才能使用核心功能。

- 断网时仍能采集、阅读与高亮、查询、编辑和导出。

### US-DATA-03：可独立阅读

> 作为长期用户，我希望能把扩展内容和已保存图片一次导出为可独立阅读的文件，从而避免被工具锁定。

- 一个 ZIP 包含全部条目的 Markdown（属性写成 frontmatter，高亮写成 `==…==`）和处理后的图片原字节；截图的图片相对链接有效，缺失图片有明确报告。
- 不提供第二种 JSON / CSV 用户导出，也不宣称该 ZIP 可恢复扩展的数据库。
- frontmatter 对任何属性名与值（含冒号、井号、引号、以冒号结尾的列表项、看起来像日期或数字的字符串）都能被 YAML 解析器还原，不丢失、不改变类型。
- 高亮写成 `==…==` 时不改动代码块里的代码，也不跨越加粗、链接这类行内语法。

### US-DATA-05：图片资产可引用且不丢失

> 作为截取网页图表的用户，我希望截图在扩展内可查看，并能在导出的 ZIP 中找到同一张图片。

- 图片元数据、字节与 `screenshot` 条目一致提交；删除条目时图片同事务删除。
- 图片暂时缺失时，条目的标题、备注与属性仍可阅读；ZIP 只写一份原图。
