# 用户故事与验收

> 层级：product
> 状态：持续维护
> 更新：2026-10-07

本文把产品定位转换为可设计、可开发、可测试和可度量的用户故事。页面细节见 [扩展 PRD](extension.md)。

## 1. 维护规则

每条故事包含：

- 稳定 ID，不因排序变化而修改。
- 目标用户和触发场景。
- 用户价值，而非实现方案。
- 对应产品版本与[路线图](roadmap.md)条目。
- 最小验收标准。
- 可观察指标（编号见 [metrics.md §5](metrics.md)）。

**故事只描述需求与验收，不记录进度。** 进度分两个维度，各有唯一归属：

| 维度     | 回答                   | 归属                                                            |
| -------- | ---------------------- | --------------------------------------------------------------- |
| 交付状态 | 这个范围做完了吗       | [roadmap.md](roadmap.md) 按版本维护                             |
| 验证状态 | 真实用户用了吗、有效吗 | [validation.md](validation.md) 按假设维护，每条故事列出相关假设 |

自动化测试通过只说明“做出来了”，不说明用户需要它。故事的验收分两层：工程验收（本文的验收清单）与真实用户验证（相关假设通过）。

## 2. 核心用户

### P1：高级工程师 / 架构师

- 高频阅读技术文档、RFC、源码说明和事故复盘。
- 输出设计文档、ADR、技术方案和故障分析。
- 对来源、隐私、本地存储和长期可访问性敏感。
- 是首批设计和验证的重点用户。

### P2：产品经理 / 设计师

- 高频阅读行业文章、竞品、用户研究和设计案例。
- 输出 PRD、方案比较、决策记录和设计说明。
- 是第二阶段目标用户。

### P3：研究者 / 分析师

- 高频处理论文、报告、观点和证据。
- 输出研究文章、观点论证和结论汇报。
- 需要更强来源与引用能力后再重点拓展。

## 3. Epic A：采集分流

### US-CAP-01：决定保存层级

**版本**：R1  
**路线图**：R1.2 · **假设**：H-01、H-05

> 作为正在浏览资料的知识工作者，当我选中一段内容时，我希望明确选择“保留页面位置”“以后查阅”还是“准备学习和使用”，从而避免所有内容都进入同一个收藏箱。

分流：

```text
保留页面位置和备注 -> Highlight
保存内容供搜索查阅 -> Clip
准备理解并实际使用 -> Fragment
```

验收：

- HoverMenu 展示四项动作：碎片、高亮、剪藏、截图；页面存在可捕获的媒体时，R4 起追加“媒体片段”。文案不混用。
- 悬停或键盘聚焦约 300ms 后出现一句后果（这个动作做什么、要多久）。
- Highlight/Clip 不创建 Fragment；剪藏保存后约 3 秒内可撤销。
- 未完成 Fragment 加工时可改存 Highlight 或 Clip；保存失败时可复制已填内容或改存为剪藏。
- 不自动把 Highlight/Clip 升级为 Fragment。
- 保存 Fragment 前用户明确确认已核对当前内容；不强制填写核验摘要或备注。

指标：Fragment Modal 打开率、完成率、退出后选择 Highlight/Clip 的比例。

### US-CAP-02：保存来源与语境

**版本**：R1  
**路线图**：R1.2

> 作为工程师，当我从网页保存知识时，我希望系统同时记录选区、所在语境、页面标题、永久链接和定位信息，以便离开原网页后仍能理解和回溯。

验收：

- excerpt 包含归一化后的 content。
- 信息流页面优先保存内容项永久链接。
- locator 失败不阻塞保存。
- 用户可以在保存前修正 excerpt 和 sourceUrl。

指标：上下文修正率、sourceUrl 回退率、回到原文成功率。

### US-CAP-03：采集概念

**版本**：R1  
**路线图**：R1.2 · **假设**：H-06

> 作为工程师，当我遇到新概念时，我希望用自己的话解释它、核对定义和边界，并写下它能解释的实际问题。

示例：

```text
content: Backpressure
understanding: 下游通过需求信号、暂停、缓冲或丢弃，把压力传回上游
verified: 不只是固定速率限流，还涉及队列边界和反馈机制
application: 检查当前事件管道为什么在消费者变慢后耗尽内存
```

验收：

- kind 为 `concept`。
- application 不等于 content 或 excerpt。
- 关闭 LLM 后可以手工完成核验。

### US-CAP-04：处理有争议的论点

**版本**：R1  
**路线图**：R1.2

> 作为产品负责人，当我看到一个有争议的观点时，我希望记录自己的立场、原文证据、隐含前提和反例，以便之后不会把作者观点误当作事实。

验收：

- kind 为 `claim`。
- stance 支持 support/oppose/uncertain。
- evidence 和 assumptions 可以分别编辑。
- claim 可以独立保存。

### US-CAP-05：把方法转成执行流程

**版本**：R1  
**路线图**：R1.2

> 作为值班工程师，当我读到一套方法时，我希望重建步骤、适用条件和失败模式，并说明准备在哪个任务中执行。

验收：

- procedure 至少一个 step。
- 支持 prerequisites 和 failureModes。

### US-CAP-06：保留问题和不确定性

**版本**：R1  
**路线图**：R1.2

> 作为研究者，当我尚未得出结论时，我希望保存当前假设、已有证据和下一步验证动作，而不是被迫把内容写成已经成立的知识。

验收：

- open/testing question 必须有 hypothesis 或 nextStep。
- answered question 必须有 answer。
- question 可以独立保存。

### US-CAP-07：从网页截图创建视觉碎片

**版本**：R1  
**路线图**：R1.2

> 作为需要记住图表或界面细节的用户，当我截取网页内容时，我希望写下关键细节、语境和应用方式，并在碎片库里回看图片。

验收：

- 截图默认留在截图集，不自动成为 Fragment。
- 转为 `visual` 前需要文字描述、网页来源、语境和应用。
- Fragment 和图片通过稳定附件 ID 关联。
- 扩展保存处理后图片的 `Blob`，截图集与 Fragment 不重复存图。
- 图片暂时不可用时，已保存的文字内容仍可查看。

### US-CAP-08：记录原创灵感与短随感

**版本**：R1  
**路线图**：R1.2

> 作为知识工作者，当我在阅读或工作中突然形成一个想法时，我希望不依赖网页选区也能记下它的缘起，并在之后的写作中重新发展，而不是把它伪装成引述。

验收：

- 从碎片库“新建灵感”可手工创建 `inspiration`，选择 `idea` 或 `reflection`。
- `content` 为一条不超过 500 字符的原创想法；触发背景非空，和 content 一起形成可独立理解的 `excerpt`。
- 无网页来源时使用 `annhub://manual/<id>`；由网页触发时保留实际页面来源，但不把用户原创文字标为网页原文。
- 应用字段可写准备如何继续思考或写作，不要求立即执行；长篇随笔不属于 AnnHub。

### US-CAP-09：把截图加工成可直接使用的成品图

**版本**：R5（后置）  
**路线图**：R5.1、R5.2 · **假设**：H-14

> 作为维护个人品牌的内容创作者，当我为小红书或 X 准备配图时，我希望在截图编辑器内加上衬底和我的账号水印，并按平台常用尺寸直接下载或复制，而不必再切换到第三方截图与图片编辑工具。

说明：目标用户是为社交平台制作配图的内容创作者，不在三类核心用户之内；这条故事后置，以 [H-14](validation.md) 为入口门槛（[D-02](validation.md) 已采纳）。精确选区另见 US-CAP-10。

验收：

- 衬底背景、内边距、圆角、输出比例与水印可即时预览，品牌预设可一键套用。
- 非原始比例时内容等比完整置入，不裁切内容。
- 支持下载 PNG/JPEG/WebP 与复制 PNG 到剪贴板；截图集入库统一 PNG。
- 水印与 LOGO 素材仅存扩展本地，不进入 Fragment 记录、不外发。
- 设置页的“截图品牌”一节管理 LOGO（上传、更换、移除）与品牌预设（重命名、删除）；编辑器里的“品牌”面板只套用与保存预设。
- 平台尺寸预设在美化面板的“输出”区选择，位于输出比例之下，只约束输出尺寸。
- 扩展不提供任何平台上传、发布或账号授权能力。

指标：美化面板使用率、品牌预设保存数、截图会话中下载/复制与入库的比例。

### US-CAP-10：精确选取截图区域

**版本**：R5  
**路线图**：R5.3

> 作为需要截取网页中某个具体图表或界面细节的用户，当我拖拽框选区域时，我希望选区自动贴合页面元素的边缘，并能在确认前精细调整，从而不必反复重选，也不会多截或少截一圈。

验收：

- 拖拽时光标下的元素边缘实时吸附并高亮提示，起止点可吸附到元素矩形。
- 确认前选区显示八向手柄，可拖拽二次调边；方向键微调 1 像素，配合 `Shift` 每次 10 像素。
- 拖拽中按住 `Shift` 临时锁定比例，也可锁定到 1:1、3:4、4:5、16:9 预设比例；锁定后拖拽始终输出目标比例。
- 拖拽松开后选区保持可调，旁边出现“确认选区 / 取消”；`Enter` 或点击确认后才进入原位编辑，`Esc` 取消；单击元素仍直接进入编辑。
- 在普通页面和 SPA 页面均可用，并与单击元素截图共存、互不冲突。

指标：确认前重新框选的比例、手柄调边与方向键微调的使用率。

## 4. Epic B：本地优先与数据控制

### US-DATA-01：离线工作

**版本**：R1  
**路线图**：R1.1–R1.2

> 作为重视隐私的用户，我希望断网时仍能采集、查询和导出，不需要上传整库内容才能使用核心功能。

验收：

- 断网时仍能采集、查询、编辑和导出。
- LLM 关闭不阻塞主流程。

### US-DATA-03：可独立阅读

**版本**：R1  
**路线图**：R1.2

> 作为长期用户，我希望能把扩展内容和已保存图片一次导出为可独立阅读的文件，从而避免被工具锁定。

验收：

- 一个 ZIP 包含 Fragment、Highlight、Clip、截图说明的 Markdown 和处理后的图片原字节。
- Markdown 的图片相对链接有效，缺失图片有明确报告。
- 不提供第二种 JSON / CSV 用户导出，也不宣称该 ZIP 可恢复扩展的数据库。

### US-DATA-05：图片资产可引用且不丢失

**版本**：R1  
**路线图**：R1.1–R1.2

> 作为截取网页图表的用户，我希望截图在扩展内可查看，转为 `visual` 后在碎片库可回看，并能在导出的 ZIP 中找到同一张图片。

验收：

- 截图元数据与处理后的原图字节在扩展 IndexedDB 中一致提交。
- 同一 `assetId` 被截图集和 `visual` Fragment 引用，转化时不复制图片。
- 图片暂时缺失时文字 Fragment 仍可读。
- ZIP 只写一份原图，所有相关 Markdown 指向它。

### US-DATA-06：使用只在本机运行的模型

**版本**：V 之后  
**路线图**：条件性范围（[D-06](validation.md)） · **假设**：H-11、H-13

> 作为重视隐私的用户，当我想获得核验建议时，我希望可以选择只在本机运行的模型，而不必申请和保管云端密钥，也不把内容发往第三方。

验收：

- 设置中可为核验建议开启设备端模型，默认关闭；开启它不会开启其他外发能力。
- 设备端模型不可用时（系统版本、硬件、功能未启用或模型未下载），界面说明原因并回到手工或本地路径，不阻塞主流程。
- 设备端建议与云端建议一样带来源标签，只是建议，用户确认后才生效。
- 使用设备端模型时内容不离开本机；日志只记录调用阶段、错误码与耗时，不记录正文。
- H-13 通过之前，界面不把设备端选项标为“推荐”。

指标：M-17，按云端与设备端分别统计。
