# macOS Desktop PRD

> 层级：product
> 状态：目标体验真源
> 更新：2026-10-04

本文定义 macOS Desktop 的页面结构、核心工作流和验收标准。Desktop 是学习消费端和本地数据中枢，不是通用 Markdown 编辑器。

## 1. 产品职责

Desktop 负责：

- 查看和整理 Fragment。
- 完成每日提取复习。
- 通过本地服务接口逐项接收扩展写入；R3 再提供内部备份与双向收敛。

Desktop 不负责网页正文阅读、网页内高亮或团队协作。

## 2. 一级导航

侧边栏提供三项：

```text
今日
碎片库
系统
```

默认页为“今日”。首次安装且没有数据时默认进入“碎片库”空状态：

```text
碎片库
        还没有碎片。
        1. 在 Chrome 中安装 AnnHub 扩展，保存第一个碎片
        2. 在“系统”页复制配对码，输入到扩展
        扩展里的碎片会在这里逐条出现；没有 Desktop 时扩展也能独立使用。
                                       [打开系统页]  [复制配对码]
        (o) 正在监听 127.0.0.1 · 等待第一条碎片
```

主按钮是“打开系统页”；“复制配对码”把配对码直接复制到剪贴板，缩短安装漏斗里最容易断掉的一步（[H-08](validation.md)）。底部一行说明本地服务正在监听，让用户知道 Desktop 已经在等第一条碎片。

## 3. 今日

今日页是行动清单，不是统计仪表盘。

### 3.1 页面结构

```text
顶部：今天需要完成什么
区块 A：到期复习
区块 B：最近由扩展写入的碎片
```

排序原则：可执行事项优先，统计信息放在底部次要区域。

```text
今日
┌─────────────────────────────────────────────────────────────────────┐
│ 今天需要完成什么                                                    │
│                                                                     │
│ 到期复习                                                            │
│ 5 条 / 预计 4 分钟                                   [开始复习]     │
│ 逾期主题：重试风暴 / 退避加抖动 / 幂等                              │
│ 已有会话时：[继续复习 2/5]                                          │
│                                                                     │
│ 最近由扩展写入                                                      │
│ 熔断 / 概念 / engineering.example.com / 今天                        │
│ 幂等 / 概念 / engineering.example.com / 周四                        │
│                                                                     │
│ ── 次要信息 ──  本周成功提取 4 个碎片                               │
└─────────────────────────────────────────────────────────────────────┘
无到期碎片时，「到期复习」区显示「今天没有到期复习」，并给出「整理最近碎片」。
```

### 3.2 到期复习

显示：

- 到期数量。
- 预计用时，按每条 45 秒估算。
- “开始复习”主按钮。
- 最多显示前三个逾期主题，不展示全部列表。

无到期碎片时显示整理最近碎片。

### 3.3 新写入碎片

新 Fragment 不要求再次编辑。用户可以打开详情；R1 Desktop 的采集字段只读。

## 4. 碎片库

### 4.1 桌面布局

采用三栏结构：

```text
左：筛选与保存视图
中：可排序列表
右：详情；复习状态由 Desktop 更新
```

窗口过窄时右栏变为 sheet，不把三栏压缩到不可读。

```text
┌ 筛选与保存视图 ─┬ 列表 ──────────────────────────────────┬ 详情 ───────────────────────┐
│ 类型            │ 内容           类型   来源   复习      │ 概念 / Backpressure         │
│ [x] 概念        │ Backpressure   概念   eng...   明天    │ ── 用户应用 ──              │
│ [ ] 论点        │ 重试风暴        概念   eng...   1 天后 │ 检查当前事件管道为什么在... │
│ [ ] 方法        │ 退避加抖动      方法   eng...   到期   │ ── 核验 ──                  │
│ 来源 v          │ ...                                    │ 已确认 / 来源：原文         │
│ 标签 v          │                                        │ ── 原始语境 ──  回到来源    │
│ 保存的视图      │                                        │ ── 复习摘要 ──              │
│                 │                                        │                             │
└─────────────────┴────────────────────────────────────────┴─────────────────────────────┘
```

### 4.2 列表字段

默认列：

- content
- kind
- sourceHost
- tags
- review 状态
- capturedAt

用户可隐藏列，但 content、kind 不可隐藏。

搜索字段、跨维度筛选、稳定排序和分页以 [检索契约](search.md) 为准；Desktop 的 review 状态以 SQLite 本地事实计算，不依赖扩展缓存。

### 4.3 详情页

按以下顺序展示：

1. 内容和 kind。
2. 用户应用。
3. 核验确认时间、来源，以及用户填写时才出现的摘要和备注。
4. 原始语境和回到来源。
5. 复习摘要。
6. 标签和元数据。

这个顺序刻意把用户加工放在原文前面，避免详情退化成剪藏查看器。

### 4.4 批量操作

R1 的扩展来源 Fragment 不在 Desktop 修改采集字段，避免单向交付后被旧数据覆盖。Desktop 可独立删除自己的 Fragment：相关复习日志一并删除；本地删除标记阻止扩展旧请求把同一 ID 重新写入。R3 建立双向冲突规则后再启用批量采集字段操作：

- 添加或移除标签。
- 归档/取消归档（目标契约增加后启用）。
- 批量删除并二次确认；删除仍只作用于 Desktop 本地。

不提供批量修改理解、核验和应用。

## 5. 复习会话

### 5.1 会话结构

```text
题面
  -> 用户主动回答
  -> 可选提示
  -> 揭示参考信息
  -> again / hard / good / easy
  -> 下一条
```

评分按钮只能在揭示后出现。

一张卡片经历三个界面状态（示例为一张新概念卡）：

```text
① 题面
┌ 概念 2/5 ──────────────────────────────────────────────┐
│ 用自己的话解释它，并给出一个适用边界。                 │
│ 主题：Backpressure                                     │
│ 先自己作答，再点「揭示」                               │
│                                    [提示 0/4]   [揭示] │
└────────────────────────────────────────────────────────┘

② 提示：逐级点开，使用任一级即记 usedHint
┌ 提示 1/4 关键词 ────────────────────────────────────────┐
│ 需求信号 / 缓冲 / 丢弃                                  │
│                                 [再给一级提示]   [揭示] │
└─────────────────────────────────────────────────────────┘

③ 揭示后：显示你的理解、核验确认和应用，评分按钮此刻才出现
┌ 揭示 ───────────────────────────────────────────────────────────┐
│ 你的理解：下游通过需求信号、暂停、缓冲或丢弃，把压力传回上游    │
│ 核验：已确认，来源：原文                                        │
│ 你的应用：检查当前事件管道为什么在消费者变慢后耗尽内存          │
│ [1 再来一次: 1 天] [2 较难: 1 天] [3 良好: 1 天] [4 容易: 4 天] │
│ 回到来源                                                        │
└─────────────────────────────────────────────────────────────────┘
```

评分按钮上的预计间隔由当前调度状态实时算出（[review.md §3](review.md)），键盘 `1…4` 对应四档。揭示面保留“回到来源”，用于对照原文。

### 5.2 题面

每种 kind 的默认题面集中在 [kinds.md](kinds.md)（§1 总览，§4 卡片），本文不重复。

首版答案由用户自评，不自动判定长文本正确性。系统可以展示核验内容和用户先前应用作为参考。

`visual` 的 R1 复习先给出来源和任务提示，让用户回忆关键细节；揭示后再展示文字描述与截图。截图经本地服务附件接口写入；附件暂时缺失时仍保留文字题面与加工内容，并显示待重试状态。图像遮挡题型放在 R4。

### 5.3 提示梯度

提示由粗到细共四级，逐级打开，按钮显示已用级数（“提示 n/4”）；使用任何一级都写入 `usedHint`。每个 kind 各级提示的内容见 [kinds.md](kinds.md)（§3 共享规则，§4 卡片），本文不重复；第四级统一为核验确认。

### 5.4 中断恢复

- 会话队列在开始时生成并持久化。
- 评分成功后才移动游标。
- 退出后首页显示“继续复习 N/M”。
- Fragment 在其他窗口被删除时跳过并记录，不导致会话崩溃，会话中只给一行轻提示。

### 5.5 收尾与每日上限

会话结束时只陈述事实：已评分条数、其中使用过提示的条数和评为“再来一次”的条数、下一批到期时间；不展示连续天数、徽章或庆祝动画。用户可以主动继续下一会话，未完成的到期项保留原 `nextReviewAt`。

```text
┌────────────────────────────────────────────────────────────┐
│ 这一轮完成了                                               │
│ 已评分 5 条 / 其中 2 条用过提示 / 1 条「再来一次」         │
│ 下一批到期：明天 2 条 / 周日 1 条                          │
│                 [回到今日]  [继续下一会话 / 还有 3 条到期] │
└────────────────────────────────────────────────────────────┘
```

当天建议量已满时（默认 20 条，见 [review.md §5](review.md)），页面如实说明“建议量 20 / 20；还有 6 条到期，保留原到期时间，明天继续”，并提供“再来一轮（超出建议量）”，不强制停止。

## 6. 系统

系统页包括：

- 本地中枢地址和运行状态。
- 配对 token。
- 最近扩展连接时间。
- 最近扩展逐项写入结果和缺失图片数。
- 数据库版本和本地交付错误。
- R3 起的同步冲突报告，放在技术信息里，不占首页。

技术信息默认折叠；首页只显示需要用户处理的异常。

```text
系统
┌ 连接 ─────────────────────────────────────────────┐
│ (o) 本地服务运行中，仅监听本机                    │
│ 配对码：********    [显示]  [复制]  [重新生成]    │
│ 最近扩展连接：2 分钟前                            │
├ 最近交付 ─────────────────────────────────────────┤
│ 碎片 5 条已接收 / 图片 1 张已接收 / 缺失图片 0    │
│ 需要处理：无                                      │
├ 技术信息（默认折叠） ─────────────────────────────┤
│ > 服务地址 / 数据库版本 / 契约版本 / 交付错误明细 │
│   / 同步冲突报告（R3）                            │
└───────────────────────────────────────────────────┘
```

“重新生成”会让旧的扩展连接失效并需要重新配对，本地数据与待发送任务保留（[storage.md §8](storage.md)）。复制配对码是新用户安装漏斗中最容易断掉的一步，其耗时由 [H-08](validation.md) 衡量。

## 7. 菜单栏

菜单栏只提供高频状态和命令：

- 打开主窗口。
- 到期数量。
- 最近扩展交付状态。
- 最近连接状态。
- 本地服务状态；R3 增量同步上线后提供同步命令。
- 退出。

配对 token 不直接占据菜单栏首屏，进入系统页查看。

## 8. 通知与偏好设置

### 8.1 通知

R1 只允许用户配置的每日复习提醒。R3 增量同步上线后，可增加连续 24 小时同步失败且有待发送数据的通知。

不发送采集数量、连续使用天数或营销通知。

### 8.2 偏好设置

用标准 macOS 设置窗口（`Cmd+,`），目前只有“复习”一页：

```text
┌──────────────────────────────────────────────────────────────┐
│ 复习                                                         │
│                                                              │
│ 每日建议上限    5 -----(o)--------- 50                 20 条 │
│ 每日复习提醒    [开]  每天  20:30                            │
└──────────────────────────────────────────────────────────────┘
```

- 每日建议上限：5 到 50，默认 20。它限制当天的建议量，不强制同一会话做完；单次会话按每条 45 秒估算，默认最多 13 条（[review.md §5](review.md)）。
- 每日复习提醒：开关与提醒时间；只发复习提醒，不发采集数量、连续使用天数或营销通知（见 8.1）。
- Desktop 没有需要模型的能力（[D-10](validation.md)），所以没有模型设置页。
- 界面语言随系统语言（[D-15](validation.md)）：中文系语言显示中文，其他语言显示英文，没有语言设置项。导航、列表、详情、复习会话（含 [kinds.md](kinds.md) 的题面和提示梯度的英文译文）、系统页、菜单栏、偏好设置和提醒通知都按这个语言显示；用户保存的内容不翻译。

## 9. 键盘与可访问性

- 所有主流程支持键盘完成。
- `Cmd+K` 打开全局搜索/命令面板。
- 使用 `Cmd+1...3` 切换一级页面，`Cmd+,` 打开偏好设置。
- 复习评分支持 `1...4`，揭示前无效。
- 颜色不是状态的唯一表达。
- VoiceOver 能读出 kind、来源和到期状态。

## 10. 验收标准

1. 用户可从新安装到完成首次复习，不依赖网络或 LLM。
2. Desktop 可通过本地服务接口逐条接收 Fragment 与所引用的原图，重复请求幂等且重启后保持一致。
3. 七种文本 kind 和基础 `visual` 的详情与复习题型正确展示。
4. 扩展再次交付同一 Fragment 时，不覆盖 Desktop 已提交的复习评分；任一写入失败不丢评分。
5. 1 万条 Fragment 的常用查询在本机 200ms 内返回首屏结果。
6. [examples.md §5](examples.md) 的场景 B、C 通过。
