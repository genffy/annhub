# Fragment 类型目录

> 层级：core
> 状态：类型产品规格真源
> 更新：2026-10-04

本文是每种 Fragment kind 的**产品规格唯一归属**：什么时候选它、采集时怎么问、复习怎么出题、好与弱的例子。字段形状与校验见 [Fragment 契约](fragments.md)，三步加工机制见 [加工规则](processing.md)，评分与调度见 [复习规则](review.md)，页面布局见 [扩展 PRD](extension.md) 和 [Desktop PRD](desktop.md)。

其他文档不再各自维护按 kind 的提问、题面或提示表，只链接到本文。

## 1. 一页总览

| kind | 一句话 | 选它的信号 | 表单必填 | 默认复习题面 | 版本 |
| ---- | ------ | ---------- | -------- | ------------ | ---- |
| `excerpt` | 有明确保留原因的一段原文 | 暂时归不进其他类，但说得出为什么留 | 无 | 这段材料的核心观点是什么？为什么值得保留？ | R1 |
| `concept` | 术语、模型或框架 | 看到一个会反复遇到的名词或模型 | 无 | 用自己的话解释它，并给出一个适用边界。 | R1 |
| `claim` | 可被支持、质疑或反驳的主张 | 作者在下判断，你不想当作事实照单全收 | 立场 | 这个主张依赖哪些前提和证据？ | R1 |
| `procedure` | 方法、步骤、检查清单 | 读到“该怎么做”，并打算照着做 | 至少一个步骤 | 从目标出发重建关键步骤和失败条件。 | R1 |
| `decision` | 一次取舍及其理由 | 读到或做出“为什么选 A 不选 B” | 理由 | 当时有哪些约束，为什么没有选其他方案？ | R1 |
| `question` | 待验证的问题或假设 | 还没有结论，但想留住这个疑问 | 状态，加假设、下一步或答案之一 | 当前假设、证据和下一步验证分别是什么？ | R1 |
| `visual` | 图表、界面或视觉细节 | 关键信息在图里，文字复述不了 | 关键细节描述，且至少关联一张图 | 这张图的关键细节、结构或意图是什么？ | R1 |
| `inspiration` | 用户自己的短篇想法或随感 | 想法是你的，不是页面里的 | 想法形式（`idea` / `reflection`）和触发背景 | 当时由什么触发这个想法？现在还认可什么？ | R1 |
| `media-clip` | 视频或音频的一段时间区间 | 要点在一段讲话里，且你记得住时间点 | 起止时间和要点摘要 | 回忆这段媒体材料的要点与时间定位。 | R4 |

“表单必填”指采集界面不允许跳过的项；数据层是否必填见 [fragments.md §7](fragments.md)。`claim` 的立场在表单中必选（`support` / `oppose` / `uncertain`），数据层允许为空。

## 2. 怎样选 kind

选择顺序从上到下，命中第一条即停。自动推断只给默认值，用户随时可改（[extension.md §4.3](extension.md)）。

| 你想保存的是… | 选 |
| ------------- | -- |
| 自己产生的想法，不是页面里的话 | `inspiration` |
| 一张图，或者一段音视频里的区间 | `visual` / `media-clip` |
| 一套能照着做的步骤 | `procedure` |
| 一次取舍及其理由 | `decision` |
| 一个还没解决的问题 | `question` |
| 一个可以被反驳的判断 | `claim` |
| 一个术语或模型 | `concept` |
| 以上都不是，但说得出为什么留 | `excerpt` |
| 以上都不是，也说不出为什么留 | 不要建 Fragment：保存为剪藏，之后再升级 |

最后一行是产品红线：Fragment 不是“稍后整理”的收件箱。说不出保留原因时，安全出口是 Highlight 或 Clip（[product.md §5.2](product.md)）。

## 3. 所有 kind 共享的规则

- **三步加工**：理解（仅深度模式）→ 核验确认 → 应用。核验是用户点击“确认已核对”，不要求另写摘要；应用不可为空（[processing.md §2](processing.md)）。
- **应用的质量标尺**：好的应用同时含有一个**对象**（哪个任务、文档、判断）和一个**动作或问题**（检查、转成、追问、验证）。校验器只拦截空白与原文复制，质量靠提示语和抽样（[metrics.md §7](metrics.md)）。

  | 弱应用（会被抽样判为敷衍） | 好应用 |
  | -------------------------- | ------ |
  | 以后可能用得上 | 在支付网关故障复盘中，检查客户端重试是否放大了流量 |
  | 作为参考 | 评审“拆服务即可提升交付速度”时，追问团队边界与发布责任 |
  | 理解这个概念 | 检查当前事件管道为什么在消费者变慢后耗尽内存 |

- **提示梯度**：复习中的提示由粗到细共四级，使用任何一级都记 `usedHint`；第四级统一为核验确认（有摘要则展示摘要，否则回看原始语境）。
- **来源透明**：核验来源三选一：原始材料、手工、用户接受的模型建议。模型建议只有被用户确认后才算数。
- **写不出来时的退路**：每个 kind 都有“何时不选”。退路永远是 Highlight 或 Clip，而不是半成品 Fragment。

## 4. 类型卡片

### 4.1 `excerpt` 摘录

**何时选**：一段原文值得留下，但不属于概念、论点或方法，且你说得出原因。
**何时不选**：说不出原因，只想以后搜得到。保存为剪藏。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解（可选）：为什么这段话值得保留？核验：回看原文和语境。应用：你准备在哪个任务中引用或使用？ |
| 详情字段 | `note`（可选） |
| 提示梯度 | 来源与出处 → 前后文语境 → 原文本身 → 核验确认 |

**示例**：内容“Retries can amplify an outage when the dependency is already saturated.”；应用“在支付网关故障复盘中，检查客户端重试是否放大了流量”。
**常见误用**：把它当无加工剪藏。应用空泛时，说明该存为 Clip。

### 4.2 `concept` 概念

**何时选**：遇到会反复出现的术语、模型或框架，想要能自己解释并说出边界。
**何时不选**：只是一句话定义、之后不会用到。存剪藏。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解：用自己的话解释它。核验：对照定义、边界和示例。应用：它可以解释你当前哪个问题？ |
| 详情字段 | `definition`、`boundaries[]`、`examples[]`、`counterExamples[]`，均可选 |
| 提示梯度 | 关键词 → 上下文 → 定义与示例 → 核验摘要 |

**示例**：内容“Backpressure”；理解“下游通过需求信号、暂停、缓冲或丢弃，把压力传回上游”；核验摘要“不只是固定速率限流，还涉及队列边界和反馈机制”；应用“检查当前事件管道为什么在消费者变慢后耗尽内存”。
**常见误用**：理解栏照抄定义。复习时会立刻暴露“只能认出、说不出”。

### 4.3 `claim` 论点

**何时选**：作者在下判断，你需要记下立场、证据和前提，避免把观点当事实。
**何时不选**：内容是已被广泛接受的定义。存 `concept`。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解：你目前赞同吗？为什么？（立场、前提、怀疑点）。核验：检查证据和反例。应用：你会用它支持、质疑或修正什么判断？ |
| 详情字段 | `stance`（`support` / `oppose` / `uncertain`）、`evidence[]`、`assumptions[]` |
| 提示梯度 | 主题 → 证据片段 → 原文 → 核验确认 |

**示例**：内容“Most microservice failures are organizational failures.”；立场 `uncertain`；证据“团队边界、部署责任、接口治理的三个例子”；应用“评审‘拆服务即可提升交付速度’时，追问团队边界与发布责任”。
**常见误用**：核验确认只代表“我回看过”，不代表主张为真；有争议的论点保持 `uncertain` 是正确用法。

### 4.4 `procedure` 方法

**何时选**：读到一套可以照着做的步骤，并打算在某个任务里执行。
**何时不选**：只是概览或原则、没有可执行步骤。存 `concept` 或 `excerpt`。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解：先写出你记得的步骤。核验：对照完整流程与适用条件。应用：你准备在哪个任务中执行？ |
| 详情字段 | `steps[]`（至少一项）、`prerequisites[]`、`failureModes[]` |
| 提示梯度 | 步骤数 → 首步 → 完整流程 → 核验确认 |

**示例**：内容“Production incident triage”；步骤“确认影响 → 限制扩散 → 保存证据 → 建立时间线 → 验证恢复”；失败模式“过早重启导致证据丢失”；应用“转成当前团队的值班检查清单，下周二交 SRE 评审”。
**常见误用**：只存标题不存步骤。数据层会拒绝没有步骤的方法。

### 4.5 `decision` 决策

**何时选**：读到或做出一次取舍，想日后复盘“当时为什么这样选”。
**何时不选**：只有结论、没有理由和约束。先补理由，否则存剪藏。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解：推断做出该决定的约束。核验：核对背景、备选项和后果。应用：以后用什么信号验证它？ |
| 详情字段 | `rationale`（必填）、`alternatives[]`、`consequences[]` |
| 提示梯度 | 结论 → 约束 → 理由 → 核验确认 |

**示例**：内容“首版不做实时协作”；理由“单人本地优先是核心验证，协作会引入账号、权限和冲突复杂度”；备选“共享文件、云工作区”；应用“用户提出共享需求时，用真实使用数据重新评估”。
**常见误用**：复盘时直接改写旧决策。应新建一条 decision，旧决策保留。

### 4.6 `question` 待验证问题

**何时选**：还没有结论，但想把疑问、当前假设和下一步验证留住。
**何时不选**：问题已有明确答案。直接存 `concept` 或 `claim`。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解：你当前的假设是什么？核验：整理已知证据和未知项。应用：下一步如何验证？ |
| 详情字段 | `status`（`open` / `testing` / `answered`）；`open` 与 `testing` 需 `hypothesis` 或 `nextStep`，`answered` 需 `answer`；`evidence[]` 可选 |
| 提示梯度 | 主题 → 最近证据 → 当前结论 → 核验确认 |

**示例**：内容“主动加工是否会让采集完成率低于可接受水平？”；假设“Highlight/Fragment 分流可以降低放弃率”；下一步“观察 Modal 退出率和完成时间”；状态 `open`。
**常见误用**：把未解决的问题写成结论。`question` 的作用就是让知识库容许不确定。

### 4.7 `visual` 视觉细节

**何时选**：关键信息在图表或界面里，文字复述不了，且你能写下关键细节。
**何时不选**：只想存一张图备用。留在截图集，不转 Fragment。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解：这张截图的关键细节是什么？核验：对照原图和页面语境。应用：准备在哪个任务中使用或检验？ |
| 详情字段 | `attachmentIds[]`（至少一项）；用户写的关键细节描述就是 `content` |
| 提示梯度 | 结构关键词 → 文字描述 → 原图 → 核验确认 |
| 增强（R4） | 复习时可先以马赛克遮挡，回答后揭示原图；图片缺失时保留文字卡并提示待重试 |

**示例**：描述“重试开始后 5 分钟，下游 p99 延迟从 120ms 升到 2s；红线标出了重试放大的时间点”；应用“在复盘文档里作为‘重试放大’的证据图”。
**来源边界**：R1 的 `visual` 只来自扩展里的网页截图；页面原文与用户描述在界面上分别标识，不能把用户描述说成网页内容。

### 4.8 `inspiration` 灵感与短随感

**何时选**：想法是你自己的，需要记下它从何而来，之后在写作或思考中继续发展。
**何时不选**：内容是页面里的话（存 `excerpt` 或 `claim`），或已经是长篇随笔（不属于 AnnHub，写在自己的写作工具里）。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解：这个想法从何而来？核验：区分观察、推测与反例。应用：准备在哪篇文章、哪个问题或下次思考中继续？ |
| 详情字段 | `form`：`idea` 或 `reflection` |
| 约束 | 内容为一条不超过 500 字符的原创想法；触发背景非空；无网页来源时使用本地来源，不伪装成引述 |
| 核验的含义 | 回看触发背景，区分直接观察与个人推测；不要求证明灵感“正确” |
| 提示梯度 | 触发背景 → 原记录 → 后续修订 → 核验确认 |
| 入口 | 碎片库“新建灵感”（无需网页选区），或从网页选区触发后保留真实页面来源 |

**示例**：内容“软件的提醒不应该只问‘今天完成了什么’，还应让我看见哪些判断改变了”；形式 `reflection`；触发背景“设计今日页时，发现任务计数无法表达理解的演化”；应用“下次写产品设计说明时，把‘判断变化’作为一个评估维度”。
**常见误用**：写成长文。超过一个知识单位的长篇内容不属于 AnnHub，写在自己的写作工具里。

### 4.9 `media-clip` 媒体片段（R4）

**何时选**：要点在一段视频或音频里，你能标出起止时间并写下要点。
**何时不选**：想存整段媒体或只存链接。存剪藏。

| 项 | 规格 |
| -- | ---- |
| 采集提问 | 理解：这段内容的要点是什么？核验：对照原片段与转写。应用：准备在哪个任务中使用这段内容？ |
| 采集方式 | 页面存在可捕获的媒体时，在选区菜单出现“媒体片段”；标记起止或精确输入秒数；转写可手工填写，模型转写只是可选加速 |
| 详情字段 | `startMs`、`endMs`（`0 ≤ startMs < endMs`）；`attachmentIds[]` 可选 |
| 内容约定 | `content` 是要点摘要；转写与前后语境放在 `context.excerpt` |
| 提示梯度 | 主题 → 要点 → 原片段 → 核验确认 |

**示例**：要点“幂等键应在请求首次落库时生成，并与结果一起保存至重试窗口结束”，区间 17:20–19:05；应用“写入支付重试方案的幂等设计章节”。
**边界**：不为媒体另建训练系统或独立复习引擎；媒体文件的容量与传送规则需单独设计，文件缺失时仍保留可读文字。

## 5. 新增一种 kind 的清单

仅把字符串加进类型列表不算完成。新增时同时提交：

1. **本文**：总览行、选择顺序中的位置、一张完整卡片（含好与弱的示例）。
2. **[fragments.md](fragments.md)**：`detail` 字段、校验与稳定错误码。
3. **[processing.md](processing.md)**：无需改表，只在本文补采集提问。
4. **[review.md](review.md)**：无需改表，只在本文补题面与四级提示。
5. **[user-stories.md](user-stories.md)**：采集、复习两条故事及验收。
6. 双端 fixture、单元测试和至少一条端到端采集测试。

注册但尚未实现的 kind 必须返回 `KIND_NOT_IMPLEMENTED`，不能静默写入未经校验的数据。
