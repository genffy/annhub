本文用具体的人、具体的时间点和具体的界面行为，把[产品定位](product.md)和各规则文档串成可演示、可验收的场景。它同时是演示脚本、端到端测试脚本和对外案例的素材来源，因此数字与行为必须与真源一致；每种 kind 的完整卡片见 [kinds.md](kinds.md)。

## 1. 场景边界

首版处理的来源：

- 技术文档、RFC、博客和事故复盘。
- 行业文章、研究报告和产品说明。
- 竞品页面、设计案例和图表说明。
- 公开会议纪要、决策记录和项目复盘。

核心输入是网页文本选区、手工原创的短篇 `inspiration` 和网页截图。截图不绕开文本说明和主动加工；手工灵感必须填写触发背景。典型用户见 [product.md §2.1](product.md)。

## 3. 主线走查：为支付系统设计失败重试策略

**人物**：L，后端工程师，正在写“支付系统失败重试策略”的设计文档，三周后评审。使用 Mac 和 Chrome，已安装扩展，**尚未安装 Desktop**。

**材料**：三篇技术文章（示例来源，非真实站点）。下表中的文案、数字只是示例，规则与界面行为以各真源为准。

| 时间 | 在哪里 | L 做了什么 | 系统结果 |
| ---- | ------ | ---------- | -------- |
| 评审当天 | 扩展碎片库 | 把周三保存的那条 `question` 的状态改为 `answered`，写下评审得出的答案（采集字段在扩展修改） | 修订号递增；之后重新交付给 Desktop |

**这条走查要证明的事**：L 第一周花很少时间采集了五条碎片；周五晚上完成第一次回忆；第二周在复习中发现并修正了一个概念的理解，并留住了一个未解决的问题；评审后补上了答案。没有任何一步依赖 LLM。

## 4. 另外两条旅程

### 4.1 产品经理比较竞品论点

| 步骤 | 做什么 | 产出 |
| ---- | ------ | ---- |
| 阅读 | 读两篇观点相反的文章 | — |
| 采集 | 各保存一条 `claim`，立场分别选 `support`、`oppose`，写下证据与前提 | 2 条论点 |
| 复习 | 到期时先回忆两种主张各自的前提与证据，再揭示 | 评分 |
| 沉淀 | 把未知项保存为 `question` | 1 条问题 |

成功条件：复习时能分别说出两种主张的前提，而不是只记住结论。

### 4.2 团队复盘是否延续过去的决策

| 步骤 | 做什么 | 产出 |
| ---- | ------ | ---- |
| 保存 | 把历史决策和理由保存为 `decision`，写明备选与后果 | 1 条决策 |
| 复习 | 到期时先回忆当时的约束，再揭示 | 评分 |
| 更新 | 保存新的判断为一条新的 `decision`，旧决策保留 | 1 条决策 |

成功条件：用户能回看旧判断和当时的理由，而不是只看到最新版本。

## 5. 验收场景

每个场景都是一条可直接执行的脚本。通过标准写成可观察的结果。

| 场景 | Given | When | Then |
| ---- | ----- | ---- | ---- |
| A 断网采集 | 断网，Desktop 未启动，LLM 关闭 | 保存一条 `concept` 和一条 `visual`，搜索它们，点“导出内容” | 两条都保存成功并可搜索；界面显示待发送项（2 条碎片、1 张图片）而不是错误；ZIP 含两份 Markdown 和一份图片，Markdown 的图片链接有效 |
| B 扩展到 Desktop | 扩展里有已保存的碎片和图片；Desktop 启动并完成配对 | 等待自动重试，或点“立即重试” | Desktop 逐条收到 Fragment 和图片；重复交付不产生重复；来源和加工字段完整；Desktop 已有的复习评分不被覆盖 |
| C 通用复习 | Desktop 里有 `concept`、`claim`、`procedure`、`decision` 各一条到期 | 连续复习四条，第三条中途退出后重开 | 四条题面与提示梯度各不相同，与 [kinds.md](kinds.md) 一致；重开后从第三条继续，已评分的不重复提交 |

## 6. 非目标

- 保存和管理完整网页阅读列表。
- 替代 Zotero 的文献引用能力。
- 替代 Obsidian 的通用自由写作和插件平台。
- 把所有高亮自动转成复习卡片。
- 用 AI 摘要替代用户理解。

完整的不做清单见 [product.md §2.3](product.md)。

## 7. 成功标准

- 用户可从不同站点创建七种文本 Fragment，也能不依赖网页选区创建 `inspiration`。
- 每条 Fragment 脱离原网页后仍可理解。
- Highlight、Clip 与 Fragment 的选择对用户清晰。
- 复习题型与 kind 匹配。
- 关闭 LLM 后主流程仍完整可用。

视觉与媒体来源的边界：多模态是 Fragment 来源的扩展，不建立独立学习系统；截图见 [screenshot.md](screenshot.md)，媒体片段见 [kinds.md §4.9](kinds.md)。任何新入口都不能绕开 L2，也不能复制一套复习或本机交付系统。
