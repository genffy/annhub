# 场景与走查

> 层级：scenario
> 状态：当前产品方向
> 更新：2026-10-07

本文用具体的人、具体的时间点和具体的界面行为，把[产品定位](product.md)和各规则文档串成可演示、可验收的场景。它同时是演示脚本、端到端测试脚本和对外案例的素材来源，因此数字与行为必须与真源一致；每种 kind 的完整卡片见 [kinds.md](kinds.md)。

页面体验见 [扩展 PRD](extension.md)。

## 1. 场景边界

首版处理的来源：

- 技术文档、RFC、博客和事故复盘。
- 行业文章、研究报告和产品说明。
- 竞品页面、设计案例和图表说明。
- 公开会议纪要、决策记录和项目复盘。

核心输入是网页文本选区、手工原创的短篇 `inspiration` 和网页截图。截图不绕开文本说明和主动加工；手工灵感必须填写触发背景。典型用户见 [product.md §2.1](product.md)。

**人物**：L，后端工程师，正在写“支付系统失败重试策略”的设计文档，三周后评审。使用 Chrome，已安装扩展。

## 4. 另外两条旅程

### 4.1 产品经理比较竞品论点

| 步骤 | 做什么                                                             | 产出     |
| ---- | ------------------------------------------------------------------ | -------- |
| 阅读 | 读两篇观点相反的文章                                               | —        |
| 采集 | 各保存一条 `claim`，立场分别选 `support`、`oppose`，写下证据与前提 | 2 条论点 |
| 沉淀 | 把未知项保存为 `question`                                          | 1 条问题 |
| 找回 | 写比较结论时，按类型筛选“论点”，并排看两条的前提与证据             | —        |

成功条件：写比较时能直接取用两种主张各自的前提与证据，而不是只记得结论。

### 4.2 团队复盘是否延续过去的决策

| 步骤 | 做什么                                            | 产出     |
| ---- | ------------------------------------------------- | -------- |
| 保存 | 把历史决策和理由保存为 `decision`，写明备选与后果 | 1 条决策 |
| 回看 | 复盘时搜到这条决策，回看当时的约束与备选          | —        |
| 更新 | 保存新的判断为一条新的 `decision`，旧决策保留     | 1 条决策 |

成功条件：用户能回看旧判断和当时的理由，而不是只看到最新版本。

## 5. 验收场景

每个场景都是一条可直接执行的脚本。通过标准写成可观察的结果。

| 场景           | Given                                      | When                                                       | Then                                                                                                       |
| -------------- | ------------------------------------------ | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| A 断网采集     | 断网，LLM 关闭                             | 保存一条 `concept` 和一条 `visual`，搜索它们，点“导出内容” | 两条都保存成功并可搜索；ZIP 含两份 Markdown 和一份图片，Markdown 的图片链接有效                            |
| B 找回与修正   | 碎片库里有一条已保存的 `concept`，LLM 关闭 | 搜索它的关键词，点“回到来源”，再修改“应用”并保存           | 搜索命中该条；来源页被打开；保存后修订号递增，再次搜索得到修改后的文字；断网时同样可用                     |
| C 各类型的采集 | 碎片库为空，LLM 关闭                       | 依次保存 `concept`、`claim`、`procedure`、`decision`       | 四种类型的采集提问和必填项各不相同，与 [kinds.md](kinds.md) 一致；缺必填项时不能保存，且已输入的内容不丢失 |

## 6. 非目标

- 保存和管理完整网页阅读列表。
- 替代 Zotero 的文献引用能力。
- 替代 Obsidian 的通用自由写作和插件平台。
- 把所有高亮自动转成 Fragment。
- 用 AI 摘要替代用户理解。

完整的不做清单见 [product.md §2.3](product.md)。

## 7. 成功标准

- 用户可从不同站点创建七种文本 Fragment，也能不依赖网页选区创建 `inspiration`。
- 每条 Fragment 脱离原网页后仍可理解。
- Highlight、Clip 与 Fragment 的选择对用户清晰。
- 采集提问与校验和 kind 匹配。
- 关闭 LLM 后主流程仍完整可用。

视觉与媒体来源的边界：多模态是 Fragment 来源的扩展，不建立独立学习系统；截图见 [screenshot.md](screenshot.md)，媒体片段见 [kinds.md §4.9](kinds.md)。任何新入口都不能绕开 L2。
