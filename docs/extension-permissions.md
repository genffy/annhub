# 扩展权限说明

> 对应 `wxt.config.ts` 的清单。商店审核的 “permission justification” 和隐私披露从这里取材；产品边界见 [docs/v2/extension.md](v2/extension.md)。
> 更新：2026-10-04。

## 申请的权限

| 权限        | 用途                                                                         | 去掉的后果                       |
| ----------- | ---------------------------------------------------------------------------- | -------------------------------- |
| `storage`   | 设置、未提交表单的草稿、高亮与剪藏、交付任务的元数据                         | 无法保存任何东西                 |
| `commands`  | 键盘快捷键：区域截图、连续高亮模式                                           | 快捷键失效，鼠标入口不受影响     |
| `alarms`    | 在 service worker 休眠后仍能按退避重试向 Desktop 的逐条交付                  | 断线后只能在重新打开扩展时才重试 |
| `downloads` | 把截图和 “导出内容” 的 ZIP 保存为本地文件                                    | 无法下载截图与导出               |
| `scripting` | 快捷键触发时，内容脚本没有应答的页面上兜底在扩展自己的隔离环境里调用一次触发 | 少数页面上快捷键首次没有反应     |

## 主机权限

| 范围                      | 用途                                                                                                                                                                                      |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<all_urls>`              | 内容脚本在用户读的任意网页上工作；`captureVisibleTab` 截取发起截图的那个标签；service worker 代页面抓取跨域图片的字节（只取公网上的图片，不碰本机和局域网），绕开页面的 CORS 才能保存原图 |
| `http://127.0.0.1:8765/*` | 向本机运行的 Desktop 交付碎片。这一条被 `<all_urls>` 覆盖，单独列出是为了让读清单的人看到它的存在                                                                                         |

采集流程只在用户主动选择或截图时读取页面内容；不会把页面内容、URL 或用户产出发往任何远程服务器。LLM 默认关闭，开启后只在用户确认的单次请求里把所选内容发给用户自己配置的 Provider（见 [docs/v2/ai.md](v2/ai.md)）。

## 刻意没有申请的权限

- `tabs`、`activeTab`：`<all_urls>` 已经包含它们能给的一切（读取标签的 URL 与标题、截取可见标签），重复申请只会增加安装时的警告。
- `history`、`bookmarks`、`cookies`、`webRequest`、`nativeMessaging`、`clipboardWrite`（后者随 R5 的复制 PNG 再申请，见 [roadmap](v2/roadmap.md)）。
- `unlimitedStorage`：截图入库前先检查配额，不足时提示导出，而不是静默申请更大的空间。

## 最低浏览器版本

`minimum_chrome_version` 为 114：依赖的最新能力是 CSS Custom Highlight API（105）和 `storage.session` 的访问级别（102），在其上留出余量；低于 114 没有测试过。

## 改动清单时

新增、删除或扩大任何权限，都要同步这份文档、商店的 permission justification 和 [docs/v2/roadmap.md](v2/roadmap.md) 里 “商店要求的隐私披露与权限说明” 一项。
