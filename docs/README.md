# AnnHub Docs

本文档目录只维护 AnnHub 当前的产品：浏览器扩展里剪藏、截图的采集，以及在资料库里读剪藏、高亮、整理、检索与导出；讲解网页时用的页面批注与标签页录屏。

## 文档索引

| 文档                               | 说明                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------ |
| [产品文档](./product/README.md)    | 产品定位、条目契约、采集与存储、扩展体验、权限与数据边界、路线图、待决事项；入口与文档地图 |
| [UX/UI 设计稿](./design/README.md) | 扩展全部界面的画板与可交互原型，文案以产品文档为准                                         |
| [审查问题](./review.md)            | 代码审查发现、还没处理的问题与已知问题；修好即删，编号留在测试用例名里                     |

## 维护约定

1. `docs/product/` 是产品层真源，描述当前的产品、边界、契约和路线图；规则见 [产品文档约定](./product/AGENTS.md)。
2. 根目录 `AGENTS.md` 是工程约定入口；目录专属规则由各级 `AGENTS.md` 管理，当前实现细节以源码和测试为准。CI、发布与仓库设置见根目录的 `README.md`（英文）与 `README.zh-CN.md`（中文），工作流文件自带说明。
3. 不另建工程方案或待办文档：候选功能是 GitHub issue，功能的规格随实现它的 PR 写进产品文档；代码审查发现的问题进 [review.md](./review.md)，修好就删；待确认的决策、风险与开放问题进 [validation.md](./product/validation.md)，交付状态进 [roadmap.md](./product/roadmap.md)，局部的维护提示放进相应目录的 `AGENTS.md`；一个文件放不下（超过预算）时，主题拆到同目录的 `notes/`，由该目录的 `AGENTS.md` 链接。
4. 新文档必须服务剪藏、截图的采集与库内阅读、高亮、检索、导出的主链路，或讲解网页时的页面批注与录屏。
5. 文档不写更新日期、版本号和状态标签：什么时候改的看 git，交付状态只在 [roadmap.md](./product/roadmap.md)。
6. 图片资源放在对应模块的 `assets/` 下，并使用相对路径引用。
