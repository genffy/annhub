# Content Script 约定

> 适用于当前 `entrypoints/content/` 实现；不是未来 monorepo 的目标划分。全局规则见根目录 `AGENTS.md`。
> 更新：2026-11-01。

## 职责与入口

- 页面里有两种采集（剪藏：选区/区块；截图）和一层页面批注（录制时的光标高亮也挂在页面上，annotate.md §3）。`index.tsx` 编排选区菜单、区块入口、区块模式、截图会话与批注层的进入/退出；高亮不在页面里（资料库读剪藏时才做）。
- `selection-menu.ts` 是两项菜单（剪藏、截图，顺序固定）：无最短长度、全空白选区不出现；选区端点在 input、textarea、contenteditable 里不出现；键盘 `Tab` 聚焦某一项后 `Enter` 才触发，没聚焦时回车属于页面；悬停/聚焦约 300ms 浮出深色后果卡片（`.ann-menu-tip`，两行：动作名 + 后果；在菜单的外侧——菜单在选区上方时在菜单上方、翻到下方时跟到下方、与菜单左缘对齐、无箭头，放不下时夹回视口、不盖选区；纯浮层，胶囊永远只有一行按钮，不留空白行——真机反馈，extension.md §2.1）。菜单是深色浮条，带指向选区中点的小三角（`--ann-caret`，`ann-menu-below` 翻转）。菜单贴着选区第一行、水平居中，并夹在选区所在的内容列里：宽视口里选区右侧的空当往往是旁边一栏（X 主页的 Premium/搜索栏），窗口放得下不等于该摆到选区右外侧。坐标用视口 CSS 像素（与 `getClientRects`、`position: fixed` 同一套），不加窗口滚动，也不加 iframe 在父页面上的偏移——中栏自己的滚动已经反映在矩形里，子框架的菜单用子框架自己的视口。`onScreenshot` 钩子可缺省：子框架里菜单只有“剪藏”（capture.md §3）。open shadow root 里的选区用 `getComposedRanges` 取范围，没有这个接口的 Chrome 降级为 `selection.toString()` 的纯文本剪藏（`plainTextForSelection`，capture.md §3）。
- `clip-flow.ts` 一次点击保存 + 约 3 秒「已剪藏 · 撤销 · 编辑」提示（深色胶囊，底部细条是同一份倒计时：悬停/聚焦暂停、离开重开一轮，`TOAST_MS` 与 CSS 动画时长成对改）+ 快速编辑气泡（头部一行“已剪藏 · 失焦即保存”，标签是 chip 输入——`Enter`/逗号提交、空输入 `Backspace` 删最后一个、失焦提交剩余文字，提交的标签列表仍经 `normalizeTags`）；失败保留选区与已输入内容并给重试（extension.md §3）。条目 ID 由调用方生成并随重试复用（保存幂等），`startedAt` 在点击时记下随消息发出。三个保存函数返回 `ClipOutcome | ClipFailure`：失败带后台的稳定错误码，`showFailureToast` 按码说明原因（配额不足时提示先导出），不认识的码只说“保存失败”，绝不回显原始信息。气泡只提交用户改动过的字段（`UPDATE_ENTRY` 的 `properties.set`、`note`），等响应成功才关闭，失败时气泡与输入都在、错误按同一套码显示在气泡里；标签超限在提交前就地提示。
- `markdown.ts` 是唯一的 DOM→Markdown 转换（链接、标题层级、列表、代码块、表格、强调；页面界面与隐藏内容剔除；100k 块边界截断），选区与区块共用，不各自实现。约定：`<br>` 是硬换行（行尾两个空格），表格单元格内折叠为空格；嵌套列表缩进到父项内容列；页面界面按 class/id 的**词**匹配剔除（语义容器不做 class 启发式）；文本节点里的 Markdown 记号按字面转义（`escapeText`），渲染器 `entrypoints/library/markdown-view.tsx` 的 `inlineRuns` 与 `learning-core/markdown.ts` 的纯文本化共用同一个转义约定，改一处要三处一起改。
- `page-meta.ts`：语境提取（取选区两端最近的块级祖先，上限、包含选区）、页面 meta（author/published/description/title）与永久链接（X 帖子 status 链接、一节标题锚点、其余页面地址）。meta 过长或不合规时降级而不是让保存失败：title、description 在字符边界截断并折叠换行，多位作者按分隔符拆开、超长单项丢弃。
- `blocks.ts` 七种区块识别，只在指针停留后沿祖先链（含 open shadow root）运行，不整页扫描；识别逐元素兜底，任何元素出错都等于“没有候选”，永不向页面抛异常。“一节”在标题与段落平铺的页面上是标题到下一个同级或更高级标题的兄弟区间（`BlockCandidate.range`，描边用 `candidateRect` 取外接矩形，转换与锚点只取区间）；标题直接放在文章容器（`main`、`article`）里时同样分节，所以一个元素可以同时是一节和文章，候选按 `sameCandidate` 去重而不是按元素，从容器第一段内容一直到末尾的区间就是文章本身，不另算一节（`spansWhole`）；内容容器按 class **词**匹配，没有 `article`/`main`/已知容器时取文字密集的 `div`（直接含至少三个有文字量的块）。并列至少两条帖子、帖外正文够不上一篇文章的容器（X 的时间线列，含高出窗口很多的虚拟列表）不是一节或文章，上一级停在引用或外层帖。`block-hover.ts` 悬停胶囊（右上角跨上沿、左右缘留在轮廓内、角点被占依次避让、高块贴窗口可见上沿；指针离开描边约 150ms 收起，停在没有候选的位置也收起，Esc 在胶囊按钮持有焦点时同样收起）与键盘区块模式（`Tab`/`↑↓`/`Enter`/`S`/`Esc`，链接不响应点击）。键盘模式的状态是 `modeChain`（目标的层级链，最里层在前）与 `modeDepth`：链只在换目标时整体替换，`↑↓` 只动深度——所以 `↓` 走回 `↑` 走过的链；每个单元都从它的锚点（`candidateAnchor`：一节取标题，其余取元素本身）重新探测，`Tab` 才能在标题与段落平铺的页面上走各节，`Enter`/`S` 保存的就是描边的那个（含 `range`）。同层单元（`peersOf`）是同一档（`KIND_RANK` 相同），嵌在另一个小单元里的小单元不算（帖子里的图归 `↓`）。在最里一层按 `↓` 由 `childChainOf` 结构化地走当前单元自己的内容（文档顺序、穿过 open shadow root，从窗口处起、再往下、再绕回开头），不做命中测试——区块模式的遮罩盖在页面上，命中测试只会打到它；文章先找一节，同类且装着它九成以上文字的外框（`wrapperOf`）不算一层，拼进链后深度落在最外一层（一次一层）。`peersOf` 与 `childChainOf` 都只在按键时现算，在 `inOneScan` 里共用一次按键的文字长度与 `article` 查询（同一批大祖先每个单元都要量，不缓存时大页面上一次 `Tab` 要近一秒），指针移动不重扫整页、也不滚页（只有键盘移动才 `scrollIntoView`）。起点是键盘焦点所在的单元，否则是视口里第一个（`firstVisibleChain`，capture.md §6.2）；模式取得键盘焦点（焦点原先在子框架里时，按键才会到这里），退出时还回去。状态行是 `role=status` 的活动区，只读“类型 · 摘要”（一节只读它那一段），按键提示不在其中反复播报；提示画成键帽，“区块模式”前缀带 `aria-hidden`，不进播报。
- 浮层样式全部挂在 `[data-ann-ui]`/`.ann-*` 命名空间下，经 manifest 注入（不使用 shadow root），不改宿主页面的 DOM。浮层分两类（visual.md §2）：**深色浮条**不随系统外观，一套深色——选区菜单、剪藏通知（已剪藏/撤销/失败提示）、区块胶囊、键盘模式胶囊，截图的提示条、比例芯片、尺寸标签、编辑工具栏、状态条、成功气泡，批注的工具栏与提示条——用 `content.css` 顶部的 `--annov-pill-*`（定义在浮层根选择器上，不在暗色 media query 里重复）；**表单类浮层**亮暗两套、跟随系统——快速编辑气泡、区块“更多”菜单、美化面板、截图的文字输入框与错误卡片——用成对的 `--annov-*`（暗色值与 `styles/tokens.css` 同一套）。新增颜色一律用变量；截图会话里由 `index.ts` 注入的样式同样引用这些变量（带浅色回退值）。data-URI 图标读不到变量，深底上颜色一次定好，不做暗色换图分支；能用 `currentColor` 的内联图标走 `icons.ts`。选区蓝 `#4c91ff` 与键盘描边两种外观共用——它们标在页面内容上，不是表面。

## 输入信任与站点规则

- 会话在页面 DOM 里，页面脚本能派发任何事件：一切会走到特权 API（截取、跨域代取、保存、起录）的入口只认 `user-input.ts` 的 `isUserInput`（`event.isTrusted`）或扩展自己的消息（`TRIGGER_SCREENSHOT`/`TRIGGER_BLOCK_MODE`/`TRIGGER_ANNOTATE`）。jsdom 的事件都不可信，单测 mock `isUserInput`。
- 新站点的永久链接规则集中维护（X 帖子在 `page-meta.ts` 的 `resolvePermalink`，Medium 文章规则待补），不要在业务模块散写 hostname 分支。
- 页面常在 `document` 上监听单键快捷键：扩展自己的输入框（快速编辑、截图文字标注）要把键盘事件留在自己界面里（`stopPropagation`）。
- 同源 iframe 与 open shadow root 里的选区和区块必须可用；跨源 iframe、可编辑区、受限页不出现入口也不报错（capture.md §3）。内容脚本注册到所有框架（`allFrames`），子框架只在与顶层同源时启用。截图会话、取景坐标和被截取的标签页都属于顶层框架的视口，所以子框架里只提供剪藏：菜单没有“截图”、胶囊没有“截图”、区块模式没有 `S`，发给标签页的三条触发（截图、区块、批注）只发顶层框架（`frameId: 0`），子框架收到也不理；录制开关不进页面，worker 直接处理。

## 页面批注与录制

- 批注层（annotate.md §1）在 `annotation/layer.ts`：透明覆盖层骑浏览器的 top layer（`showPopover`），页面自己的浮层、全屏内容与原生模态对话框盖不住它；原生模态对话框会挡住其余全部指针（包括这层），所以对话框开着时层挪进对话框里住、关闭后挪回（`syncDialogPlacement`，`dialog:modal` 需要 Chrome 105+）。没选工具时页面照常可交互，选了工具后一笔拖画只落在层上。墨迹在层存活期间存在：退出、刷新、导航即清空，不保存任何东西；“截图”按钮（或截图快捷键）把墨迹交给截图会话，层先藏起来，会话结束再把舞台还回来（`index.tsx` 的 `enterScreenshotWithInk`）。工具栏可设自动擦除（关闭/3 秒/8 秒三档，默认关闭，D-39）。
- 墨迹模型只有一份，在 `annotation/ink.ts`（annotate.md §1.2）：笔画按画下那一刻的**页面** CSS 坐标存储（跟随页面滚动），画在钉住窗口的元素（fixed、当前吸顶的 sticky）上的笔画保持视口坐标并带 `pinned` 标记——滚动长图不带上它。ink 换算成截图编辑器标注的规则也只在这里：整段落在取景框内的保持原生形状，完全在外面的丢弃，跨界的在边界处切断。
- 画笔与荧光笔的笔画是轨迹（annotate.md §1.2）：`points` 就是指针的样点，只追加；两点形状（直线、箭头、矩形、椭圆）的 `points[1]` 是“终点”，每次移动改写它——对轨迹工具也这样做，就会让每一笔都带一条起点到终点的连线，拖动时还有一条跟着指针的线（`follow` 按工具分两条路，`annotation/__tests__/layer-strokes.test.ts` 守着）。样点用 `pointer-samples.ts` 的 `pointerSamples` 取，批注层与截图编辑器共用：浏览器每帧只派发一个 `pointermove`，一帧里折叠的移动在 `getCoalescedEvents()` 里，不读就是折线；`pointerup` 的合并列表是空的，退回事件本身。平滑只在 `screenshot/editor.ts` 的 `tracePath`（二次曲线以样点为控制点、过相邻样点的中点，首尾半段是直的，所以笔迹从第一个样点起、到最后一个样点止）：两边都经 `drawAnnotation` 画，墨迹截进编辑器样子不变；直线、箭头、矩形、椭圆与墨迹裁剪出来的 `polyline` 不走它（矩形的角是角）。钉住窗口的笔画（`isPinnedPoint`）从第一个样点起存视口坐标：存成加了滚动量的页面坐标，而 `inkToViewport` 又把它当视口坐标用，滚动之后画的笔画会落在指针下方一个滚动量的位置。画布在选了工具时 `touch-action: none`：缺了它，触摸与手写笔的第一次移动被浏览器当成平移，随后 `pointercancel`，什么也画不出；一次只画一笔（已有笔画在进行中，或不是主指针的 `pointerdown` 不开始新的一笔，`move`/`up`/`cancel` 按 `pointerId` 过滤）。`Ctrl`/`Cmd`+`Z` 在 `onKeydown` 里：选了工具且焦点不在可编辑区域时才拦下撤销，“指针”时属于页面（D-81）。
- 录制时（annotate.md §3）被录标签页有光标高亮与点击涟漪（`cursor-highlight.ts`：`pointer-events: none`，指针离开页面时隐藏，截图截取期间也隐藏，免得高亮进了图）：录制状态在脚本启动时经 `RECORDING_STATUS` 读一次，此后以 `RECORDING_LIFECYCLE` 消息为准——生命周期消息到过之后，迟到的启动读数不得回滚它（`lifecycleSeen`）。录制中批注层以无工具栏形态打开（`setRecordingMode`），批注的控件不进画面（annotate.md §3.1）。

## 截图

- 区域截图从视口 CSS 坐标按 dpr 裁剪，调用 `captureVisibleTab` 前隐藏扩展 UI 等两帧；后台回 `CAPTURE_RATE_LIMITED`（浏览器每秒只给两次截取）时，`requestCapture` 隔 400 ms 再要、最多三次，等待中被取消就不再要。等待放在页面里，因为 worker 的定时器可能晚几秒；元素截图经离屏克隆栅格化，跨域图片由 background 代取内联（`FETCH_IMAGE`）；栅格器按样式拷贝、带不走视频帧与滚动位置：克隆里的 `<video>` 换成当前帧（跨域保护的视频从 `captureVisibleTab` 裁可见部分），滚动容器按滚动窗口重建（`element-capture.ts` 的 `restoreScrollPositions`，foreignObject 不裁嵌套 overflow）。
- 拖拽松开后选区进入待确认态（`Enter` 确认、`Esc` 取消），单击元素路径不变。待确认的选区独占画面（D-66，screenshot.md §1.2）：会话根加上 `ann-shot-modal` 接住指针，点在选区里不会穿透到页面，也不会拆掉确认条；`trackHover` 只在取景态（`selecting`）工作，待确认时没有悬停描边与边距条，方向键只微调、`↑↓` 不爬层级；`enterConfirming` 拆掉比例条并把提示条换成 `shot.hintPending`，`syncHint` 按状态选文案，进出待确认态都要重同步。点选区外是放开选区（`backToPicking`：清掉上次取景框的标签与记忆的提议，提示条、比例条回来，遮罩重新压暗）：拖动则画新选区，单击不截取，只是回到取景并立刻给指针下的元素描边。开始拖拽与确认进入编辑都会清掉悬停 UI，描边不陪选区进预览。提示条与比例条的 `z-index` 高于选区的遮罩（选区的 9999px 阴影会盖住更早的兄弟节点），不被压暗。滚动长图的入口在比例条上，所以只在取景态可用。吸附、八向手柄、方向键微调、`Shift` 临时锁比、层级 `↑↓` 与元素+边距的几何换算都是 `screenshot/selection.ts` 的纯函数，会话只做接线（screenshot.md §1.2、§1.4）。
- 上次取景框归后台：会话经 `screenshot/frame-memory.ts` 的 `REMEMBER_FRAME`、`READ_FRAME` 交给 worker，每个标签页一份，只对来源 + 路径相同的网页有效，导航到别的页面、关闭标签页、重启浏览器即清除（screenshot.md §1.4）。内容脚本不直接读写 `chrome.storage.session`，也不为此放开它的访问级别：`sender.ts` 信任的最近保存记录也在那里。元素锚点带 10% 容差。沿用从不滚动页面（D-67）：元素找得到且大小在容差内，取元素此刻的位置，否则取记录的页面位置（元素找不到时带“没找到上次的元素”），两者都要求取景框（含边距）完整落在窗口里，不然这次不出现，记忆原样留着。X 这类会回收单元格的时间线上，结构路径与页面坐标都会指向另一条帖子，滚动曾把页面拉回顶部（`e2e/virtualfeed.html` 守着）。原样确认的、由记忆给出的元素取景框仍记为元素（`offeredFrame` 与当前选区经 `sameFrame` 比较），微调过的才记为页面位置。恢复经后台往返、晚于会话开场，所以比例条等恢复有了答案才出现（`offerPicking`，不在 `settingsLoaded` 里，截取不等它）；指针已开始悬停或已在拖拽时这次不恢复，不抢用户已经在做的事。
- 区域截取前用透明 sweeper 清扫悬停样式并等 `pageStable`（连续两帧布局不变，最长 500ms），元素 + 边距能放进视口时走区域截取，放不下提示而不是截不全。
- 滚动长图（screenshot.md §1.5）是截图会话里的一个工具（`screenshot/stitcher.ts` 驱动）：页面逐屏滚动、每屏等图，每次截取都隐藏扩展 UI 与录制中的光标高亮；fixed 与当前吸顶的 sticky 元素只在第一屏拍、从第二屏起隐藏、每次截取前重查，收缩成吸顶栏的页头要在它出现的那一刻抓到。数值规则全在 `screenshot/stitch.ts`（分屏数、各屏在成品画布上的落位取整到设备像素，页底、30 屏上限、约 4000 万像素上限（D-49）与画布 65535 像素边谁先到谁停）。
- 选区内本地标注与马赛克只把处理后的 PNG 交后台入库；确认/复制/下载三个去处互相独立，复制与下载保留会话；`http:` 页面复制提示下载（screenshot.md §4）。成功类提示（已复制、已下载等）是工具栏上方的深色气泡，约 3 秒自动消失（`showNotice(message, false)` 走 `showBubble`），错误是工具栏上的红色横幅（notice 行），等下一次操作替换。工具栏下方的状态条（深色浮条，visual.md §2）显示匿名与水印状态、遮挡候选的个数与逐个移除，由 `syncStatus`/`updateToolbar` 重绘。JPEG 下载一律先铺白（`matteOnWhite`），透明处不会变黑。入库的 `startedAt` 是点击“保存”的时刻（metrics.md §9），不含此前的编辑时间；失败文案经 `screenshotFailureText`/`screenshotSaveErrorText` 由稳定错误码生成，不显示后台的原始信息。
- 美化（screenshot.md §4.4）的合成只有一份实现，在 `screenshot/output.ts`（背景、内边距、圆角、阴影、画布比例与水印；预览、复制、下载共用）；`beautify-panel.ts` 是工具栏“美化”打开的面板，纯 DOM、不留状态：显示会话给它的样式，只报告用户改了哪个字段，复原与“改动即开启”的结果由会话 `sync` 回去。会话里有三块画布：`sourceCanvas`（原始截取）、`croppedCanvas`（再加匿名、马赛克与标注，入库存的就是它）、`displayCanvas`（再加美化与水印，预览显示、复制与下载发出去的就是它）。`displayCanvas` 永远是单独的一块：给 `canvas.width` 赋值会清空画布，与 `croppedCanvas` 合成一块时，一画标注整张图就空了。标注坐标是截取画布的坐标，预览上的指针位置要先减去 `contentOrigin`（内容在画布里的偏移）。画布渐变用 `createLinearGradient`，把 CSS 渐变字符串赋给 `fillStyle` 画出来是黑的；阴影的 alpha 与图形自己的 alpha 相乘，所以阴影由画在画布外的不透明图形经 `shadowOffsetX` 投到内容上。背景、内边距、圆角的取值与默认样式只在 `output.ts` 定一次（`BEAUTIFY_BACKGROUND_IDS`、`PADDING_PX`、`BEAUTIFY_RADII`、`DEFAULT_BEAUTIFY`，背景的颜色与明暗在 `BEAUTIFY_BACKGROUNDS`），面板、设置页的选项和 `settings-schema.ts` 的校验与默认值都从它派生；背景的名字是 `ui-text` 里的 `shot.beautify.background.<id>`，不在界面里用字母或数字编号。
- 美化面板的摆放由 `placePanel` 算：预览旁边（先右后左），放不下再放工具栏下方、预览上方；原位仍然清爽就不挪，不盖住预览与工具栏，不出窗口。预览按 `previewBox` 在选区周围长大，超出视口时缩小，工具栏跟着挪；复制与下载仍是完整像素。尺寸标签由 `placeSizeLabel` 放：预览左上角外侧，上方放不下或被工具栏占着就放下方，再不行放进左上角内侧（`SIZE_LABEL_ROOM` 是它在上方要的地方，也是预览离窗口顶的最小距离，两处必须是同一个数）；它 `pointer-events: none`，放进图里也不挡画标注。面板打开时键盘落在它的第一个控件上，`Esc` 先关面板（焦点回美化按钮），再次按下才取消会话。预览出现时键盘落在工具栏的第一个按钮上：工具栏是 React 根，第一次渲染用 `flushSync` 同步提交——React 19 的 `createRoot().render()` 可能晚于下一帧才提交，找按钮的那一帧就扑空，焦点留在页面上（`e2e/screenshot-capture.spec.ts` 连开 6 次预览守着）。
- 水印（screenshot.md §4.3、§5）的排版与绘制也只有一份实现，在 `screenshot/output.ts`：`watermarkLayout` 排版（图片在前、文字在后，整行贴着所选的角；只有文字时保持原来的锚点，不量字宽），`paintWatermark` 绘制，设置页的预览与它共用 `watermarkBox`。`enabled` 是唯一的开关，图片和文字只是内容：关着时不解码、不画，`W` 也不出现；`W` 同时开关图片与文字，只影响这一次。图片在会话拿到设置时解码一次（`decodeWatermarkImage`，用 `HTMLImageElement.decode()`：设置校验只看 PNG 签名和大小，“头是对的、内容坏了”的文件要靠解码才发现），之后 `refreshDisplay` 同步地画。解码在拖拽选区期间就结束了；预览已经出来时才结束，就补画一次。读不出来是 `null`：只画文字，不抛错也不写日志（§5）。文字的墨色随背景明暗换（`onDark`），图片按原样画、不换色；两者共用同一个 `globalAlpha`，画完复位。水印只画在 `displayCanvas` 上，入库存的 `croppedCanvas` 从不带水印，所以预览、复制与下载是同一份像素。设置页预览同样调用 `paintWatermark` 画图片与文字，改画法时只改这一份，不在设置页另抄一份。
- 文字标注框的所有关闭路径——`Enter`、`Esc`、点别处、开下一个框——都走 `commitText`：已输入的文字变成标注，空框不留标注。它先清 `textInput` 再 `remove()`：Chrome 在移除有焦点的元素时同步触发 `blur`，顺序反了会重入，外层的 `remove()` 抛“节点已不是子节点”的 DOMException（`e2e/screenshot-beautify.spec.ts` 守着，页面抛错会让用例失败）。
- 序号（screenshot.md §1.1）是标注的一种（`StepAnnotation`），和其他标注在同一个数组里、由同一个 `renderScreenshot` 画，不另开绘制路径。数字不存：`stepNumbers` 按放下的顺序在同一组（`sequence`）里现数，所以删掉一个，后面的自动前移；“重置计数”只把会话的 `stepSequence` 加一。撤销栈存快照（标注数组加 `stepSequence`），画上、写下、放下、拖动、删除与重置都经 `commit` 进栈，`undo` 整体还原；按住拖动时只重画，松开才 `commit`。选中只是会话的 `selectedStep` 加一个 DOM 圆圈（`screenshot-step-selection`，里面是“×”），不画进任何画布；`shownStep` 只在工具是序号、没有按住、徽章还在标注里时才算选中，撤销拿走的徽章不会留下圆圈。大小、命中、贴边与墨色都在 `editor.ts`（`stepRadius`、`stepAt`、`clampStep`、`stepInk`），随 `capturedDpr` 缩放，会话只接线。
- 荧光笔、直线与线宽（screenshot.md §1.1）也是普通标注，由同一个 `renderScreenshot` 画。画笔、直线、荧光笔的标注带 `width`（细、中、粗），像素由 `editor.ts` 的 `lineWidth` 按工具与 `capturedDpr` 换算；矩形、椭圆、箭头没有这个字段，固定 3 像素。荧光笔是一条路径只描一次，`globalAlpha` 取 `HIGHLIGHTER_ALPHA`，所以来回涂不加深，画完 `restore`；直线按住 `Shift` 时终点经 `snapLine` 落到最近的水平、竖直或 45° 线上，每次指针移动与松开都按事件的 `shiftKey` 重算。会话只记当前的 `lineWidth`：和颜色一样每次截图从默认开始，换线宽不进撤销栈；这三种工具开着时，工具栏下方显示线宽一行。
- 会话期间在 capture 阶段吞掉可信的 `click`/`dblclick`/`auxclick`/`contextmenu`/`submit`（扩展自己的界面内除外，进入预览后恢复）：取消 `pointerdown` 挡不住随后的 `click`，不吞的话单击选取链接会真的跳转（`e2e/page-entry.spec.ts` 守着）。
- 匿名默认值与范围（头像、名字与账号，screenshot.md §3）来自设置（`GET_SETTINGS`）。区块胶囊的截图与会话同时开始、选区菜单交来的取景框可以立刻确认，所以每条截取路径都先等设置到达（`settingsLoaded`），状态在等待之前就置为 `capturing`，防止重复确认截两次。`A` 在截取之前（`selecting`、`confirming`）切换；用户按过 `A`，迟到的设置不再覆盖；两种都关时不显示也不响应 `A`。身份元素的种类只由 `detect.ts` 的 `identityPartOf` 判定，区域覆盖、克隆匿名与马赛克预填都经 `identityElements` 取元素，不各自筛选。`Esc` 先关最里面的一层：文字输入框，其次美化面板，最后才取消会话。

## 验证

- 改转换、识别、菜单或胶囊：跑 `npx vitest run`（相关单测）并构建后跑对应 E2E（`e2e/selection-clip.spec.ts`、`e2e/block-clip.spec.ts`、`e2e/screenshot-capture.spec.ts`、`e2e/page-entry.spec.ts`、`e2e/page-shapes.spec.ts`）。`page-shapes` 用平铺文档、div 汤、Docusaurus、长文（标题直接在 `main` 里、引言占满窗口、图里有代码）、带 meta 的文章、各类内容形状和页面界面类名的夹具，在真实浏览器里验识别与转换；转换器的转义约定还要跑 `learning-core/__tests__/fixtures/page-text.ts` 的共享夹具（`__tests__/markdown.test.ts` 里）。
- 改批注层、墨迹或它的换算：先跑 `entrypoints/content/annotation/__tests__`，再跑 `e2e/page-annotation.spec.ts`；改录制状态接线或光标高亮后跑 `e2e/recording-annotation.spec.ts`。改截图链路先跑 `entrypoints/content/screenshot/__tests__`；改美化、标注或预览布局后跑 `e2e/screenshot-beautify.spec.ts`（在预览、剪贴板和入库图片的像素上断言）；改水印的排版、解码或 `W` 后跑 `e2e/screenshot-watermark.spec.ts`（同样读像素，再加下载的 data URL；水印图片是测试里现编的 PNG，经 `setSettings` 播种，读不出来的那张是“PNG 签名 + 垃圾”，能通过设置校验却解码失败）；改序号后跑 `e2e/screenshot-steps.spec.ts`（读预览、三种格式的下载、剪贴板与入库图片的像素，并造下载与保存的失败）；改荧光笔、直线或线宽后跑 `e2e/screenshot-strokes.spec.ts`（同样读这些像素，另量 1x 与 2x 的线宽）；改滚动长图后跑 `e2e/screenshot-stitch.spec.ts`（`longpage.html` 夹具，读成品画布的接缝与像素）；改选区确认、吸附、手柄、层级或取景框记忆后跑 `e2e/screenshot-frame.spec.ts`（改源码必须 `rm -rf .output/chrome-mv3 && npm run build` 再测，`.output` 不随源码变化重建）。
