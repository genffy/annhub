# 阅读、抽屉与属性

> 适用范围：`entrypoints/library/` 的阅读视图、详情抽屉与属性页；上级约定见 [../AGENTS.md](../AGENTS.md)。

- `reading-view.tsx`、`highlight-surface.tsx`、`markdown-view.tsx` 是阅读与库内高亮。
- `markdown-view.tsx` 是渲染以及“选区 ↔ 源文本偏移”换算的唯一实现（RK-13），界面与导出不各自换算：渲染的每个 run 带 `data-s`（源偏移；转义序列单独成 run，显示 1 个字符、占 2 个源字符），表格逐单元格渲染，围栏代码块按存下的高亮切开。
- 引文由 `core/markdown.ts` 的 `quoteFromMarkdownRange` 按源偏移拼出可见文字（`quoteForRange` 只是它的薄封装，store 合并重叠高亮时用的是同一个函数），不是源 Markdown 切片。
- 围栏与行内代码的判定也取自那里，渲染器的 `INLINE` 与 `parseBlocks` 不各自再定。

- `property-panel.tsx`、`properties-view.tsx` 管属性。

- `property-order.ts` 定属性页的行序（`title`、`tags` 置顶并锁定，其余内置按注册表顺序，自定义按名称）；`utils/entry-icons.tsx` 是所有扩展页面共用的图标与类型标记（`VIEW_ICONS`、`ENTRY_TYPE_ICONS`、`PROPERTY_TYPE_ICONS`、`TypeChip`，样式在 `styles/chips.css`），图标一律来自 lucide，类型在列表、抽屉、筛选和弹窗里都是图标加文字，颜色不单独表意（visual.md §3）。

- 阅读视图只占内容区（`.reading` 在内容列里铺满），不盖导航：导航里高亮的是打开前的那个列表（`navView`，由 `returnHashRef` 的列表路由推出），点导航离开阅读视图去那个列表。被盖住的列表留在 `.content-stage` 里，保持布局与滚动位置，但设为 `inert`——焦点、指针与读屏都进不去；阅读视图载入后焦点落在它自己的“返回”上（测试：`e2e/library-shell.spec.ts`，含“返回时列表还在原来的位置”）。
- 抽屉里 `clip` 的原文与语境就地编辑（失焦或确认时提交一次，被拒绝的编辑保留草稿并可取消，任何关闭路径先写入未提交的编辑）：语境必须包含原文，清空即移除；有高亮时原文只读并写明原因（锁图标加高亮条数），语境照常可改；截图没有原文可改（`e2e/library-drawer-edit.spec.ts`）。
- 属性页：注册表是一张加了 `role` 的 grid 表格（`tr` 是 grid，隐式表头关联会丢，角色要写全），页头带副标题计数与“删除未使用（N）”（N 为 0 时禁用），表格上方是三条规则的提示条。
- `title`、`tags` 置顶并标“固定”，预设两列固定勾选并灰显。
- 删除按钮永远在行里，不可用时灰显且中性着色，下面写明原因——可见处是短词（内置/使用中，`.prop-reason`），整句在 `.sr-only` 里供 `aria-describedby` 朗读，也在按钮 `title` 里，亮暗两套外观下可见文字对比度都不低于 4.5（`e2e/library-properties-page.spec.ts`）。
- 新建表单在表格末尾展开：类型用 `property-type-picker`，名称错误就地显示在输入下方，保存按钮在名称为空或有错时禁用——错误提前用 `core/properties.ts` 的校验函数与已载入的注册表判断，不在界面里复制规则。
- 渲染不解析原始 HTML；链接只允许 http(s)，新标签页打开并带 `rel="noopener noreferrer"`（capture.md §3.1）。围栏代码块里的高亮同样画出来（`code` 块按存下的范围切开，每段带自己的源偏移），可点、可改色、可删。

- 抽屉是模态：透明的点击区域盖住左导航（点抽屉外面关闭，不压暗页面；要导出先关抽屉），焦点进入并被限制在里面，关闭后回到打开它的卡片，`Esc` 在输入法组合期间不关。
- 删除确认是一张卡片叠在抽屉之上：焦点进“取消”，Tab 在两个按钮间循环，`Esc`、取消与点遮罩都只取消确认并把焦点还给“删除”。
- 导出是对话框（`ExportDialog`）：准备 / 进行中 / 完整 / 部分导出各态。
- 进行中不能关闭（导出不可取消，`Esc` 无效），其余状态 `Esc` 与“完成”关闭并把焦点还给导航里的“导出内容”。
- `Esc` 永远先关最里面的一层：导出对话框与删除确认，其次高亮工具条，再次浮层（打开时取得焦点，关闭后还给原来的标记；点浮层外面也会保存并关掉），最后才是阅读视图或抽屉。
- 键盘扩展出的选区（`Shift` + 方向键，Chrome 在已有选区之后才允许）与鼠标一样出工具条，`H` 以默认颜色创建。
- 属性面板的每种行（含复选框）都参与 `flush()`：任何关闭路径先提交未提交的草稿；一行没有输入控件时视为“没有待并入的输入”，不能因此让 `flush()` 失败，否则抽屉就关不掉。
- 关闭路径永远不能被“没有可保存的内容”拦住：抽屉的条目还在加载、或已经不存在（URL 里的 `e=` 指向被删的条目）时，`Esc` 与遮罩照样关闭。
- 抽屉的按键处理器只订阅一次，通过 ref 调用最新的“保存并关闭”。
- 用依赖 `entry` 的回调重新订阅，异步渲染提交之后到被动副作用执行之前会有一个空档，这时的 `Esc` 落在上一次渲染的闭包上（测试：`e2e/library-property-regressions.spec.ts`，用 `MutationObserver` 在提交之后立刻发 `Esc`）。
- 高亮工具条拦 `Esc` 的捕获监听同理只订阅一次，由渲染时写入的 `toolbarRef` 判断工具条在不在：随工具条订阅、由被动副作用移除的监听，在高亮的回复让工具条离开 DOM 之后还会留一会儿，这时的 `Esc` 什么也没关，也到不了阅读视图。
